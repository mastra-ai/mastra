# TXT typography audit and migration

Scope: Playground UI (including enterprise Signals), Playground application, and Factory UI. Inventory baseline: `b5a7bb1a7a` (main after rebase). Screenshot baseline: `53ef78fa13`. The original JSX audit found 488 styled call sites in 221 files; constants, inherited typography, and tone-only usages were reviewed as well.

The final AST audit of 1931 production TypeScript files outside the design system finds **0 active typography class literals**. Layout, wrapping, alignment, tabular numbers, interaction colors, and semantic status colors remain application concerns.

## Decisions implemented

| Usage                                                      | Decision                                                                                                                      | Migration cost                                       |
| ---------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------- |
| Page/panel headings, tables, cards, descriptions, metadata | Existing title, heading, subheading, body, body-sm, column, caption, meta, and card-title roles                               | Direct call-site replacement                         |
| One-off size, weight, line height, and tracking overrides  | Choose the closest complete existing role; no single-use role added                                                           | Direct replacement with a small visual normalization |
| Responsive Factory welcome headlines and introduction      | Add hero (32–52px) and lead (16–20px); share both across sign-in and empty Factory                                            | New reusable roles                                   |
| Repeated uppercase section labels                          | Add eyebrow (12px, 500, 150% line height, .08em tracking), used by section headers, model provider titles, and command groups | New reusable role                                    |
| IDs, hashes, file paths, commands, timestamps, durations   | Existing Txt font=mono; expose the same face on Input, Tree.Label, TextAndIcon, Code, and CodeEditor where required           | Shared API plus call-site replacements               |
| Human labels and nontechnical counts                       | Body face; tabular-nums when columns need alignment                                                                           | Direct replacement                                   |
| Links, buttons, labels, native inputs, preformatted text   | Preserve native elements via Txt as; compose router links with render, retaining navigation, handlers, and refs               | Shared composition API plus replacements             |
| Text-bearing controls with an existing visual variant prop | textVariant or headingVariant on the shared control; typography owned by textStyle                                            | Shared API plus replacements                         |

The mono prop already existed on Txt. It now shares a single textStyle contract with other controls. Explicit font=body resets an inherited mono face; omitting font still inherits. Hero selects the display face. No variants encode colors: tone remains ink, muted, or faint.

## Shared contracts

Input (textVariant, font), Textarea (textVariant), Tree.Label and TextAndIcon (variant, tone, font), Code (variant, tone, font), InlineCode (variant, tone), MarkdownRenderer (variant), EntityName (variant), FieldLabel/FieldDescription/FieldsetLegend (textVariant), DataList.Cell (textVariant), CollapsibleTrigger (textVariant), ComposerInput (textVariant), DataPanelSectionHeading (variant), DataDetailsPanel.Heading (variant, tone, font), and CommandGroup (headingVariant) expose typography without descendant selectors. CodeEditor exposes font through its editor theme, defaults to mono, and lets prose editors request body. Standard button and tab typography comes from their existing DS contract.

## Intentional visual changes

Factory sign-in uses the same 32–52px hero scale as empty Factory onboarding, replacing its former 42–68px headline. Introductions use the shared 16–20px lead scale. Repeated section and command-group labels use eyebrow; default command group headings grow from 10px to 12px. Tables, alerts, panels, and compact actions lose one-off weight/leading/size adjustments and use their existing role. Human labels and counts previously inheriting mono become proportional; actual technical values remain mono.

See [the screenshot gallery](SCREENSHOTS.md) for before/after captures and the new role/font contracts at 1440×1000, 768×1024, and 390×844 in both themes. These are representative changed surfaces and shared contracts, not a screenshot of every individual migrated call site. Factory authentication is a browser network fixture; this is visual verification, not a live login test.

## Retained non-call-site typography

SVG/canvas labels keep font sizes calculated for drawing and geometry (KnowledgeGraph, charts, and the Factory stage animation). Font-face registration, native code font-size adjustment, and the legacy syntax-highlighting language selector are infrastructure. CodeMirror face selection lives in CodeEditor. The old experiment-trace-timeline-name-col block is commented out and not executable. Those are not active JSX overrides.

ESLint prevents typography class literals returning in Playground UI applications (including Signals) and Playground; design-system primitives retain ownership of the generated classes.

# Family Fit Matrix

| Family | Source | Scope | Candidate Direction | Runtime Ref | Shape Notes | Verdict |
| --- | --- | --- | --- | --- | --- | --- |
| Agent config version | `StorageAgentSnapshotType`, `AgentVersion`, `VersionedStorageDomain` | Permanent until replaced | Referenced artifact plus lifecycle ChangePulse | `uses_config_version` | Version row already is a stable body with id/versionNumber/changedFields/changeMessage. Treat storage call as source, not emitter. | Strong fit |
| Instructions revision | `StorageAgentSnapshotType.instructions`, `Agent.getInstructions()` | Both | Referenced artifact when reusable; ChangePulse when introduced | `uses_instruction_version` | Static instructions, function-resolved instructions, and call-site `options.instructions` need different scope labels. | Strong fit |
| Tool definition | `Tool`, `createTool`, integration-generated tools | Both | Referenced artifact likely strongest | `uses_tool_definition` | Tool body includes id, description, schemas, approval policy, suspend/resume support, provider options, metadata. | Strong fit |
| Tool schema only | `Tool.inputSchema`, `Tool.outputSchema`, builder compatibility layers | Both | Usually part of tool definition; separate only when transformed/generated independently | `uses_definition` | Compat layers can create LLM-facing schemas distinct from author schemas. | Mixed |
| Tool set changed for remainder of run | agent runtime options / request-level toolsets / processor-loaded tools | Permanent within run | ChangePulse over active tool-set definition | `uses_definition` | The changed set keeps applying until replaced or run ends. | Strong fit |
| Tool set changed for next step | `ProcessorRunner` activeTools step output | Temporary | ChangePulse with scope `step` | `uses_definition` | Same domain body as tool-set change, but narrower applicability. | Strong fit |
| Model settings | agent model config, fallback entries, call options | Both | Artifact for reusable settings; ChangePulse for scoped override | `uses_definition` / `uses_config_version` | `prepareModels()` resolves modelSettings/providerOptions/headers dynamically per request. | Strong fit |
| Request context schema | agent config, tool config, validation helpers | Both | Artifact or schema definition under config version | `uses_config_version` / `uses_definition` | Stored on agent versions as JSON Schema; tools can also validate request context per tool. | Strong fit |
| Processor config | processor setup, step processors | Both | Artifact for configured processor; ChangePulse for per-step effects | `uses_definition` | Processor config explains why messages/tools/model changed; processor outputs are changes, not definitions. | Mixed |
| Scorer/eval config | scorer/eval setup | Permanent until replaced | Artifact plus lifecycle ChangePulse | `uses_definition` | Useful for comparing eval results across definition changes. Needs more scorer source review. | Tentative |
| Memory config | agent version snapshot / memory processors | Both | Config artifact plus runtime ChangePulses | `uses_config_version` | Config explains recall/working-memory behavior; memory pull content itself should be content Pulse. | Mixed |
| Workflow config | workflow definition/version | Permanent until replaced | Artifact plus lifecycle ChangePulse | `uses_definition` | Strong conceptually, but deferred because this pass did not inspect workflow definition source deeply. | Defer |
| Structured output schema | `StructuredOutputProcessor` / agent call options | Both | Artifact if configured; ChangePulse with inline/ref body if generated at runtime | `uses_definition` | Schema and generated instructions guide an internal structuring agent. | Strong fit |
| Tool-search loaded tool state | `ToolSearchProcessor` | Temporary or thread-context scoped | ChangePulse over tool definitions | `uses_tool_definition` | Known tool definition becomes active after search/load; do not create duplicate tool definition. | Strong fit |
| Workflow step schema | `StepParams`, workflow config | Permanent until workflow changes | Nested artifact under workflow definition unless independently referenced | `uses_definition` | Step input/output/resume/suspend/request-context schemas are contracts, not runtime events. | Mixed |
| Dataset schemas | dataset storage / experiment runner | Permanent until dataset update | Artifact plus lifecycle ChangePulse | `uses_definition` | Input, ground truth, and request context schemas explain eval behavior. | Tentative |

# Onboarding design preview

This preview renders the production onboarding components. MSW supplies demo responses only in this separate entrypoint; it is never imported by the Factory application. No real integration is connected and submitted keys are discarded.

Run from `mastracode/factory-ui` after building the package’s dependencies:

- `pnpm exec msw init preview/public --no-save`
- `pnpm exec vite --config preview/vite.config.ts`
- `pnpm exec vite build --config preview/vite.config.ts`

The build is written to `preview-dist`. “Try another setup” on the completion screen clears only this preview’s data and onboarding markers. GitHub and Linear redirects return to the same preview with session-local demo connections. The final screen is a preview completion screen, not a running agent factory.

Each desktop scene illustrates its current setting: repository context for new sessions, tracker issues becoming backlog cards, the selected agent model, and personal credentials alongside the unchanged team default. It follows real selection and connection state, with gentle continuous motion and a static reduced-motion presentation. Tracker issues are explicitly illustrative; connecting a tracker does not automatically import or run work. Mobile shows only the form. Progress lives at the bottom. Back restores editable choices, including the repository and GitHub/GitLab provider. The final review offers direct Edit actions. The Factory, repository link, intake selection, default model are saved only after Create factory; retries reuse the pending Factory. Non-secret draft choices survive redirects and reloads. Connecting an integration or model account still authorizes that account immediately; these reusable connections are separate from the Factory draft.

The right-hand preview is one persistent custom Hairline drawing. Its rounded panel paths morph through four poses: an isometric factory with a joined sawtooth roof and input/output belts; an open repository folder feeding an agent workstation; a source issue or incident follow-up entering To do; and company or personal accounts feeding agent sessions. Intake shows the same source ID and title in the source and destination cards, with different examples for Linear, Jira and incident.io. Examples are illustrative and importing remains a post-setup action.

The unchanged skill kernel (MIT license included) drives geometry interpolation, distance-staggered 700ms tweens, the pointer tour, and the movement of work along belts and connections. Silhouettes retain their rounded corners during interpolation; returning to another step starts from the currently drawn pose. There is no Hairline package or stock figure dependency. The SVG and its surfaces persist across steps and rapid back navigation; only HTML annotations fade after the geometry starts moving. Labels stay sharp, untransformed and tied to the actual selection. Factory and codebase use the skill’s 2:1 camera, rounded solids, opaque faces and dim internal creases. The app uses softer neutral outlines and white card surfaces from its existing theme; there is no blur, SVG filter or scaled HTML text. Intake and account poses deliberately keep front-facing UI geometry and semantic HTML labels for legibility; motion is concentrated on the traveling card so board lanes stay still while reading. The kernel sleeps offscreen, reduced motion lands immediately, and mobile unmounts the drawing. No motion controls or outer preview panel are added.

Model onboarding separates API keys from provider sign-in, with explicit organization and personal scope. Both methods use the existing credential endpoints. Members without a shared provider can continue to personal setup. Provider sign-in is simulated with the code `DEMO`; API key values are discarded and only connection method/scope are retained. The preview now offers editable Company account and Everyone brings their own presets before provider selection, plus Allow personal connections for a hybrid setup. Company setup chooses a Factory default from an organization connection; individual setup chooses a user default from a personal connection; hybrid can configure both. API keys and provider sign-in remain available in each scope. These presets are an opt-in prototype: only this preview entrypoint supplies the preset save adapter, and its MSW route stores the selection locally on final confirmation. Production onboarding keeps its existing flow. Backend enforcement of company-only/owner-pays policy and stable session payer binding still requires FACT-317 and FACT-314; the adapter must be replaced by a real enforced API before exposing presets in production. No per-lane models are introduced.

GitLab has an existing demo connection with two projects so provider switching can be exercised. No real GitLab account is connected.

After syncing with main, onboarding leaves Observer and Reflector on Auto and never calls the removed `/web/config/om/provider-defaults` endpoint. Existing pinned memory settings remain untouched.

The preview offers Linear, Jira, and incident.io. Previously its Platform connections mock returned 404, intentionally hiding Jira and incident.io. It now returns the same available/connected response shapes as production. The preview Vite config alone substitutes `demo-platform-auth.ts` for the external Nango SDK: Jira authorization completes locally, and incident.io opens the real API-key form but discards the submitted value. The local demo authorization endpoint receives only the fake session identifier, never credentials. Production keeps the real Nango SDK and server-side availability gating. Connection failures offer Retry; expired connections reauthorize their existing account.

Validated against main `c4694e40fb304bbfd794caaa953cf0f30de84288` on 2026-10-09: production and preview builds, UI typecheck, 179 workspace UI/unit tests, and 168 backend route/integration tests pass. Browser checks cover company, personal, and hybrid presets, GitHub/GitLab switching, draft reloads, tracker authorization/redirects, and final confirmation at 1440×960, 375×667, and 390×844. A separate browser harness also exercises the production onboarding without the preset adapter against real ProjectRoutes, IntakeRoutes, and file-backed LibSQL: changing the repository before confirmation saves only the final repository, intake source, and Factory model. Identity and external-provider listings are fixtures in that harness. Live third-party authorization and paid model execution are not exercised by this preview.

Hairline source: [hairline-create](https://github.com/lucasmarkes/hairline/tree/main/skills/hairline-create). The kernel is copied unchanged between its original markers; its license and ES module export sit outside those markers. To reproduce its standalone checks, download that skill folder, then run `node preview/build-hairline-checks.mjs <skill-folder> <output-folder>`. Run the skill’s `validate.mjs` and `look.mjs` on the generated figures. The four poses pass static validation and the eight-view browser checks (including both themes and 240px thumbnails). Their complete meaning is checked with the React annotations in the app. The thumbnail motion heuristic reports small changes: motion intentionally stays with the incoming ticket, repository pages and connection marker, keeping the factory roof joined and readable board surfaces fixed. App checks verify intermediate geometry during a morph, one SVG across all steps, matching source/destination cards, stable lanes on tracker hover, scoped presets, reduced motion, and removal of the drawing on mobile. The app intentionally supplies its own existing layout instead of the skill bench’s slider, theme switch, and play controls.

The root formatter excludes the two Hairline JavaScript sources: the vendor kernel must remain byte-for-byte unchanged inside its hash markers, and the custom figure retains the skill’s compact source format for its standalone validator. TypeScript integration and React components use the repository formatter.

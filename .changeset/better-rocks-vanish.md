Improved the span details panel in Studio traces. Each nested span now opens with a one-sentence summary of what it did, naming the agent, model, tool or processor involved, for example "gpt-5-mini called weatherInfo, then wrote the answer", "Observational Memory loaded 2 earlier messages from memory into the conversation" or "Moderation left the system prompt and the conversation unchanged", in a color that matches the result. A failed span, root included, shows its error right in that summary at the top of the panel, once. Every span now reads in the same order: what it changed (shown inside the summary for memory, workspace, skill and processor spans), its input, its output, then its tools, metadata and attributes. A span whose model called tools lists those calls in its summary, each opening on its input and result like in the chat, and still lists the tools that were available. A processor that edits the system prompt directly shows exactly which system messages it added or removed, and a processor that failed or tripped a tripwire still shows the changes it made before stopping. Processor spans list their phase, executor, pipeline position, hook duration and tripwire (full reason, retry and metadata) as labelled values right under the summary, like the model facts of a model span. The root span skips the summary unless the run failed or was stopped, since its input and output already say what happened. The Preview, JSON and copy actions of each section now appear when you hover or focus that section. Metadata and attributes are now folded by default at the end of every span and show the raw JSON once opened. JSON views are no longer clipped behind an Expand button: they open with each top-level value folded, so you see the keys at a glance. An output with nothing to preview, like a model step that only called tools, goes straight to its JSON instead of an empty box.

`SpanProcessorAttributes` now renders only those labelled values (phase, executor, pipeline position, hook duration and tripwire), takes a `className` instead of a section frame, and leaves message-list changes to the new `SpanProcessorMutations` component.

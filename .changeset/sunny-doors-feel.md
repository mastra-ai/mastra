---
'@mastra/factory': minor
---

Factory environments now keep one template identity between builds and rebuild on triggers. The factory passes the heads it recorded on the last build (`factory_projects.active_template_heads`) to the sandbox template through `FactorySandboxContext.resolveHead`, so a session's template no longer changes with every commit on a base branch. A build worker rebuilds when the factory asks for it (a template-affecting environment change, or the new `POST /web/factory/projects/:id/environment/build` Build now route), on a push to an environment repository's base branch (leading-edge debounce: the first push builds, later ones are held and collapse into one build after the window; state kept on the project row so restarts and replicas lose nothing), and on a schedule that first checks whether any base-branch head moved. Successful builds record the template id, heads and per-repository status; failures record the error and back off. The environment `GET`/`PATCH` payloads gain `buildTriggers` and `build`, and `PATCH` returns `buildRequested` when a change queued a build. Hosts opt in with the new `MastraFactoryConfig.sandboxTemplate(ctx)` option, returning the same template resolver they hand to `PlatformSandbox`; without it, nothing changes and environments keep building lazily on the first session. Push triggers need the platform GitHub polling worker (`MASTRA_PLATFORM_GITHUB_POLLING_ENABLED` not `false`) or the self-hosted webhook; a build is bounded at 30 minutes and only one runs per factory at a time.

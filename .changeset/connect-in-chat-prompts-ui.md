Studio chat renders the built-in `request_connection` tool result as a connect card: provider rows with Connect actions that drive the mounted `userConnectRoutes()` flow (session → launch gate popup → status polling) so users can connect an account without leaving the conversation. Historical messages render the card read-only. The end-user connections domain (`@mastra/playground-ui/domains/connect`) now also exports a `usePendingConnect` hook that owns the full add-connection lifecycle: providers the browser can authorize headlessly (OAuth, API key, Basic, two-step) go through the launch gate's JSON redemption and the Nango SDK's provider-direct popup — no hosted page — while everything else keeps the hosted popup flow, with recovery when the popup is closed, the auth or poll fails, or the poll budget runs out. The hook takes the provider object (`connect(provider, values?)`), exposes `cancel()` to abandon an in-flight flow, and reports a `settled` outcome (`active` / `failed`, with a failure `message`) so UIs can react when a flow finishes. The headless primitives (`supportsHeadlessAuth`, `headlessAuthFields`, `splitHeadlessAuthValues`, `startHeadlessAuth`) are exported for custom surfaces.

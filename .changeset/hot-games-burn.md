Fixed session activity lagging behind reality, end to end. The server now stamps every run end on the session row and announces every session, decision, and materialization transition on the project feed, so board cards, sidebar rows, and the open chat refresh the moment something happens instead of waiting on the next poll — and every poll pauses while the stream is connected. Attention marks derive from the run-end stamp against a per-viewer seen store, so they survive reloads and no longer miss runs that finish in a hidden tab. The chat's favicon, composer, and status line read one shared phase (error > running > initializing > pending > awaiting), fixing the favicon claiming the session awaits input while history is still loading, and letting a rejoined running session be steered or aborted right away. The dispatcher keeps observing a leased run the registry still shows in flight instead of declaring a false start after ten minutes and kicking off a duplicate.

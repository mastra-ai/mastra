Fixed ClickHouse deletion requests blocking review updates on feedback that was never actually deleted. Requests are marked applied only after their delete succeeds, and review updates ignore unapplied requests. If a delete fails, the still-visible feedback stays editable; call `deleteFeedback()` again to retry. Review-status updates now change the existing feedback row in place instead of inserting a copy, so a concurrent update can no longer bring deleted feedback back, including on replicated clusters. This requires `ALTER UPDATE` permission on `mastra_feedback_events` and, when delta polling is enabled, `INSERT` permission on `mastra_feedback_events_delta`. If newer feedback content is ingested while a review update is running, the update is re-applied to the newest version; after repeated conflicts it throws a conflict error instead of reporting the feedback as missing. Overlapping deletion-request writes on replicated clusters retry briefly before failing; retry the delete API to recover.

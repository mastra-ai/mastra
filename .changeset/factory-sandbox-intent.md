'@mastra/factory': minor
---

Factory sandbox management is reduced to intent. Sessions construct sandboxes through a bare `sandbox: (ctx) => MastraSandbox` config callback (every shipped provider extends that base class; factory depends on its start lifecycle and runtime env rather than the looser `WorkspaceSandbox` interface) — sandbox identity is the session id, the provider resolves it with id-keyed getOrCreate on `start()`, workdirs are never read from persisted state (local providers check out under their own `workingDirectory`; remote providers clone into the VM's home dir, resolved from the live VM at first start), and session repo setup runs inside the start lifecycle, so any lazy start heals a replaced VM. Factory attaches that setup to the sandbox it gets back with `setOnStart`, so the callback has nothing to wire up and cannot break setup by omission; a callback that passes its own `onStart` keeps it, running after factory's setup against a prepared workspace. `ctx.getGithubToken` mints a fresh short-lived installation token for the session's repository, letting providers authenticate work that runs outside the VM (such as private-repo template builds). `SandboxFleet`, the base-checkpoint subsystem, pooled-sandbox claiming, and the reattach/revival ladder are deleted; `session.sandboxId`/`sandboxWorkdir` writes remain for observability only.

BREAKING: `sandbox` is a function now. The old object form (`machine`, `create`, `localRoot`, `idleTimeoutMinutes`, `instructions`, `workdir`, `maxSandboxes`) is removed — set provider options like idle timeouts on the provider constructor inside the callback. The host dynamic-workspace fallback is also removed: workspaces come only from the sandbox callback, and session-less requests get no workspace; host-cwd behavior is opt-in via a `LocalSandbox` callback. Deliberately dropped with the fleet: the per-replica sandbox budget (`SandboxBudgetError`), the fleet's provisioning-failure teardown-and-retry ladder, and cross-session sandbox pooling. Git transfer retries inside repo materialization are unchanged. The factory-side lazy-sandbox interposer and dead-VM revive-and-replay are also gone: the workspace holds the provider's real sandbox instance, which starts itself lazily (`ensureRunning()` on the first command) and owns its own self-healing (E2B restarts and retries internally; PlatformSandbox now resets its status on destroy so the next command re-runs the start lifecycle). A dead-VM command failure surfaces to the caller once instead of being transparently replayed. The unused worktree helpers (`ensureWorktree`, `removeWorktree`, `computeWorktreePath`, `safeBranchDir`) are removed — worktrees were the shared-VM era's per-branch isolation and have no callers with one sandbox per session; the setup/teardown-command helpers are renamed to `runSetupCommand`/`runTeardownCommand` (`SetupCommandError`) to match what they actually do.

The project-level sandbox concept is deleted. The per-(project,user) VM that used to back the workspaces panel independent of sessions can no longer be created: `/ensure` is a pure metadata handshake (opening a thread provisions nothing), `ensureProjectSandbox`/`projectSandboxKey`/`teardownProjectSandbox` and the `DELETE /web/github/projects/:id/sandbox` route are removed, and the per-user sandbox binding row is no longer created or read. Session sandboxes boot lazily at the first real command and are the only sandbox-bearing unit; file/git surfaces observe them passively and report "no sandbox running" when nothing is live.

The dead fleet-era storage domains go with it: the `sandboxes` and `worktrees` handles and the `source_control_project_repository_sandboxes`, `source_control_sandbox_pool`, and `source_control_worktrees` collection schemas are removed from source-control storage. Factory storage is additive-only, so existing databases keep those tables as untouched orphans — a deploy stops reading and writing them, a rollback still finds them; dropping them is a manual operation. Skill-invocation authorization no longer consults worktree rows (a gate that always failed closed once worktrees stopped being written): the scope must now match the live workdir of a viewer-visible session's memoized sandbox.

The orphaned base-checkpoint storage remnants are also removed: the `base_checkpoint_*` columns on project repositories, the `ProjectRepositoryBaseCheckpoint` type, and the `setBaseCheckpoint` API had zero readers once the sha moved to live head resolution. Existing databases keep the orphan columns untouched.

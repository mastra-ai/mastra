Factory sandbox management is reduced to intent. Sessions construct sandboxes through a bare `sandbox: (ctx) => WorkspaceSandbox` config callback — sandbox identity is the session id, the provider resolves it with id-keyed getOrCreate on `start()`, workdirs are derived from the constructed instance (local providers check out under their own `workingDirectory`, remote providers use `/workspace/<owner>/<repo>`; never read from persisted state), and session repo setup runs inside the start lifecycle via `ctx.onStart`, so any lazy start heals a replaced VM. `SandboxFleet`, the base-checkpoint subsystem, pooled-sandbox claiming, and the reattach/revival ladder are deleted; `session.sandboxId`/`sandboxWorkdir` writes remain for observability only.

BREAKING: `sandbox` is a function now. The old object form (`machine`, `create`, `localRoot`, `idleTimeoutMinutes`, `instructions`, `workdir`, `maxSandboxes`) is removed — set provider options like idle timeouts on the provider constructor inside the callback. The host dynamic-workspace fallback is also removed: workspaces come only from the sandbox callback, and session-less requests get no workspace; host-cwd behavior is opt-in via a `LocalSandbox` callback. Deliberately dropped with the fleet: the per-replica sandbox budget (`SandboxBudgetError`), the fleet's provisioning-failure teardown-and-retry ladder, and cross-session sandbox pooling. Git transfer retries inside repo materialization are unchanged.

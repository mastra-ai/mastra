Knowledge stores can now hold sequences: a page whose dated items, such as chat messages, deploys or build results, are stored as rows keyed by the source's own ID instead of one page per item. `store.sequences` marks a leaf page as a sequence and upserts items by `(sequenceId, externalId)`. An item has an optional one-line title, body, up to 10 http(s) links, JSON properties of up to 16 KB and a type such as `deploy`, and needs at least one of the first four. It can sit under another item of the same sequence, one level deep. Replaying an identical item changes nothing, and an older edit can't overwrite a newer one. Deletes are tombstones that clear the content, keep the type, and can't be brought back by a replay. A sequence orders its items by time (`orderBy: 'timeline'`, the default) or by position (`orderBy: 'position'`), fixed when the page is marked; on a position sequence an item goes at an explicit key no other item holds, or `after`/`before` another item, else last, and needs no time; concurrent writes get distinct keys. Search ranks equal matches by newest time on a timeline sequence and by position on a position sequence. Items are read in either direction with a cursor, filtered by time range, parent item or type. Search matches titles, bodies, link titles and string property values. An item is visible only when its sequence page is live and readable. Items of a deleted sequence are purged in bounded batches. A sequence can declare a `propertiesSchema` for untyped items and an `itemTypes` map (up to 50 types, each with an optional label, description and schema). A schema names up to 50 properties of type string, number, boolean, date or a capped array, with required keys and enums; writes that break it are refused with `KnowledgeSequenceItemPropertiesError`, and invalid declarations with `KnowledgeSequenceSchemaInvalidError`. A typed item follows its type's schema, an untyped item the sequence schema, and an item without one stays free-form. Marking again replaces the declaration (`markSequence` returns `updated`, or `unchanged` when only key order differs), never re-validates stored items, and can't change `orderBy`; `getSequence` returns it. This covers the in-memory and LibSQL stores. Nothing writes sequences yet.

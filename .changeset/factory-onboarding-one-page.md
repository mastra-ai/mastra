Redesigned Factory onboarding as one page with Codebase, Work, Accounts and Model sections. Finished sections collapse to a summary you can change in place, with sections sliding smoothly as they open and close, GitHub install problems appear inside the Codebase section, and Create factory stays disabled until every required account and model is ready. Accounts asks who pays for model usage (one company account, company for Factory work and personal accounts for sessions, or everyone's own account), and Model, right below it, shows the accounts that answer needs. Each account switches between the recommended Mastra Gateway and your own provider, picked from one searchable list of API key and subscription providers. Since the gateway bills the organization's credits, personal session accounts under company work and personal sessions use your own provider only. The gateway connects from its own button in the account, and Create factory sits below the cards. The account menu on the onboarding page now lets you switch between System, Light and Dark themes. Every onboarding problem now says why and what to do next: GitHub App results appear in the Codebase section with a recovery step, including installs on a personal GitHub account shared by a team, which Factory can't use; GitHub status failures offer Retry; a disabled Create factory says what is still missing; and cancelling a provider dialog keeps the provider you already connected. GitHub status now reports when Mastra Platform withholds a personal GitHub account installation from an organization with more than one member, so onboarding explains it on every visit, not only right after the install.

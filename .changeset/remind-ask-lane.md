Let the main agent ask the Subconscious reminder agent questions in natural language.

A new `ask_memory` tool takes a question and a `wait` flag, and every question is an explicitly correlated request. The tool mints a correlation id before it dispatches anything, registers the question against that id, and only then sends it to the reminder agent — as a runtime message on the thread the reminder agent already keeps for the session, carrying the id both in the text the model reads and in the message's structured metadata.

Both dispositions run that same dispatch. With `wait: true` the caller waits for that id to settle and gets `{ ok: true, correlationId, status: 'replied', answer }`. With `wait: false` the caller gets `{ ok: true, accepted: true, correlationId, status: 'pending' }` immediately and the answer arrives afterwards as the same `remembered` signal the passive reminder path already sends, carrying the id so a late answer names the question it belongs to. The only difference between the two is whether the caller waits; the request, the delivery, and the settlement are one path.

The reminder agent answers through a dedicated `reply_to_memory_question` tool that requires the correlation id, and that tool is the only way a question can succeed. A run finishing with text that looks like an answer no longer counts as one, which matters because the reminder agent's thread is shared: several questions can be delivered into one already-running turn, and each answer has to name which question it belongs to. The reply is validated against the thread and resource the tool is actually executing on rather than anything the model supplies, so a reply cannot cross from one conversation into another.

Once a question has been registered against its id, it reaches exactly one terminal state — `replied`, `timed_out`, `model_failed`, `aborted`, or `delivery_failed` — and the first one wins. Repeating the identical reply returns the stored result and delivers nothing a second time; a reply that disagrees with a settled answer, names an unknown or long-expired id, or arrives from the wrong conversation is rejected without disturbing the stored result. A run that dies fails only the questions that run was carrying. Settled questions are retained briefly so an immediate retry stays idempotent, then pruned; questions still waiting are never pruned.

Questions and the passive reminder evaluation still share one reminder thread, and the thread runtime still runs that thread one turn at a time with its transcript persisted in causal order, so a question and a passive evaluation never talk over each other. Within a turn the two differ: a passive evaluation owns its run, while a question is delivered to whichever run is live, which is why several questions can be in flight inside one turn and why each answer has to name its own id. Because a question now settles when its reply lands rather than when the turn ends, a caller can be answered slightly before that turn's transcript finishes persisting.

The tool registers behind the existing Subconscious `tools` flag, alongside the knowledge tools. It resolves its model from the subconscious agent config or the observational memory model, including the `default` sentinel (which falls back to the observational memory default model). Configured failover arrays and dynamic model functions pass through to the reminder agent unreduced, and token-routed models resolve their tier from an estimate of the turn's instructions and prompt — lane history and tool schemas are not counted, so routing skews toward smaller tiers on long-lived lanes — clamping to the largest tier rather than failing when the estimate exceeds every threshold. A deployment with no resolvable model at all gets an explicit unavailable result rather than a silent empty answer. Failures never throw into the main agent's turn, including a failing agent-registry lookup, which comes back as a tool error result.

Each question also has a deadline (120 seconds) as the terminal backstop for a genuinely hung run: the waiting caller gets a `timed_out` result while the turn itself continues and its transcript still persists in order, and a reply that arrives after the deadline is refused rather than overwriting it. A blocking ask also stops waiting when its calling turn aborts, without cancelling the lane turn. A detached ask deliberately outlives the turn that asked it, so aborting that turn does not cancel the question.

Correlation makes a late answer attributable; it does not make it durable. The request registry lives in the process that created it, so detached answers remain best-effort and in-process only: there is no durable queue, no retry, and no delivery across processes or restarts. The signal's persist write is awaited when the sender exposes one, but if the process exits before the answer lands, the answer is lost. The tool's acceptance note says so to the calling agent.

Fixed follow-up messages getting stuck after a tool suspends on an agent with `autoResumeSuspendedTools` enabled. A message sent with `agent.sendMessage()` (as Studio does once a chat exists) is now saved to the thread and starts the next turn, so the suspended tool or workflow resumes with the user's answer and the agent replies. Before, the message was accepted but never ran. This also works when the reply reaches the suspended run from another server process that shares the thread: the process running the run answers it once. On Inngest agents, approving a tool with only `runId` and `toolCallId` now lets a message queued behind the approval run once a tool that waits for input suspends afterwards. A run started with `autoResumeSuspendedTools: false` keeps that setting when it is resumed without the option, including from another server process or after a restart, so a later message still waits for an explicit resume. A resume on a run's open stream that names no thread now continues on the run's own thread and keeps the memory settings it does not pass. Fixes [#30190](https://github.com/mastra-ai/mastra/issues/30190).

Fixed follow-up messages getting stuck after a tool suspends on an agent with `autoResumeSuspendedTools` enabled. A message sent with `agent.sendMessage()` (as Studio does once a chat exists) is now saved to the thread and starts the next turn, so the suspended tool or workflow resumes with the user's answer and the agent replies. Before, the message was accepted but never ran. This also works when another server process that shares the thread resumed the run: whichever process the message is sent to, the process running the run answers it once. On Inngest agents, approving a tool with only `runId` and `toolCallId` now lets a message queued behind the approval run once a tool that waits for input suspends afterwards. A resume that leaves out `autoResumeSuspendedTools` keeps the run's latest setting, the one it was started or last resumed with, including from another server process or after a restart. A run that turned auto-resume off keeps holding a later message for an explicit resume. A resume on a run's open stream that names no thread now continues on the run's own thread and keeps the memory settings it does not pass. Fixes [#30190](https://github.com/mastra-ai/mastra/issues/30190).

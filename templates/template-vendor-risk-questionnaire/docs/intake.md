# Input profiles and mappings

The primary `npm run respond -- /absolute/path/questionnaire.xlsx` (or `.docx`) command builds mappings internally. Known verified sample layouts need no mapping file; supported exceptions prompt for regions, row bounds, fields and explicit exclusions. The administrative JSON mapping interfaces below remain available. Destination preflight runs before drafting, including direct draft/Studio routes. It binds exact spans and prefilled consent to the immutable source and mapping hashes.

Questionnaire inputs support XLSX ordinary worksheet tables, DOCX body tables, and identified DOCX paragraph blocks. Evidence intake separately supports XLSX, PDF, CSV, JSON and Markdown. DOCX evidence and PDF questionnaires are not supported. Approved review exports one answered XLSX or DOCX copy in the input format through the parent questionnaire workflow.

Mappings bind the source hash, adapter/profile version, selected region ranges, field columns, response constraints and explicit exclusions with reasons. Row and column selectors are zero-based; XLSX row selectors refer to original worksheet rows. Inspection records the original indices of every nonempty candidate row. Each candidate must be selected or explicitly excluded exactly once, and emitted questions must match the selected original locations, order and supplied IDs. Selected sheets and DOCX body regions retain source order, including hidden worksheet content when explicitly mapped.

Table fields include `question`, `id`, `type`, `options`, `section`, `instructions`, `required`, `maxChars`, `response`, `explanation`, `evidence`, `yes`, `no` and `not_applicable`. Map any supported headers by their column indices. Use `answerType` and `answerConstraints` on a region when these are supplied by trusted operator mapping rather than source columns. Source options use ordered `|`-separated literal values and labels. Supported types are `boolean`, `single_choice` and `free_text`. Mapped `required` cells use literal `true` or `false`, and `maxChars` cells use a positive integer. Supplied choice options and optional requirements/maximum lengths are preserved. Separate response/explanation columns, a combined response column, or explicit Yes/No/N/A target columns are supported through these bindings.

A `docx.blocks.v1` paragraph follows `ID: <id>`, a newline, `Question: <original text>`, a newline and `Response:`. Map column zero and row zero of each selected paragraph region; provide answer constraints in that region's mapping. Explicitly exclude inspected section paragraphs and non-question headers/footers. Arbitrary prose boundaries are not inferred.

Merged question records, nested/irregular question tables, formulas in semantic question fields, text boxes, unsupported body/cell/inline containers, interactive controls, tracked changes, embedded objects, encrypted packages and remote relationships receive diagnostics. Untrusted prefilled responses preserve their original location; formulas carry their original formula literal alongside untrusted cached display text. They are never approved evidence. Ordinary run text, tabs, line breaks, nonbreaking hyphens and soft hyphens retain their literal representation. Unsupported semantic run nodes receive diagnostics. Parsing occurs in a terminable native TypeScript worker with bounded bytes, ZIP expansion, XML/text size, memory and elapsed time. Unsupported or incomplete parsing never returns a successful partial intake.

## Evidence and local state

Each run receives a fresh Mastra Workspace BM25 index of eligible excerpt snapshots. Its LocalFilesystem is contained and read-only, with no sandbox or external URL retrieval. The backend retrieves evidence through bounded snapshot search/read functions; agents receive no filesystem or retrieval tools. The mutable Workspace instance is private. Retrieval scores rank candidates and are not confidence probabilities. Original evidence locators are sheet/cell, PDF page/text-block, CSV record/column, JSON pointer or Markdown heading/line references. PDF text order is the extractor's structural order, not a promise of visual reading order; scanned pages, forms, annotations, attachments and JavaScript actions are rejected.

Source hashes and policy can be validated again using `validateSnapshotSources`; `resolveEvidenceLocator` independently resolves original evidence bytes. `validateEvidenceCitation` verifies a citation version/hash, eligibility, locator and literal supporting excerpt against the snapshot and original source. Deterministic locator/excerpt checks do not prove semantic entailment. Intake itself performs no model calls or semantic security checks. The subsequent drafting and review phases apply native detectors, independent verification and explicit customer release approval.

Runtime state lives under ignored `.runtime`, including file-based LibSQL, immutable original source bytes and eligible normalized snapshots. There is no automatic cleanup, encryption-at-rest guarantee, remote backup or multi-user authorization system. The local OS operator is trusted. Retain state until you explicitly select and remove local runtime data; source evidence and environment files are separate.

`npm run dev` opens the local Mastra application and `npm run build` bundles it. Studio registers intake, draft and parent questionnaire workflows plus the four guarded phase agents. `npm run typecheck`, `npm run format:check` and `npm run test` provide contributor tooling. Offline fixture generators live in `tests/fixtures`; live model evaluations are excluded from ordinary test discovery and use the explicit command described in [evaluation and metrics](evaluation.md).

To add a format, implement `FormatParser` in `src/mastra/parsers`, then register its supported modes and lazy loader in `catalog.ts`. Questionnaire mapping belongs in the input adapter; evidence extraction must retain exact source locators. XLSX intake and export share `coordinates.ts`. Document completion requires a source-bound plan, bounded literal writer and exact approved-answer readback; additional customer export formats are outside the current contract.

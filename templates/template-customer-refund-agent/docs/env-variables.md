# Environment variables

The root `.env.example` contains only the settings needed for `npm run demo:local`. Add optional settings to your ignored `.env` when you need them.

## Local demo

| Variable         | Value               | Purpose                                                                             |
| ---------------- | ------------------- | ----------------------------------------------------------------------------------- |
| `OPENAI_API_KEY` | Your OpenAI API key | Required for interactive model responses.                                           |
| `APP_MODE`       | `local`             | Uses mock support and commerce providers, even if external credentials are present. |

`npm run demo:local` creates the local databases and signing keys automatically. No Intercom, Stripe, or Turso account is needed. OpenAI receives the prompts and relevant support/order context; API usage is billed to your account.

## Local demo options

| Variable                         | Default                                           | Purpose                                                                                          |
| -------------------------------- | ------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| `LOCAL_DEMO_DATABASE_URL`        | `file:.data/local-demo.db`                        | Local backend database for cases, history, and mock commerce.                                    |
| `LOCAL_DEMO_CLIENT_DATABASE_URL` | `file:.data/local-demo-client.db`                 | Separate local customer accounts and sessions.                                                   |
| `LOCAL_DEMO_BACKEND_PORT`        | `4111`                                            | Mastra backend and Studio port.                                                                  |
| `LOCAL_DEMO_CLIENT_PORT`         | `3000`                                            | Customer demo port.                                                                              |
| `LOCAL_DEMO_SUPPORT_PORT`        | `5173`                                            | Support dashboard port.                                                                          |
| `LOCAL_AUTH_SIGNING_KEY`         | Generated by `npm run demo:local`                 | Session signing key, at least 32 characters. Set it yourself when starting the backend directly. |
| `DEMO_AUTH_BRIDGE_SIGNING_KEY`   | Generated by `npm run demo:local`                 | Shared backend/client signing key for customer-scoped requests, at least 32 characters.          |
| `LOCAL_DEMO_BACKEND_URL`         | Set from the backend port by `npm run demo:local` | Backend origin when running local services separately.                                           |

The two local database URLs must refer to different persistent SQLite files. Relative local paths resolve from the template root. Each launcher run resets these files before creating the demo data; use separate paths from external databases. The generated signing keys are stored in ignored `.data/local-demo.env`.

Choose three distinct ports if the defaults are occupied. The local demo and its documented mock logins are intended for local use; keep these services off public tunnels.

## External integrations

Use `APP_MODE=staging` to connect an Intercom development workspace and Stripe test account. This mode requires both integrations and explicit backend/client database settings. See [external adapters](./external-adapters.md) for permissions, webhooks, and startup steps.

| Variable                       | Value                                              | Purpose                                                                                                                                                                     |
| ------------------------------ | -------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `APP_MODE`                     | `staging`                                          | Selects the external integration profile. `production` is also recognized, but does not enable Stripe live operations.                                                      |
| `SUPPORT_SOURCE`               | `intercom`                                         | Explicit staging/production mode overrides this value to `intercom`; otherwise a legacy provider selector.                                                                  |
| `COMMERCE_SOURCE`              | `stripe`                                           | Explicit staging/production mode overrides this value to `stripe`; otherwise a legacy provider selector.                                                                    |
| `DATABASE_URL`                 | For example, `file:.data/staging-backend.db`       | Required external-profile backend database. Keep it separate from the local demo.                                                                                           |
| `DEMO_DATABASE_URL`            | For example, `file:.data/staging-client.db`        | Required external-profile customer-demo database. Relative file paths resolve from `client-demo-ui/`.                                                                       |
| `LOCAL_AUTH_SIGNING_KEY`       | A private random value of at least 32 characters   | Required for authenticated staff sessions.                                                                                                                                  |
| `DEMO_AUTH_BRIDGE_SIGNING_KEY` | A private random value of at least 32 characters   | Configure the same value in backend and client processes.                                                                                                                   |
| `SUPPORT_BACKEND_URL`          | `http://127.0.0.1:4111`                            | Backend URL used by the customer demo in external mode.                                                                                                                     |
| `DEMO_PUBLIC_ORIGIN`           | The HTTPS customer-demo origin                     | Used for cookie security and origin validation when exposing the customer demo.                                                                                             |
| `DEMO_PRIVATE_DIR`             | `demo-private` beside the enclosing Git repository | Optional absolute directory for private files written by `npm run demo:setup`. It must remain outside the Git repository, including when the template is inside a monorepo. |

Keep `OPENAI_API_KEY` configured for interactive use. Local mode ignores external providers. With no explicit `APP_MODE`, legacy `SUPPORT_SOURCE=intercom` or `COMMERCE_SOURCE=stripe` settings select the external profile; set `APP_MODE` explicitly for new environments.

### Turso

The backend supports libSQL, including Turso. For a remote backend in external mode, set `DATABASE_URL` to the database's `libsql://` URL and `TURSO_AUTH_TOKEN` to its authentication token. A local SQLite backend needs no token. This does not configure the separate customer-demo database.

`TURSO_DATABASE_URL` is accepted only as a legacy fallback when `DATABASE_URL` is blank. Use `DATABASE_URL` for new configurations. The local demo always uses its separate SQLite files.

## Intercom

| Variable                        | Required / default                      | Purpose                                                                                                                                    |
| ------------------------------- | --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `INTERCOM_DEVELOPMENT_ENABLED`  | Required: `true`                        | Enables the development adapter.                                                                                                           |
| `INTERCOM_TENANT_ID`            | Required: `local-demo`                  | Matches the template's authenticated tenant.                                                                                               |
| `INTERCOM_APP_ID`               | Required                                | Development workspace app ID.                                                                                                              |
| `INTERCOM_ACCESS_TOKEN`         | Required                                | Token for the configured workspace and permissions.                                                                                        |
| `INTERCOM_CLIENT_SECRET`        | Required                                | Verifies webhook signatures.                                                                                                               |
| `INTERCOM_ADMIN_ID`             | Required                                | Admin used for support replies and notes.                                                                                                  |
| `INTERCOM_MESSENGER_JWT_SECRET` | Required for the external customer chat | Initializes authenticated Messenger. Without it, Messenger is unavailable.                                                                 |
| `INTERCOM_API_BASE_URL`         | `https://api.intercom.io`               | The adapter also accepts `https://api.eu.intercom.io`; fake HTTP origins are test-only.                                                    |
| `INTERCOM_KNOWLEDGE_ENABLED`    | `false`                                 | Reads published Articles as the Intercom knowledge source when `true`. Requires article read/list permission and reindexing after changes. |
| `INTERCOM_TICKET_TYPE_ID`       | Unset                                   | Creates a structured Ticket for an escalated case; the Conversation remains canonical.                                                     |
| `INTERCOM_TICKET_STATE_ID`      | Unset                                   | Optional Ticket state; requires a Ticket type ID.                                                                                          |

The runtime needs conversation read/write and contact read permissions. Ticket read/write is needed only for Ticket conversion, and article read/list only for Articles knowledge. The API version is pinned to `2.16` in source. Configure `conversation.user.created`, `conversation.user.replied`, and `conversation.admin.closed` webhook topics.

`npm run demo:setup` additionally reads `/me` to confirm the app and creates mock Contacts in that development workspace. See [policies and actions](./policies-and-actions.md#optional-intercom-articles) for adding Articles.

## Stripe

| Variable                    | Required / default               | Purpose                                                 |
| --------------------------- | -------------------------------- | ------------------------------------------------------- |
| `STRIPE_SANDBOX_ENABLED`    | Required: `true`                 | Enables the test-only adapter.                          |
| `STRIPE_TENANT_ID`          | Required: `local-demo`           | Matches the template's authenticated tenant.            |
| `STRIPE_ACCOUNT_ID`         | Required                         | Stripe test account ID.                                 |
| `STRIPE_RESTRICTED_API_KEY` | Required, starts with `rk_test_` | Restricted test key. Live keys are rejected.            |
| `STRIPE_WEBHOOK_SECRET`     | Required                         | Verifies Stripe webhook signatures.                     |
| `STRIPE_API_BASE_URL`       | `https://api.stripe.com`         | Must use the Stripe API origin outside fake HTTP tests. |

Runtime permissions: read Account, Customers, Checkout Sessions, PaymentIntents, Subscriptions, Invoices, Invoice Payments, and Refunds; write Refunds, Subscriptions, and Customers. **Customers: Write** is needed to create an approved **customer balance transaction** for a next-invoice credit. Subscription writes are limited to end-of-period cancellation. Financial proposals require authenticated human approval.

`npm run demo:setup` needs additional test-fixture permissions: read Account, Customers, and Invoices; write Customers, Payment Methods, Invoices, Invoice Items, Products, Prices, and Subscriptions. The setup does not issue refunds, credits, or cancellations. Configure `refund.created`, `refund.updated`, and `refund.failed` webhook topics. Live resources and redirected API origins are rejected.

## Retention

| Variable                                 | Default    | Allowed range                |
| ---------------------------------------- | ---------- | ---------------------------- |
| `SUPPORT_RETENTION_RAW_PAYLOAD_DAYS`     | `7`        | 1–7 days                     |
| `SUPPORT_RETENTION_CASE_DAYS`            | `90`       | 1–90 days                    |
| `SUPPORT_RETENTION_TRACE_DAYS`           | `30`       | 1–30 days                    |
| `SUPPORT_RETENTION_FINANCIAL_AUDIT_DAYS` | `365`      | 1–365 days                   |
| `SUPPORT_RETENTION_SWEEP_MS`             | `86400000` | 60000–604800000 milliseconds |

Retention windows may only be shortened. Run `npm run local:retention` for a one-off local sweep; it rejects remote database URLs.

## Validate a configuration

`npm run check:env -- --profile=auto` checks an interactive configuration, including the OpenAI and staff signing keys. For the local quickstart, use `npm run demo:local`, which generates signing keys before starting the services.

`npm run verify:pre-push` runs deterministic verification in an isolated copy and supplies its own mock test configuration. It does not need your `.env` or OpenAI key.

# Scan the example Orders API

Start [`npm run example-target`](example-target.md) in one terminal and `npm run dev` in another after [setup](../README.md#quickstart-). Keep the example terminal private: it prints the base URLs, two user IDs and API keys. Sign in to the local console with `CONTROL_BOOTSTRAP_SECRET`.

1. In **Policies**, choose **New policy**. Permit GET and HEAD, set finite request and duration limits, and enter evidence-retention days plus an approver.
2. In **Targets**, choose **New target**. Select **REST API**, paste the printed `scannerUrl` as the entry URL and its `openApiUrl` as the OpenAPI URL. Confirm the approved origin, `/api` path scope, GET/HEAD methods, authorization evidence and authorization checkbox. Review the route table: mark the order collection, detail and receipt as `User / Owner only`, and products as `Public`. The local example uses the verified owned lab transport; use **Staging** for a separately authorized public HTTPS origin.
3. Open the saved target and add two **API key header** profiles. Use the printed A and B keys separately, `x-api-key` as the header and `/api/orders` as each existing own-resource access check, and `/principal` as each account identifier JSON pointer. Choose **Check identity** for each profile after both are registered. Both must be `READY` at the current target revision.
4. Choose **Start REST assessment**. This admits discovery, grounded Sherlock selection and a two-GET owner/alternate comparison. In **Scans**, inspect candidates, selected route, hypothesis, statuses, request and token reservations, and cleanup. A vulnerable order detail read can yield `CONFIRMED`; **Findings** then has a separate REST BOLA record. Public products do not become a BOLA finding.
5. Stop the example, restart it with `npm run example-target -- --mode=protected`, then run another assessment against the same seeded data. The alternate-account detail read returns 403, so the new assessment is `NOT_REPRODUCED` and creates no new finding. An earlier confirmed finding remains in history.

In a terminal with the scanner still running, `npm run sync:advisories` calls the protected local sync endpoint. It can contact cve.now and, when models are enabled, make up to eight bounded paid Sherlock calls. If cve.now fails or returns inconsistent data, the command reports `SKIPPED` with a reason and checkpoint; imported pages remain partial, no new hypothesis is planned, and retry respects backoff. In **Vulnerabilities**, a new eligible CVE may show a manual advisory hypothesis with target relevance unknown and no executable checker; unavailable inference leaves triage pending. **Ignore** records a reason and scope, **Investigate** creates a manual case, and **Search scanner/checker** inspects the local catalog without running internet code. An advisory card is not an application finding.

The local example and automated model fixtures establish the setup and product behavior. A real Morph response, real cve.now sync and a separately hosted target require distinct evidence. The [public HTTPS tunnel procedure](example-target.md#public-https-transport-check) exposes the project-owned example and proves the external transport path, not independent hosting.

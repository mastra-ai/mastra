# Themes

Mastra Code ships with bundled themes and loads custom ones from `~/.mastracode/themes/<name>.json`.

- `/theme` — open the theme picker (built-ins + pairs + bundled + custom, live preview)
- `/theme list` — list all available themes
- `/theme <name>` — apply and persist a theme by name
- `/theme auto|dark|light` — built-in modes
- `/theme <light>/<dark>` — follow the terminal appearance with a theme pair
- `/theme status` — show the active mode and stored preference
- `MASTRA_THEME=<name>` — environment override (mode, theme name, or pair)

## Bundled themes

`tokyo-night`, `catppuccin-mocha`, `catppuccin-latte`, `gruvbox-dark`, `dracula`, `nord`, `solarized-dark`, `solarized-light`

Bundled themes are defined in `src/tui/bundled-themes.ts`. A user file in `~/.mastracode/themes/` with the same name overrides the bundled version, so you can tweak one by copying its definition into a file and editing it.

## Follow your terminal's light/dark mode

Picking a single custom theme locks you into its `appearance`, so it keeps the same palette no matter what your terminal is set to. To follow the terminal instead, use a light/dark pair: the light theme first, the dark theme second, separated by `/`.

```bash
MASTRA_THEME=catppuccin-latte/catppuccin-mocha mastracode
```

```json title="~/.mastracode/settings.json"
{
  "preferences": {
    "theme": "solarized-light/solarized-dark"
  }
}
```

Mastra Code reads the terminal's background color (OSC 11), then the `COLORFGBG` environment variable, and falls back to dark. It applies the light theme when the terminal is light and the dark theme otherwise. `auto` does the same for the built-in palettes.

The picker offers a pair for every bundled light/dark family: `catppuccin-latte/catppuccin-mocha` and `solarized-light/solarized-dark`. Any two theme names work in a pair, and each name must not contain `/`.

## File format

```json
{
  "name": "midnight",
  "appearance": "dark",
  "bg": "#1a1b26",
  "vars": {
    "bg-raise": "#16161e",
    "blue": "#7aa2f7",
    "purple": "#bb9af7",
    "green": "#9ece6a",
    "red": "#f7768e",
    "yellow": "#e0af68",
    "fg": "#c0caf5",
    "fg-dim": "#565f89"
  },
  "colors": {
    "accent": "blue",
    "borderAccent": "blue",
    "success": "green",
    "error": "red",
    "warning": "yellow",
    "text": "fg",
    "muted": "fg-dim",
    "dim": "fg-dim",
    "textHighlight": "purple",
    "userMessageBg": "bg-raise",
    "function": "blue",
    "number": "yellow",
    "path": "fg-dim"
  }
}
```

- `appearance` (required): `"dark"` or `"light"`. Selects the surface palette and the built-in theme used as a fallback for any color you don't set.
- `bg` (optional): the terminal background the theme is designed for. Panel and overlay shades derive from it, and foreground colors contrast-adapt against it. Mastra Code does not paint the terminal background, so set it in your terminal for a theme whose `bg` differs from it. Background color keys you don't set explicitly (`overlayBg`, `selectedBg`, `userMessageBg`, `systemReminderBg`, `toolPendingBg`, `toolSuccessBg`, `toolErrorBg`, `errorBg`) are derived from `bg` so overlays and panels match instead of falling back to the built-in near-black/white values.
- `vars` (optional): named palette. Values must be hex colors (`#rrggbb` or `#rgb`).
- `colors` (optional): any subset of the color keys below. Values are a hex color or the name of a `var`. The loader ignores unknown keys, but the JSON schema (`theme-schema.json`, beside this page) is stricter and flags them so typos show up in your editor.

Without a `bg`, foreground colors and panel shades contrast-adapt against the terminal's actual background (WCAG-based), so the theme stays readable whatever your terminal is set to.

## Color keys

| Key | Used for |
| - | - |
| `accent` | Primary accent: prompts, highlights, selected prefix |
| `border` / `borderAccent` / `borderMuted` | Box borders |
| `success` / `error` / `warning` | Status colors |
| `text` | Main body text |
| `secondary` | One step softer than `text`: tool calls, status line |
| `muted` / `dim` | De-emphasized text |
| `thinkingText` | Reasoning/thinking output |
| `userMessageBg` / `userMessageText` | Sent user messages |
| `systemReminderBg` | System reminder blocks |
| `toolPendingBg` / `toolSuccessBg` / `toolErrorBg` | Tool call panels |
| `toolBorderPending` / `toolBorderSuccess` / `toolBorderError` | Tool panel borders |
| `toolTitle` / `toolArgs` / `toolOutput` | Tool call text |
| `textHighlight` | Inline code, headings, links |
| `selectedBg` | Selected list rows |
| `overlayBg` | Modal overlays |
| `errorBg` | Error display background |
| `path` / `number` / `function` | File paths, line numbers, function names |

## Translating themes from other tools

Any existing theme can be converted — pi themes (`~/.pi/agent/themes/*.json`), VS Code color themes, terminal schemes (iTerm2, Ghostty, Alacritty, Windows Terminal), base16/base24 palettes, and editor themes like Tokyo Night, Catppuccin, or Gruvbox. The job is always the same: extract the source's palette, then map it onto the color keys above.

Common source vocabularies and where they land:

| Source concept | mastracode |
| - | - |
| Editor / terminal background | `bg` |
| Accent / primary / blue | `accent`, `borderAccent`, `function` |
| Green / success / diff-added | `success` |
| Red / error / diff-removed | `error`, `toolBorderError` |
| Yellow / orange / warning | `warning`, `number` |
| Magenta / purple / keywords | `textHighlight` |
| Foreground / editor text | `text` |
| Comments / gray / inactive | `muted`, `dim`, `path` |
| Selection background | `selectedBg` |
| Panel / sidebar / raised background | `overlayBg`, `toolPendingBg`, `toolSuccessBg` |
| Error background | `errorBg`, `toolErrorBg` |
| Dark/light variant | `appearance` |

Specific source hints:

- **pi** (`vars` + `colors`): structure is nearly identical — keep `vars`, remap `colors` keys per the table.
- **VS Code** (`.json` theme): use `editor.foreground`/`editor.background` for `text`/`appearance`, `editor.selectionBackground` for `selectedBg`, and `tokenColors` scopes (keyword → `textHighlight`, string → `success`-family, comment → `muted`).
- **Terminal schemes** (ANSI 16): foreground → `text`, blue → `accent`, green/red/yellow → `success`/`error`/`warning`, bright black → `muted`, magenta → `textHighlight`.
- **base16**: base05 → `text`, base03 → `muted`, base0D → `accent`, base0B/base08/base0A → `success`/`error`/`warning`, base0E → `textHighlight`, base02 → `selectedBg`.

Keep hex values as-is; drop source keys with no counterpart and let the built-in fallback fill the rest. Ask your agent: "translate the theme file or name to a mastracode theme at `~/.mastracode/themes/<name>.json` using the mapping in themes.mdx".

# Studio deployment

Studio is a React-based Single Page Application (SPA) that runs in the browser and connects to a running [Mastra server](/docs/deployment/mastra-server).

You can deploy Studio in two primary ways:

- The Mastra platform provides a hosted Studio for you and allows you to share access with your team via link
- Self-host Studio on your own infrastructure, either alongside your Mastra server or separately as a standalone SPA

On this page you'll learn how to deploy Studio on your own infrastructure. As the finer details of deployment can vary widely based on your needs and setup, we'll cover the general principles and options available to you.

## Quickstart

The easiest way to run Studio is the [`mastra studio`](/reference/cli/mastra#mastra-studio) command.

Whereas `mastra dev` runs both Studio and an API for development purposes, the purpose of `mastra studio` is to serve a standalone, static UI that connects to an already-running Mastra server. You can deploy Studio separately from the Mastra server.

Open a terminal and install the `mastra` CLI globally:

```bash npm2yarn
npm install -g mastra
```

Run the `mastra studio` command:

```bash
mastra studio
```

Open [localhost:3000](http://localhost:3000) in your browser to see the Studio UI. By default, it connects to a Mastra server at `http://localhost:4111`; when no server is available, the UI displays a form for entering your Mastra instance URL and API prefix.

The command uses Node's built-in `http` module and [`serve-handler`](https://www.npmjs.com/package/serve-handler) to serve the static files.

:::note

If you're hosting Studio under a subpath (for example `/agents` behind Nginx), set `MASTRA_STUDIO_BASE_PATH` before starting Studio:

```bash
MASTRA_STUDIO_BASE_PATH=/agents mastra studio
```

This updates the HTML base URL and static asset routing so the standalone Studio works correctly under that subpath.

:::

## Mastra platform

For hosted Studio on Mastra platform, see [Studio on Mastra platform](/docs/mastra-platform/studio).

## Running a server

Running `mastra studio` as a long-running process is no different from running any other Node.js service. The same deployment practices and tools apply here. Use process managers such as PM2 or Docker. Cloud services that support Node.js applications are another option. As with any web service, configure CORS correctly and monitor errors.

:::warning

Once Studio is connected to your Mastra server, it has full access to your agents, workflows, and tools. Be sure to secure it properly in production (e.g. behind authentication, VPN, etc.) to prevent unauthorized access.

Visit the [Authentication](/docs/studio/auth) docs to learn more.

:::

### Alongside your API

Alternatively, you can serve Studio alongside your [Mastra server](/docs/deployment/mastra-server). This way you only have one service to deploy and manage.

To do this, run `mastra build` with the `--studio` flag:

```bash
mastra build --studio
```

It'll create a `.mastra/output/studio` folder with the built Studio assets. By defining the `MASTRA_STUDIO_PATH` environment variable, the Mastra server can serve the Studio UI, too.

```bash
MASTRA_STUDIO_PATH=.mastra/output/studio node .mastra/output/index.mjs
```

## Open the trace list as an MCP App

Mastra Server includes a Studio [MCP App](/reference/tools/mcp-server#mcp-apps-appresources) at `/api/studio/mcp`. It serves the connection screen and a filterable trace list to MCP Apps hosts, including ChatGPT plugin extensions. The HTML, JavaScript, and styles are bundled into `@mastra/server`, so you don't need a separate UI deployment or the `--studio` build flag.

This preview connects to public servers without authentication. It includes time ranges, filters, sorting, column preferences, pagination, and automatic refresh. Trace details, usage metrics, and the Studio sidebar aren't included.

1. Deploy your Mastra server at a public HTTPS URL with trace storage and browser access through CORS enabled.
1. Connect the host to `https://your-server.example/api/studio/mcp`. If you configure a different API prefix, replace `/api` in this URL.
1. Open **Mastra Studio** through the `open_studio` tool or the extension's global entry point.
1. Confirm the **Mastra instance URL** and select **Connect**. Run an agent or workflow in your Mastra application to create traces, then verify that they appear in the list.

The MCP endpoint serves the UI shell. The UI reads the existing observability API directly with browser credentials omitted. API authentication remains enforced. Servers that require authentication display a connection error in this preview.

The app's Content Security Policy (CSP) allows connections to the server hosting its MCP endpoint. To use another server, add that server's MCP endpoint to your host and open its Studio app. Entering an unrelated server domain in the connection screen isn't supported.

### Set the public URL behind a proxy

By default, the app derives its server origin from the HTTP request. If your reverse proxy terminates HTTPS or mounts the server under a path, set `MASTRA_STUDIO_PUBLIC_URL` to the externally reachable base URL before starting the server:

```bash
MASTRA_STUDIO_PUBLIC_URL=https://agents.example.com node .mastra/output/index.mjs
```

Include any proxy mount path in this value, but don't include the API prefix. The app uses the server adapter's configured API prefix automatically. The public URL also determines the app's CSP connection origin.

For ChatGPT, follow the [plugin extension setup](https://developers.openai.com/plugins/build/extensions) to connect your deployed MCP endpoint. Deploying Mastra Server provides the app endpoint. Distributing a plugin is a separate host-specific step. This preview uses the same MCP protocol revision as `@mastra/mcp` (`2026-07-28`).

## Using a CDN

### Automatic

Some of the [Cloud providers](/docs/deployment/cloud-providers) offer an option to deploy Studio alongside your serverless function. Currently, the supported providers are:

- [`VercelDeployer`](/reference/deployer/vercel)

### Manual

You can't directly deploy the built Studio assets to a CDN, as the UI relies on some runtime configuration. With a bit of extra setup, you can create a standalone SPA out of the built assets and deploy it to any static hosting service.

Follow the example below to create a SPA using Vite.

<Steps>
  <StepItem>
    Create a new folder and initialize a new Node.js project:

    ```bash npm2yarn
    mkdir studio-spa
    cd studio-spa
    npm init
    ```
  </StepItem>

  <StepItem>
    Install `vite` and `mastra` as dependencies:

    ```bash npm2yarn
    npm install vite mastra
    ```
  </StepItem>

  <StepItem>
    Add a build script to your `package.json`:

    ```json title="package.json"
    {
      "scripts": {
        "build": "vite build"
      }
    }
    ```
  </StepItem>

  <StepItem>
    Create a placeholder `index.html` file:

    ```html title="index.html"
    <!doctype html>
    <html>
      <head></head>
      <body></body>
    </html>
    ```
  </StepItem>

  <StepItem>
    Create a `vite.config.js` file. It copies the built Studio assets to the `dist` folder and replaces any `%%PLACEHOLDER%%` values in the HTML with environment variable values.

    ```js title="vite.config.js"
    import { defineConfig, loadEnv } from 'vite'
    import { readFileSync, cpSync, writeFileSync } from 'node:fs'
    import { resolve, join } from 'node:path'

    const studioDir = resolve(import.meta.dirname, 'node_modules/mastra/dist/studio')

    export default defineConfig(({ mode }) => {
      const env = loadEnv(mode, process.cwd(), 'MASTRA_')

      return {
        plugins: [
          {
            name: 'mastra-studio',
            closeBundle() {
              const outDir = resolve(import.meta.dirname, 'dist')
              cpSync(studioDir, outDir, { recursive: true })

              const indexPath = join(outDir, 'index.html')
              const html = readFileSync(indexPath, 'utf-8')
              writeFileSync(
                indexPath,
                html.replaceAll(/%%(\w+)%%/g, (_, key) => env[key] ?? ''),
              )
            },
          },
        ],
        build: {
          emptyOutDir: true,
        },
      }
    })
    ```
  </StepItem>

  <StepItem>
    Create a `.env` file with the necessary environment variables.

    ```env title=".env"
    MASTRA_SERVER_HOST=localhost
    MASTRA_SERVER_PORT=4111
    MASTRA_SERVER_PROTOCOL=http
    MASTRA_API_PREFIX=/api
    MASTRA_HIDE_CLOUD_CTA=false
    MASTRA_CLOUD_API_ENDPOINT=
    MASTRA_EXPERIMENTAL_FEATURES=false
    MASTRA_TEMPLATES=false
    MASTRA_TELEMETRY_DISABLED=true
    MASTRA_REQUEST_CONTEXT_PRESETS=
    MASTRA_THEME_TOGGLE=false
    MASTRA_EXPERIMENTAL_UI=false
    MASTRA_STUDIO_BASE_PATH=
    ```
  </StepItem>

  <StepItem>
    Run the build script to generate the static files in the `dist` folder:

    ```bash npm2yarn
    npm run build
    ```
  </StepItem>

  <StepItem>
    Point your hosting provider to the `dist` folder and deploy!
  </StepItem>
</Steps>

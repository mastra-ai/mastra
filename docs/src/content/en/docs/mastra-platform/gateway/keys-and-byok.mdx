# Keys and BYOK

## API keys

Gateway keys start with `msk-gateway-`. Send a key in either header:

```text
Authorization: Bearer msk-gateway-...
x-api-key: msk-gateway-...
```

| Key type | Scope | Created from |
| - | - | - |
| Project key | One project. Usage is attributed to the project, and responses include `x-gateway-project`. | **Gateway** > **API keys** inside a project |
| Organization key | The whole organization. | **Gateway** > **API keys** at organization level |

Keys are shown once when created. Gateway stores only a hash.

Keys that start with `msk_` belong to the previous Memory Gateway and don't work with the current API. Memory Gateway shuts down on December 31, 2026. See [Migrate](/docs/mastra-platform/gateway/migrate#from-mastra-memory-gateway).

## Restrict a key

When you create a key, you can set:

- **Label**: A name to identify the key.
- **Expiry**: A date after which the key stops working.
- **Allowed models**: The only models the key can call. `/v1/models` lists only those models for the key.
- **Disable failover**: Keep each request on a single route.

You can rename project and organization keys at any time. Expiry, allowed models, and failover are fixed at creation. To change them, create a new key and revoke the old one.

A key can also have a spend limit (daily, weekly, monthly, or lifetime, from $1). Gateway rejects requests with that key once the limit is reached.

## Regions

Gateway runs in two regions, US and EU. Each key belongs to one region, chosen with **Region** when you create it. The default is US, and a key keeps its region for life.

| Region | Key prefix | Base URL |
| - | - | - |
| US | `msk-gateway-` | `https://gateway-api.mastra.ai/v1` |
| EU | `msk-gateway-eu_` | `https://gateway-api.eu.mastra.ai/v1` |

To run inference in the EU, create an EU key and point your client at the EU base URL. The EU instance routes requests only to Gateway-managed provider endpoints in the EU (BYOK is the exception, see below), and it rejects US keys with a `401 key_wrong_region` error.

```typescript
import OpenAI from 'openai'

const client = new OpenAI({
  apiKey: process.env.MASTRA_GATEWAY_API_KEY, // msk-gateway-eu_...
  baseURL: 'https://gateway-api.eu.mastra.ai/v1',
})
```

Things to know about EU keys:

- **Model catalog**: The EU serves fewer models than the US, and prices can differ. With an EU key, [`GET /v1/models`](/docs/mastra-platform/gateway/api/models) lists only EU models at EU prices. Without a key, call `GET /v1/models?region=eu` to see the EU catalog.
- **No cross-region failover**: Requests with an EU key never fall back to the US. If no EU route can serve the request, it fails.
- **Web search**: [Gateway-managed web search](/docs/mastra-platform/gateway/web-search) runs in the US only. With an EU key, the search tool call returns a failed search to the model.
- **BYOK**: A [BYOK connection](#bring-your-own-key) isn't tied to a region, even when you use an EU key. OpenAI, Anthropic, and Google connections send requests to that provider's own API. Only a custom HTTPS endpoint connection lets you choose where requests go. To keep BYOK traffic in the EU, use a custom endpoint that processes requests in the EU, and confirm that it doesn't forward them to a provider outside the EU.

Keys created before regions existed are US keys. [Deployment keys](#deployment-keys) follow the region the deploy runs in, so a deploy in an EU region gets an EU key.

## Rotate and revoke

- **Organization keys** can be rotated. Rotation issues a new secret for the same key.
- **Project keys** are revoked and replaced. Create the new key, update your application, then revoke the old one.

Revoked and expired keys return `401`.

## Deployment keys

:::info[Rolling out]

Automatic deployment keys are rolling out by organization.

:::

When enabled, Mastra platform injects a Gateway key into each deploy as `MASTRA_GATEWAY_API_KEY`, so deployed agents can call Gateway without manual setup. The key is scoped to the deploy and is revoked when the deploy stops, fails, or is cancelled. A key you set yourself isn't replaced.

Turn injection on or off, and restrict allowed models, in project settings. A deployment-key spend limit set in project settings applies to each deploy's key.

## Bring your own key

A BYOK connection routes requests through your own provider account. The provider bills you directly, and Gateway doesn't charge Mastra credit for those requests.

| Provider | Supported endpoints |
| - | - |
| OpenAI | Chat Completions, Responses, Embeddings, Decisions |
| Anthropic | Messages and Chat Completions (OpenAI-compatible) |
| Google | Chat Completions and Embeddings (OpenAI-compatible) |
| Custom HTTPS endpoint | Chat Completions, Responses, and Messages |

Images, audio, and rerank aren't available over BYOK.

An Anthropic connection also serves `/v1/messages/count_tokens` and the Anthropic Files API through the same key.

To set up a connection:

1. Open **Gateway** > **BYOK** in [projects.mastra.ai](https://projects.mastra.ai).
1. Add a connection with your provider API key.
1. Optionally assign the connection to projects. Keys in those projects then use it for that provider.

Each connection's proxy key can have an expiry and a spend limit, set when you add the connection. You can edit the spend limit later, but not the expiry. Custom endpoint connections support an expiry only.

BYOK requests make one attempt on your connection and don't fail over to another provider. Allowed-model restrictions and organization policy still apply. If the connection is inactive, requests return `403` with `byok_connection_inactive`.

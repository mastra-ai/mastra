# Channels

[`channels()`](/reference/connect/channels) turns the Slack, Telegram, and Discord connections in your project into [channels](/docs/channels), so people can talk to your agents there. The platform stores each token, and your app fetches it when it needs it.

Each platform needs a different credential:

- **Slack**: A **Slack channels** (`slack-channels`) connection, which holds an app configuration token. Mastra creates a Slack app for each agent from it. This is a different connection from **Slack** (`slack`), which gives agents Slack tools.
- **Telegram**: A bot token from BotFather.
- **Discord**: A bot token from a Discord application you create. The same connection also gives agents Discord [tools](/docs/mastra-platform/connect/tools).

## Add channels to Mastra

Pass `channels()` to the `Mastra` constructor:

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { channels } from '@mastra/connect'
import { assistant } from './agents/assistant'

export const mastra = new Mastra({
  agents: { assistant },
  channels: await channels(),
})
```

`channels()` returns a promise. It creates a provider for each channel before `Mastra` starts. Their webhook routes exist from the first request. A provider starts working when the project gets an active connection for it, without a redeploy.

The providers come from `@mastra/slack`, `@mastra/telegram`, and `@mastra/discord`, which `@mastra/connect` installs for you.

## Configure a channel

Pass provider options under `integrations`. Credentials always come from the connection, so options like `botToken` are ignored:

```typescript
channels({
  integrations: {
    discord: {
      providerOptions: { applicationId: process.env.DISCORD_APPLICATION_ID },
    },
    telegram: { disabled: true },
  },
})
```

See the [`channels()` reference](/reference/connect/channels) for every option. Which channels your app exposes is decided here, not per request: use `disabled` to leave one out.

## Vary tools by channel

When a message arrives through a channel, the agent runs with a `channel` entry on the [request context](/docs/server/request-context) that says where the message came from. Combine it with [`tools()`](/docs/mastra-platform/connect/tools#filter-tools-per-request) to give the agent a different toolset per conversation, such as read-only tools in group channels and the full set in direct messages:

```typescript title="src/mastra/agents/assistant.ts"
import { Agent } from '@mastra/core/agent'
import type { ChannelContext } from '@mastra/core/channels'
import { tools } from '@mastra/connect'

const connected = tools()

export const assistant = new Agent({
  name: 'assistant',
  instructions: 'You help the team from Slack and Discord.',
  model: 'openai/gpt-5-mini',
  tools: async ({ requestContext }) => {
    const channel = requestContext?.get('channel') as ChannelContext | undefined
    const all = await connected()

    // Anyone can talk to the agent in a group channel, so keep writes out of reach there.
    if (channel && !channel.isDM) {
      return Object.fromEntries(
        Object.entries(all).filter(([key]) => !/create|update|delete|send/.test(key)),
      )
    }
    return all
  },
})
```

The channel context carries the platform, the channel and thread IDs, and the sender's identity, so the same pattern can branch per platform or per user. The [Slack guide](/integrations/channels/slack#request-context) lists every field.

## Bring your own app instead

To configure a Slack app, Telegram bot, or Discord bot yourself, skip Connect and follow the platform guides on [Channels](/docs/channels).

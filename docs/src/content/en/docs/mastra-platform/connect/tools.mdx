# Tools

[`tools()`](/reference/connect/tools) gives an agent ready-made tools for every provider connected to your project, such as `linear_list_issues` and `linear_create_issue` for Linear. You write no tool code and store no provider credential: each call goes through the platform proxy, which adds the connection's credential before forwarding the request.

## Add tools to an agent

Pass `tools()` to the agent's `tools` option:

```typescript title="src/mastra/agents/ops.ts"
import { Agent } from '@mastra/core/agent'
import { tools } from '@mastra/connect'

export const opsAgent = new Agent({
  id: 'ops',
  name: 'ops',
  instructions: 'You help the team track work in Linear and GitHub.',
  model: '__GATEWAY_OPENAI_MODEL_MINI__',
  tools: tools(),
})
```

With no options, the agent gets the tools for every connected provider. The resolver caches them for 30 seconds by default. The first call after the cache expires returns the cached tools and starts a background refresh. Later calls use the refreshed tools once that request finishes, without a restart. Because refreshes depend on resolver calls, an idle app doesn't poll for connection changes.

## Combine with your own tools

To give an agent connect tools alongside tools you define yourself, spread the resolver's result in a `tools` function. Your tools win when a key collides:

```typescript title="src/mastra/agents/ops.ts"
import { Agent } from '@mastra/core/agent'
import { tools } from '@mastra/connect'
import { weatherTool } from '../tools/weather'

const connected = tools()

export const opsAgent = new Agent({
  id: 'ops',
  name: 'ops',
  instructions: 'You help the team track work in Linear and GitHub.',
  model: '__GATEWAY_OPENAI_MODEL_MINI__',
  tools: async ctx => ({ ...(await connected(ctx)), weatherTool }),
})
```

## Limit what an agent can use

The `providers` option lists the providers an agent gets. Pass an array of provider IDs to allow only those:

```typescript
tools({
  providers: ['linear', 'github'],
})
```

Pass an object to configure providers individually. `true` enables a provider with defaults, `false` excludes it even when connected, and an options object filters its tools. Each provider takes either `allowTools` or `disallowTools`, not both:

```typescript
tools({
  providers: {
    linear: { allowTools: ['linear_list_issues', 'linear_create_issue'] },
    github: { disallowTools: ['github_delete_*', 'github_merge_pull_request'] },
    slack: false,
  },
})
```

Tool entries accept `*` globs, so `github_delete_*` covers every delete tool. Check tool keys against the [provider toolsets reference](/reference/connect/providers). A misspelled tool key, or a glob that matches nothing, fails resolution with an error instead of being ignored. The same goes for a misspelled provider ID: an enabled ID that matches no provider fails resolution, so a typo can't silently drop a provider.

To apply one policy across providers, set `allowTools`, `disallowTools`, or `requireApproval` at the top level. Per-provider options win:

```typescript
tools({
  allowTools: ['*_list_*', '*_get_*', '*_search_*'],
  providers: {
    // Its own filter opts linear out of the top-level allowlist.
    linear: { allowTools: ['linear_list_issues', 'linear_create_issue'] },
  },
})
```

Top-level entries apply leniently per provider. An entry that matches nothing on one provider doesn't apply there, and only an entry that matches nothing anywhere logs a warning.

## Filter tools per request

`providers` fixes the toolset when the agent is built. To decide per request, pass a function as the agent's `tools` option. Mastra calls it on every `generate()` and `stream()` with the [request context](/docs/server/request-context), so you can call the resolver inside and filter what it returns:

```typescript title="src/mastra/agents/ops.ts"
import { Agent } from '@mastra/core/agent'
import { tools } from '@mastra/connect'

const connected = tools()

export const opsAgent = new Agent({
  id: 'ops',
  name: 'ops',
  instructions: 'You help the team track work in Linear and GitHub.',
  model: '__GATEWAY_OPENAI_MODEL_MINI__',
  tools: async ({ requestContext }) => {
    const all = await connected()

    // Viewers get Linear tools only, and nothing destructive.
    if (requestContext?.get('role') === 'viewer') {
      return Object.fromEntries(
        Object.entries(all).filter(([key]) => key.startsWith('linear_') && !key.includes('delete')),
      )
    }
    return all
  },
})
```

Tool keys start with the provider, so a key prefix such as `linear_` filters a whole provider in or out. Calling `connected()` on every request stays cheap because the resolver serves its cached snapshot. [Request context](/docs/server/request-context) shows how to set the values from middleware or per call.

## Choose between connections

If a project links two Slack workspaces, the agent chooses a workspace on each call. The same applies to any provider with more than one connection: the toolset gains a `<provider>__list_connections` tool, and every other tool takes a `connection_name` input. Give connections [names you can tell apart](/docs/mastra-platform/connect/connections#name-connections).

To always use one connection, pin it:

```typescript
tools({
  providers: {
    slack: { connectionId: 'c_yourconnectionid' },
  },
})
```

## Use MCP providers

Some providers serve their tools from a hosted Model Context Protocol (MCP) server instead of a generated toolset. `tools()` loads those tools from the provider at runtime, so tool keys take the form `<provider-id>_<tool-name>` and can change without a package upgrade. [Providers](/docs/mastra-platform/connect/providers#mcp-providers) lists them.

Tools run without [tool approval](/docs/agents/human-in-the-loop) unless you ask for it. Set `requireApproval` on a provider to make the agent pause for a human before risky calls. Pass `true` to cover every tool from that provider, or list tool keys:

```typescript
tools({
  providers: {
    'neon-mcp': { requireApproval: ['neon-mcp_run_sql'] },
    'robinhood-mcp': { requireApproval: true },
  },
})
```

`requireApproval` works on any provider, not only MCP ones. A misspelled tool key in the list fails resolution with an error instead of being ignored, so a typo can't silently drop an approval gate.

## Pass tools at call time

Call the resolver to get the current tools as a plain record, for example to pass them for a single `generate()` call:

```typescript
import { tools } from '@mastra/connect'

const connected = tools()

const response = await agent.generate('Summarize my open issues.', {
  toolsets: { connect: await connected() },
})
```

Use `await connected.refresh()` to fetch the current connections and wait for the updated tool record instead of using the cached snapshot. See [the resolver](/reference/connect/tools#the-resolver) for the other methods.

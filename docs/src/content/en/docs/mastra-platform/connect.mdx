# Connect

`@mastra/connect` lets your application use the [provider connections](/docs/mastra-platform/providers) attached to a Mastra platform project:

- [`tools()`](/reference/connect/tools): a live toolset resolver for agents.
- [`channels()`](/reference/connect/channels): chat channel providers (Slack, Telegram, Discord) for `Mastra({ channels })`.
- [`credential()`](/reference/connect/credential): the raw credential for a connection, for custom SDK or MCP use.

Follow this page to connect a provider from the terminal and give an agent its tools. Platform-side setup, multiple connections, and re-authentication are covered in [Providers](/docs/mastra-platform/providers).

## Prerequisites

- A [Mastra platform](/docs/mastra-platform/overview) project to hold the connections.
- The [`mastra` CLI](/reference/cli/mastra), signed in with `mastra auth login`.

The CLI resolves the target project from `MASTRA_PROJECT_ID`, the `--project` flag, or the `.mastra-project.json` written by `mastra deploy`.

## Install

```bash npm2yarn
npm install @mastra/connect
```

## Connect a provider

Start with the catalog. `mastra connect list` prints every provider, with the ones already connected to your project in green:

```bash
mastra connect list
```

Pick one and connect it:

```bash
mastra connect add linear
```

What happens next depends on the provider's auth type. OAuth providers like Linear open a consent screen in your browser, and the CLI waits until the connection becomes active. API key and Basic auth providers prompt for credentials in the terminal.

If your organization already has Linear connections that aren't attached to this project, the CLI offers to reuse one instead of running the auth flow again. Once a new connection is active, it offers to set a display name, which helps you tell connections apart when a project holds several for the same provider. Pass `--yes` to skip every prompt and always create a new, unnamed connection.

To unlink a provider from the project later:

```bash
mastra connect remove linear
```

The organization keeps the underlying connection, so a later `mastra connect add` can re-attach it without re-authorizing.

Providers can also be connected from the project's **Integrations** tab in the dashboard. [Providers](/docs/mastra-platform/providers#connect-a-provider) covers the full flow.

## Configure the environment

At runtime, `@mastra/connect` authenticates to the platform with an access token:

```bash
mastra auth tokens create
```

Put the token alongside the project ID in your app's environment:

```bash title=".env"
MASTRA_PLATFORM_ACCESS_TOKEN=your-token
MASTRA_PROJECT_ID=your-project-id
```

Both values can also be passed explicitly through options. See the [full environment variable list](/docs/mastra-platform/providers#environment-variables).

## Give an agent connected tools

[`tools()`](/reference/connect/tools) returns a live toolset resolver over your project's connections. Pass it straight to an agent's `tools` and Mastra calls it on every generate/stream:

```typescript title="src/mastra/agents/ops.ts"
import { Agent } from '@mastra/core/agent'
import { tools } from '@mastra/connect'

export const opsAgent = new Agent({
  name: 'ops',
  instructions: 'You manage our workspaces.',
  model: 'openai/gpt-5-mini',
  tools: tools(),
})
```

With no options, every connected provider with a generated toolset is included. The resolver caches its snapshot and revalidates from the platform every 30 seconds. Run `mastra connect add` while the server is running, or connect from the dashboard, and the new provider's tools show up without a restart.

Ask the agent to do something with a connected provider:

```typescript
const response = await opsAgent.generate('Summarize my open Linear issues.')
```

The agent sees tools like `linear_list_issues` and `linear_create_issue`. Each call is proxied through the platform, which injects the connection's credentials server-side.

## Limit what an agent can touch

The `integrations` option is an allowlist. The string-array shorthand enables providers with no overrides:

```typescript
const opsTools = tools({
  integrations: ['linear', 'github'],
})
```

Use the object form for per-provider control. `allowTools` and `disallowTools` are mutually exclusive per provider, and unknown provider IDs or tool names throw at startup, so typos surface before an agent runs:

```typescript
const opsTools = tools({
  integrations: {
    linear: { allowTools: ['linear_list_issues', 'linear_create_issue'] },
    github: { disallowTools: ['github_delete_repository'] },
    slack: { disabled: true },
  },
})
```

## Resolve toolsets on demand

Call the resolver directly when you want the current tool record, for example for the `toolsets` option at generate time:

```typescript
import { tools } from '@mastra/connect'

const connected = tools()

const toolsets = await connected()

const response = await agent.generate('Summarize my open issues.', { toolsets })
```

The resolver also exposes `invalidate()`, `refresh()`, and `disconnect()`. Call `refresh()` to pick up a newly attached connection without waiting for the TTL.

## Add chat channels

For channel-capable providers, [`channels()`](/reference/connect/channels) resolves the same project connections into `ChannelProvider` instances and plugs into `Mastra({ channels })`:

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { channels } from '@mastra/connect'

export const mastra = new Mastra({
  // ...
  channels: await channels(),
})
```

`channels()` is async: provider instances are constructed up front so their webhook and OAuth routes mount at `Mastra` construction. Slack, Telegram, and Discord are supported, backed by `@mastra/slack`, `@mastra/telegram`, and `@mastra/discord`. See the [`channels()` reference](/reference/connect/channels).

## Custom interactions with `credential()`

For use cases the toolsets don't cover, such as driving a provider SDK directly, [`credential()`](/reference/connect/credential) fetches the raw credential for a connection:

```typescript
import { credential } from '@mastra/connect'

const cred = await credential('c_yourconnectionid')

if (cred.type === 'oauth2') {
  startSdkSession(cred.accessToken)
} else {
  startSdkSession(cred.apiKey)
}
```

Handle returned credentials carefully. They grant direct access to the provider account and bypass the proxy's guardrails.

# MCP server on Mastra platform

The Mastra platform MCP server gives AI assistants access to your organization's [Observability](/docs/mastra-platform/observability) data through the [Model Context Protocol (MCP)](https://modelcontextprotocol.io/docs/getting-started/intro). Connect it to Claude Code, Codex, or another MCP client, then ask questions about your traces, logs, metrics, scores, and feedback in chat. The assistant can also chart the results and save them to dashboards on Mastra platform.

## Connect your MCP client

You need a Mastra platform account and membership in the organization whose data you want to query.

<Tabs>
  <TabItem value="claude-code" label="Claude Code">
    Add the server:

    ```bash
    claude mcp add --transport http mastra https://platform.mastra.ai/v1/mcp
    ```

    Start Claude Code, run `/mcp`, select **mastra**, and choose to authenticate.
  </TabItem>

  <TabItem value="codex" label="Codex">
    Add the server:

    ```bash
    codex mcp add mastra --url https://platform.mastra.ai/v1/mcp
    ```

    Sign in:

    ```bash
    codex mcp login mastra
    ```
  </TabItem>

  <TabItem value="json" label="mcp.json">
    Add the server to your client's MCP configuration file:

    ```json title="mcp.json"
    {
      "mcpServers": {
        "mastra": {
          "type": "http",
          "url": "https://platform.mastra.ai/v1/mcp"
        }
      }
    }
    ```

    Restart the client and follow its prompt to authenticate the **mastra** server.
  </TabItem>
</Tabs>

Authentication uses OAuth. Your browser opens the Mastra sign-in page, where you sign in and select an organization. The connection acts as you in that organization, so it can read the same data you can. Removing your membership from the organization revokes access on the next request.

## Scope queries to a project

Tools read data across the whole organization by default. To focus on one project, name it in your request, for example "in the `checkout` project". The assistant passes the project ID or slug from `list_projects` to each tool. Score tools always need a project.

## Available tools

The server provides read-only tools for observability data and tools that create and edit dashboards.

### Traces and spans

| Tool | Description |
| - | - |
| `query_traces` | Search traces by entity, status, time range, metadata, and other fields. |
| `aggregate_traces` | Count traces and compute durations and error rates, optionally grouped and bucketed over time. |
| `get_trace_query_fields` | List the fields that `query_traces` can filter and group on. |
| `get_trace_query_values` | List the values recorded for one trace query field. |
| `get_trace` | Get a trace as a tree of lightweight span records. |
| `get_span` | Get one span, including its input, output, and attributes. |
| `query_spans` | Search individual spans, such as model calls, tool calls, and workflow steps, across traces. |
| `aggregate_spans` | Count spans and compute durations and token usage, optionally grouped and bucketed over time. |
| `query_threads` | Search conversation threads by the traces recorded in them. |

### Logs, metrics, scores, and feedback

| Tool | Description |
| - | - |
| `list_logs` | List log records, filtered by level, trace, entity, or time range. |
| `list_scores` | List scorer results, filtered by scorer, trace, entity, or time range. |
| `list_feedback` | List user feedback, filtered by trace, entity, or time range. |
| `analyze_metrics` | Aggregate metrics such as tokens, cost, latency, and counts as a single value, a breakdown by label, a time series, or percentiles. |
| `analyze_scores` | Aggregate scorer results as a single value, a breakdown, a time series, or percentiles. |
| `analyze_feedback` | Aggregate user feedback as a single value, a breakdown, a time series, or percentiles. |
| `list_metric_names` | List metric names, a metric's label keys, or a label's values. |
| `discover_observability` | List the metric names, labels, entities, environments, and tags the organization or a project records. |

### Dashboards

| Tool | Description |
| - | - |
| `show_observability_dashboard` | Draw charts in the chat. |
| `list_dashboards` | List the organization's or a project's dashboards. |
| `get_dashboard` | Read a dashboard and its cards. |
| `create_dashboard` | Create a dashboard, optionally with a first card. |
| `rename_dashboard` | Rename a dashboard or change its description. The Metrics dashboard can't be renamed. |
| `add_dashboard_widget` | Add a card to a dashboard, such as a chart shown with `show_observability_dashboard`. |
| `update_dashboard_widget` | Replace a card's chart or change its title. |
| `remove_dashboard_widgets` | Remove cards from a dashboard. |

### Account

| Tool | Description |
| - | - |
| `whoami` | Report the organization and user the connection acts as. |
| `list_projects` | List the organization's projects. |

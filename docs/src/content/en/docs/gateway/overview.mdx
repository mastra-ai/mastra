# Gateway

Mastra Gateway lets you call models from many providers through one managed API. It centralizes credentials, fails over between providers, controls spend, and records the cost of every request. You don't have to run your own proxy or routing layer.

Gateway uses the OpenAI and Anthropic wire formats. To use it with an existing SDK or framework, change the base URL and the API key. The model ID picks the provider:

<Tabs>
  <TabItem value="mastra" label="Mastra">
    ```typescript title="src/mastra/agents/assistant.ts"
    import { Agent } from '@mastra/core/agent'

    export const assistant = new Agent({
      id: 'assistant',
      name: 'Assistant',
      instructions: 'You are a helpful assistant.',
      model: 'mastra/__GATEWAY_OPENAI_MODEL__',
    })
    ```
  </TabItem>

  <TabItem value="typescript" label="OpenAI SDK">
    ```typescript title="index.ts"
    import OpenAI from 'openai'

    const client = new OpenAI({
      baseURL: 'https://gateway-api.mastra.ai/v1',
      apiKey: process.env.MASTRA_GATEWAY_API_KEY,
    })

    const completion = await client.chat.completions.create({
      model: '__GATEWAY_ANTHROPIC_MODEL_SONNET__',
      messages: [{ role: 'user', content: 'Explain Mastra Gateway in one sentence.' }],
    })

    console.log(completion.choices[0].message.content)
    ```
  </TabItem>

  <TabItem value="python" label="Python">
    ```python title="main.py"
    import os
    from openai import OpenAI

    client = OpenAI(
        base_url="https://gateway-api.mastra.ai/v1",
        api_key=os.environ["MASTRA_GATEWAY_API_KEY"],
    )

    completion = client.chat.completions.create(
        model="__GATEWAY_GOOGLE_MODEL_FLASH__",
        messages=[{"role": "user", "content": "Explain Mastra Gateway in one sentence."}],
    )

    print(completion.choices[0].message.content)
    ```
  </TabItem>

  <TabItem value="curl" label="cURL">

      -d '{

## Connect from your stack

| If you use | Connect with |
| - | - |
| Mastra framework | A `mastra/provider/model` model ID and the `MASTRA_GATEWAY_API_KEY` environment variable. See [Integrations](/docs/gateway/integrations#mastra-framework). |
| AI SDK | The OpenAI-compatible or Anthropic provider with the Gateway base URL. See [Integrations](/docs/gateway/integrations#ai-sdk). |
| OpenAI SDK (TypeScript or Python) | `baseURL` set to `https://gateway-api.mastra.ai/v1`. See [Chat Completions](/docs/gateway/api/chat-completions) and [Responses](/docs/gateway/api/responses). |
| Anthropic SDK | `baseURL` set to `https://gateway-api.mastra.ai`, without `/v1`. See [Anthropic Messages](/docs/gateway/api/messages). |
| LangGraph, Deep Agents, or Pydantic AI | The framework's OpenAI-compatible model client. See [Integrations](/docs/gateway/integrations). |
| Any other language | Any HTTP client that can call the [OpenAI](/docs/gateway/api/chat-completions) or [Anthropic](/docs/gateway/api/messages) API. |

## What Gateway handles

| Requirement | How Gateway handles it |
| - | - |
| Centralized credentials | Your app authenticates with one Gateway key. Gateway calls providers with Mastra-managed credentials, or with your own provider accounts through [BYOK](/docs/gateway/keys-and-byok#bring-your-own-key). |
| Provider failover | When a provider fails before any output reaches your client, Gateway retries the request on another eligible route. The `x-gateway-provider` response header names the provider that served it. See [Models and routing](/docs/gateway/models-and-routing). |
| Key scoping | Project keys attribute usage to one project. Organization keys cover the whole organization. Each key can have an expiry date and a list of allowed models. See [Keys and BYOK](/docs/gateway/keys-and-byok). |
| Cost tracking | Each request records its model, its provider attempts, its token counts, and its cost. Search usage logs by the `x-request-id` header. See [Usage, pricing, and limits](/docs/gateway/usage-and-limits#usage-logs). |
| Spending controls | An organization spend cap rejects new requests with `402` when it's reached. Per-key spend limits are rolling out. See [Usage, pricing, and limits](/docs/gateway/usage-and-limits#spend-caps). |
| Rate limits | Each key has request-rate limits. Responses with status `429` include `retry-after` and headers that name which limit was hit. See [Usage, pricing, and limits](/docs/gateway/usage-and-limits#rate-limits). |
| Built-in tools | Add `mastra:web_search` to any chat model. Gateway runs the search and reuses the results if the request fails over. See [Web search](/docs/gateway/web-search). |

You pay only for the attempt that served your request. Failed attempts aren't charged. BYOK requests are billed by your provider, not from Mastra credit. Your provider's own limits and behavior apply to BYOK requests, and they don't fail over. Gateway doesn't store prompts or completions.

:::note

Conversation memory is a separate product. To give agents memory, see [Memory](/docs/memory/overview).

:::

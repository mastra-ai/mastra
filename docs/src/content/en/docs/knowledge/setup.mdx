# Set up Knowledge

:::warning

Knowledge is experimental and can change without notice.

:::

A `Knowledge` instance needs the scope types its runs hold, somewhere to store pages, and the tools its agents should get.

## Create the instance

```typescript title="src/mastra/knowledge.ts"
import { Knowledge, knowledgeMemoryScopes } from '@mastra/core/knowledge'
import { LibSQLStore } from '@mastra/libsql'

export const knowledge = new Knowledge({
  id: 'company',
  storage: new LibSQLStore({ id: 'knowledge', url: 'file:./knowledge.db' }),
  scopes: { ...knowledgeMemoryScopes() },
  tools: true,
})
```

`scopes` is required. It declares every scope type your runs hold and who gets which role on them. Pass `{}` to declare nothing. See [declare scope types](/docs/knowledge/scope-types).

Leave out `storage` to use the storage configured on `Mastra`. Knowledge storage is supported by `LibSQLStore`, `PostgresStore`, `MySQLStore`, `MongoDBStore` and `InMemoryStore` (for tests).

Without a vector store, search matches pages and notes that contain every word of the query, case-insensitively. See [add semantic search](#add-semantic-search) to also match by meaning.

## Add semantic search

Pass a `vector` store and an `embedder` to match pages and notes by meaning as well as by keyword. A search for "reimbursement" then finds a page about getting money back, with no shared word:

```typescript title="src/mastra/knowledge.ts"
import { Knowledge, knowledgeMemoryScopes } from '@mastra/core/knowledge'
import { ModelRouterEmbeddingModel } from '@mastra/core/llm'
import { LibSQLStore, LibSQLVector } from '@mastra/libsql'

export const knowledge = new Knowledge({
  id: 'company',
  storage: new LibSQLStore({ id: 'knowledge', url: 'file:./knowledge.db' }),
  vector: new LibSQLVector({ id: 'knowledge-vector', url: 'file:./knowledge.db' }),
  embedder: new ModelRouterEmbeddingModel('openai/text-embedding-3-small'),
  scopes: { ...knowledgeMemoryScopes() },
  tools: true,
})
```

Pass both or neither. Passing only one throws ``Knowledge semantic search needs both `vector` and `embedder`; pass both or neither.`` `embedderOptions` (`maxRetries`, `headers`, `providerOptions`, `telemetry`) applies to every embedding call, the same way it does in Memory. `maxRetries` retries transient provider errors.

`knowledge_search` then blends keyword and semantic results into one ranked list. Every semantic hit is read again with the run's access before it can take a place in the results. A run never sees content it can't read, and that content never takes a slot from content it can.

Pages and notes written through the tools are embedded as they're written. Scope pages aren't embedded, but notes on them are. Run `reindex()` to re-embed every page and note. It returns how many it indexed. Run it after:

- Content written straight to the store, outside the tools.
- A write that logged `Knowledge semantic index update failed; run knowledge.reindex() to repair`. The write itself succeeded. Only search by meaning misses it until you reindex.

```typescript
const indexed = await knowledge.reindex()
```

If the embedder or vector store fails during a search, the search returns keyword results and logs a warning.

## Choose the tools

Tools are off by default, so an agent with Knowledge attached gets nothing until you turn them on:

| `tools` | Tools the agent gets |
| - | - |
| `true` | `knowledge_search`, `knowledge_read`, `knowledge_page`, `knowledge_note` |
| `{ read: true }` | `knowledge_search`, `knowledge_read` |
| `{ write: true }` | `knowledge_page`, `knowledge_note`, for agents that only ingest |

Set `pinnedContext: true` to add `knowledge_pin` and deliver pinned pages every turn. See [pins](/docs/knowledge/pins).

The tools only offer what a run's roles allow at call time. Turning on `write` doesn't let a run write anywhere it has no role.

## Attach to an agent

Pass the instance as `knowledge` on the agent:

```typescript title="src/mastra/agents/support.ts"
import { Agent } from '@mastra/core/agent'
import { knowledge } from '../knowledge'

export const support = new Agent({
  id: 'support',
  name: 'Support',
  instructions: 'You answer customer questions.',
  model: '__GATEWAY_OPENAI_MODEL__',
  knowledge,
})
```

You can also register the instance on `Mastra` and pass its key, as in `knowledge: 'company'`.

An agent without Memory works too, as long as its runs have `scopes`. Without either, the tools fail with:

```text
Knowledge tools need run scopes: give the agent or the call `scopes`, or run it with Memory.
```

## Use the tools without attaching

`createTools()` returns the tools for your own agent setup, and `getInstructions()` returns the usage block that goes with them. Both take `{ read, write, pinnedContext }` to override which groups they cover:

```typescript
const tools = knowledge.createTools({ read: true })
const instructions = knowledge.getInstructions({ read: true })
```

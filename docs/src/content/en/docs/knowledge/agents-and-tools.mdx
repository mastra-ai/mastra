# Agents and tools

:::alpha

Knowledge is in alpha. Its API may change between releases.

:::

An agent with Knowledge attached works with it through tools. You choose which tools it gets, and your [scope declarations](/docs/knowledge/scopes-and-access) decide what each call may do.

## Turn on the tools

Tools are off by default. Turn on reading and writing:

```typescript title="src/mastra/knowledge.ts"
const knowledge = new Knowledge({
  id: 'company',
  scopes,
  tools: true,
})
```

For an agent that only answers from Knowledge, such as a docs or support agent, turn on reading alone:

```typescript
const knowledge = new Knowledge({
  id: 'docs',
  scopes,
  tools: { read: true },
})
```

`tools: { write: true }` turns on writing alone. To let agents pin pages, add `pinnedContext: true`. See [Pinned context](/docs/knowledge/pinned-context).

## What agents can read

With the read tools, an agent finds and reads what its run can see. It can browse how a scope is organized, search pages and notes by keyword (and by meaning, with [semantic search](/docs/knowledge/search#add-search-by-meaning)), and read a page with its notes and the notes on other pages that mention it. A long page comes back in parts: the first read shows the page's headings, and the agent then reads the section it needs, reads on from a line, or reads only the lines that match a term. When nothing matches, the result says so, so the agent can tell the user it doesn't know instead of guessing.

One read returns at most 1,000 tokens of a page by default. Raise the cap for models with large context windows, or lower it for small models:

```typescript
const knowledge = new Knowledge({
  id: 'docs',
  scopes,
  tools: { read: { maxTokens: 3000 }, write: true },
})
```

## What agents can write

With the write tools, an agent creates pages in the scopes it can write to, and puts each one where its audience is: a fact for the whole team in the team's scope, one for this user only in the user's scope. It edits a page by changing only the lines it read, so it never overwrites parts of a long page it hasn't seen, and an edit is refused if someone changed the page since the agent read it. It can also move, merge and delete pages, and add notes: short attributed facts on a page, which can link to other pages and carry their own audience.

## What a call is allowed to do

Turning on a tool doesn't grant access. Each call is checked against the roles the run holds in the scopes it touches: reading needs `viewer`, creating pages and adding notes needs `contributor`, editing needs `editor`, and deleting needs `owner`. A refused call comes back to the model as the tool result, not as an exception in your code. See [what each operation needs](/reference/knowledge/knowledge-tools#what-each-operation-needs).

Knowledge also adds short usage instructions for the tools it turns on, so you don't need to explain them in your agent's instructions. See [Tool instructions](/reference/knowledge/tool-instructions) to change them. To give the tools to an agent without attaching the instance, use [`createTools()`](/reference/knowledge/knowledge-class#createtools).

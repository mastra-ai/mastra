# Load your content

Agents write to Knowledge as they work, but you often want content in place before they start, such as your product docs or company policies. Seed it from your own server code with [`upsertPage()`](/reference/knowledge/knowledge-class#upsertpage) and [`addNote()`](/reference/knowledge/knowledge-class#addnote).

To keep Knowledge in step with another system, such as an issue tracker or a wiki, wrap the same writes in an [importer](#sync-with-an-importer).

:::alpha

Knowledge is in alpha. Its API may change between releases.

:::

## Declare a scope for the content

Give the seeded content its own scope type, and say who can read it:

```typescript title="src/mastra/knowledge.ts"
import { Knowledge, knowledgeMemoryScopes } from '@mastra/core/knowledge'
import { LibSQLStore } from '@mastra/libsql'

export const knowledge = new Knowledge({
  id: 'company',
  storage: new LibSQLStore({ id: 'knowledge', url: 'file:./knowledge.db' }),
  scopes: {
    ...knowledgeMemoryScopes(),
    'docs:$orgId': {
      description: 'Product docs',
      belongsTo: 'org:$orgId',
      access: [{ principal: 'org:$orgId', role: 'viewer' }],
    },
  },
  tools: true,
})
```

`belongsTo` places the docs under the org in the scope tree. Agents in the org can read these pages but not change them.

## Write the pages

Write each document to a path in that scope. A path such as `guides/install` becomes the page `docs:acme#guides/install`, and missing pages along the path are created:

```typescript title="src/seed-docs.ts"
import { knowledge } from './mastra/knowledge'

type Doc = { slug: string; title: string; markdown: string }

export async function seedDocs(orgId: string, docs: Doc[]) {
  for (const doc of docs) {
    await knowledge.upsertPage({
      scope: `docs:${orgId}`,
      path: doc.slug,
      name: doc.title,
      body: doc.markdown,
      author: 'seed:docs',
    })
  }
}
```

Agents whose runs hold `org:acme` can now find these pages with search and read them. If you set `vector` and `embedder`, `upsertPage()` also embeds each page for [search by meaning](/docs/knowledge/search#add-search-by-meaning).

To add a dated fact or a comment to a page, add a note. The `[[docs:acme#releases/2026-12]]` mention becomes a link once that page exists:

```typescript title="src/seed-docs.ts"
await knowledge.addNote({
  scope: 'docs:acme',
  path: 'guides/install',
  text: 'Node 18 support ends on [[docs:acme#releases/2026-12]].',
  when: new Date('2026-11-01'),
  author: 'seed:docs',
})
```

These methods are for trusted server code. They don't check run scopes or access rules, so don't call them from an agent tool or from a route without admin-level auth.

## Keep content in sync

Run the seed again when your source changes. `upsertPage()` updates changed pages and skips unchanged ones, so a re-run doesn't rewrite or re-embed them.

`addNote()` adds a new note on every call. Running the seed twice leaves duplicate notes. Add notes once, or change an existing note with [`updateNote()`](/reference/knowledge/knowledge-class#updatenote).

A document you delete from your source stays in Knowledge. Remove it with [`removePage()`](/reference/knowledge/knowledge-class#removepage). A page with child pages can't be removed until its children are.

## Sync with an importer

An importer is a seed that Knowledge runs for you. It records each run, keeps a cursor between runs, and removes the pages its source no longer has. Write one with `id` and `run()`, and write pages through `ctx.pages`:

```typescript title="src/mastra/docs-importer.ts"
import type { KnowledgeImporter } from '@mastra/core/knowledge'

type Doc = { slug: string; title: string; markdown: string }

export const docsImporter: KnowledgeImporter<{ orgId: string }> = {
  id: 'docs',
  async run(ctx) {
    const docs: Doc[] = await fetch('https://docs.example.com/export.json', { signal: ctx.signal }).then(res =>
      res.json(),
    )
    for (const doc of docs) {
      await ctx.pages.upsert({
        scope: `docs:${ctx.options.orgId}`,
        path: doc.slug,
        name: doc.title,
        body: doc.markdown,
      })
    }
  },
}
```

Register it on Knowledge, then run it from a job or an admin route:

```typescript title="src/mastra/knowledge.ts"
export const knowledge = new Knowledge({
  // ...
  importers: [docsImporter],
})

const run = await knowledge.runImporter('docs', { options: { orgId: 'acme' } })
console.log(run.status, run.counts) // succeeded { created: 12, updated: 0, unchanged: 0, removed: 0, notes: 0 }
```

Every write is recorded with the author `importer:docs`. After a run succeeds, Knowledge removes pages this importer created in earlier runs and didn't write this time, so a doc you delete from the source leaves Knowledge on the next run. A page someone else created is never removed, even if the importer writes to it. A run that throws or is aborted is recorded as `failed` or `canceled`: it keeps the writes it already made, but removes no stale pages and saves no state.

An importer that fetches only what changed since its last run should run with `incremental: true`, which removes nothing, and save its cursor with `ctx.state`:

```typescript title="src/mastra/docs-importer.ts"
const since = await ctx.state.get<string>('since')
// fetch docs changed after `since`, upsert them, and ctx.pages.remove() the deleted ones
await ctx.state.set('since', new Date().toISOString())
```

Pass `dryRun: true` to see what a run would change. It writes no pages and saves no state, and its counts say what it would have done. Importers need LibSQL, PostgreSQL or in-memory storage. Only one run of an importer happens at a time on a `Knowledge` instance. A second call throws `KnowledgeImporterBusyError`, so schedule each importer on one worker.

# Knowledge in Mastra Code

:::warning

Knowledge is experimental and can change without notice.

:::

Knowledge is off in Mastra Code until you turn it on.

## Turn it on in the TUI

Open `/settings`, turn on **Experimental Knowledge**, and restart Mastra Code. The code agent then gets the Knowledge tools (search, read, write, and pin) and pinned context every turn. Knowledge is stored with Mastra Code's own storage under a shared `org:local` scope.

## Attach your own Knowledge

When you embed Mastra Code, attach Knowledge the way you would on an agent, with `knowledge` and `scopes`:

```typescript
const code = await createMastraCode({
  knowledge: companyKnowledge,
  scopes: ['org:acme', { scope: 'team:acme:support', access: 'write' }],
})
```

Here every run reads `org:acme` and `team:acme:support` and writes only to `team:acme:support`. As everywhere else, a plain tag is read-only. See [read and write access](/docs/knowledge/concepts#read-and-write-access). The instance's own `tools` and `pinnedContext` options decide which tools the agent gets.

The instance is registered on the mounted Mastra runtime under its `id`. To register it under another key, pass `knowledge: { key: 'company', instance: companyKnowledge }`.

The `knowledge` option also accepts:

- `true`: the built-in Knowledge, the same one the TUI setting turns on. With no `scopes`, it writes to `org:local`.
- `false`: Knowledge stays off, even when the TUI setting is on.

## Session scopes

Local sessions act with the `scopes` you pass. Factory sessions always add writable `org:<org>` and `project:<project>` tags. The tags you pass keep the access you gave them.

If a Factory session has no organization, or a tag in `scopes` has the same type as one of those but a different value, the agent runs with only its `resource:` and `thread:` tags. Its writes are private to the run, and the `/knowledge` inspector reports Knowledge as unavailable.

In a Factory session, Knowledge is stored under `project:<projectId>` together with `org:<orgId>`. Knowledge written earlier under `resource:<projectId>` no longer shows.

By default the agent writes at all of its writable tags: org, project, its Memory resource, and the thread. Those records show only in that session's drill-down. To share a record with the whole project, have the agent write with `scope: ['org:<org>', 'project:<id>']`.

## Scopes per message

A long-lived session can change what a run is allowed to see for each task. Pass `scopes` to `session.sendMessage`. Entries take the same form as above: a plain tag is read-only, and `{ scope, access: 'write' }` is writable:

```typescript
await session.sendMessage({
  content: 'Fix the login bug',
  scopes: [{ scope: 'request:r25', access: 'write' }],
})
```

A run's scopes are fixed when it starts:

- A message with the same scopes, or none, joins the running run.
- A message with different scopes waits for the running run to end, then starts its own run in the same conversation.
- Several scoped messages sent in the meantime start in the order they were sent.

A scoped message to a thread whose run is owned by another process doesn't wait. It rejects with "scopes don't cross processes". Messages without scopes are unaffected.

`queueMessage`, `queueSignal`, `sendNotificationSignal`, and `steer` take `scopes` the same way. A queued message, steering message, or notification whose scopes differ from the running run's starts its own run after that one instead of joining it.

### Remote callers

Scopes are set in process only. Remote callers, through the agent controller HTTP routes or `@mastra/client-js`, can't send them, and the server drops `scopes` from a request body. To derive scopes from a request, give the agent a `scopes` function that reads trusted request context.

## Upgrading

`experimental_subconscious` and the Memory `knowledge` option are removed, and setting either throws. Attach Knowledge to the agent instead. The `MASTRACODE_EXPERIMENTAL_KNOWLEDGE` and `MASTRACODE_EXPERIMENTAL_SUBCONSCIOUS` environment variables do nothing.

Scope entries changed shape. A plain tag used to be writable and is now read-only. Mark tags the run should write to as `{ scope, access: 'write' }`. The old `{ tag, access: 'read' }` form is gone, because a plain tag already means read-only.

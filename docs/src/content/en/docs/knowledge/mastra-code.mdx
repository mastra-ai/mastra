# Knowledge in Mastra Code

:::warning

Knowledge is experimental and can change without notice.

:::

Mastra Code can attach Knowledge to its agent with read, write, and pin tools on. Set `MASTRACODE_EXPERIMENTAL_KNOWLEDGE=1` to use a default instance on the session's storage.

To supply your own, pass `knowledge` when creating the harness. `key` is the name it's registered under on the Mastra runtime and defaults to `'default'`. `scopes` are the tags every run acts with:

```typescript
const code = await createMastraCode({
  knowledge: {
    instance: companyKnowledge,
    key: 'company',
    scopes: [{ tag: 'org:acme', access: 'read' }, 'team:acme:support'],
  },
})
```

Pass `knowledge: false` to turn Knowledge off, even when the environment variable is set.

## Session scopes

Local sessions run as `org:local` only when you pass no scopes. Factory sessions always add `org:<org>` and `project:<project>` tags.

If a Factory session has no organization, or a tag in `scopes` has the same type as one of those but a different value, the agent runs with only its `resource:` and `thread:` tags. Its writes are private to the run, and the `/knowledge` inspector reports Knowledge as unavailable.

In a Factory session, Knowledge is stored under `project:<projectId>` together with `org:<orgId>`. Knowledge written earlier under `resource:<projectId>` no longer shows.

By default the agent writes at all of its tags: org, project, its Memory resource, and the thread. Those records show only in that session's drill-down. To share a record with the whole project, have the agent write with `scope: ['org:<org>', 'project:<id>']`.

## Scopes per message

A long-lived session can change what a run is allowed to see for each task. Pass `scopes` to `session.sendMessage`. Entries can be plain tags or `{ tag, access: 'read' }`:

```typescript
await session.sendMessage({
  content: 'Fix the login bug',
  scopes: ['request:r25'],
})
```

A run's scopes are fixed when it starts:

- A message with the same scopes, or none, joins the running run.
- A message with different scopes waits for the running run to end, then starts its own run in the same conversation.
- Several scoped messages sent in the meantime start in the order they were sent.

A thread whose owner is in another process refuses scoped messages with "scopes don't cross processes".

## Upgrading

`experimental_subconscious` is removed. Attach Knowledge to the agent instead.

# Knowledge

Knowledge is a graph context system for agents. It works directly with [signals](/docs/signals/overview), Mastra's context engineering primitive. Signals bring the right knowledge into an agent's context and keep it current while the agent runs.

:::alpha

Knowledge is in alpha. Its API may change between releases.

:::

## When to use Knowledge

[Memory](/docs/memory/overview) is the conversation: the messages and observations that guide one agent's work in a thread. Knowledge is the organized information agents bring into a thread, shared across threads, agents and people.

Use Knowledge for:

- Documentation, policies or runbooks an agent should answer from instead of guessing.
- Decisions and conventions that several agents or users build on.
- Facts that only some runs may see, such as one customer's account notes or one team's playbooks.

## What Knowledge is

Knowledge holds **pages** and **notes** that agents read and write across conversations. A page is a topic with a name, a short description and a markdown body. A note is a short, attributed fact added to a page. A note can mention other pages, and those mentions link pages together in the context graph. Knowledge is divided into separate subgraphs by its **scope** system. A scope, such as `org:acme` or `team:acme:support`, is a subgraph that controls who can access that area and what they're allowed to do there. Inside a scope, pages nest like folders.

## Quickstart

Declare the scope types, turn on the tools, and attach the instance to an agent:

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Agent } from '@mastra/core/agent'
import { Knowledge, knowledgeMemoryScopes } from '@mastra/core/knowledge'
import { LibSQLStore } from '@mastra/libsql'
import { Memory } from '@mastra/memory'

const storage = new LibSQLStore({ id: 'storage', url: 'file:./mastra.db' })

export const knowledge = new Knowledge({
  id: 'company',
  storage,
  scopes: { ...knowledgeMemoryScopes() },
  tools: true,
})

export const agent = new Agent({
  id: 'assistant',
  name: 'Assistant',
  instructions: 'You help your team and keep its knowledge up to date.',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory({ storage }),
  knowledge,
})

export const mastra = new Mastra({ agents: { agent } })
```

`knowledgeMemoryScopes()` sets up three kinds of scope: one per org, one per user and one per conversation thread. Your server code says which ones each call holds:

```typescript
await agent.generate('Our refund window is 30 days. Save that for the team.', {
  scopes: [`org:${user.orgId}`, `resource:${user.id}`, `thread:${threadId}`],
})
```

The `resource:` and `thread:` scopes also tell Memory which user and thread the conversation belongs to. Scopes always come from your server code, never from the model or the request body. To set them for every request, see [Set who a run is](/docs/knowledge/scopes-and-access#set-who-a-run-is).

### What happens

When Dana at Acme sends that message, the agent calls `knowledge_page` to save a page in her org and gets back:

```json
{
  "page": { "name": "Refund window", "ref": "org:acme#refunds", "scope": "org:acme", "version": 1 }
}
```

Later, Bea at Acme asks the agent about refunds in a new thread. The agent calls `knowledge_search`, finds `org:acme#refunds`, reads it with `knowledge_read` and answers from it. A user at another org who asks the same question gets no results from Knowledge, because their run holds a different `org:` scope.

From here, [pin a page](/docs/knowledge/pinned-context) so the agent sees it every turn, or [seed your own docs](/docs/knowledge/seed-data) into Knowledge so the agent answers from them.

`tools` is off by default, so an agent with Knowledge attached gets no tools until you turn them on. An agent without Memory works too, as long as the call passes `scopes`.

# Knowledge

Knowledge is a graph context system for agents. It works directly with [signals](/docs/signals/overview), Mastra's context engineering primitive. Signals bring the right knowledge into an agent's context and keep it current while the agent runs.

:::alpha

Knowledge is in alpha. Its API may change between releases.

:::

Knowledge holds **pages** and **notes** that agents read and write across conversations. A page is a topic with a name, a short description and a markdown body. A note is a short, attributed fact added to a page. Pages live in **scopes**, such as `org:acme` or `team:acme:support`, and nest inside each other like folders. The scope types you declare decide who can read and write each scope.

Agents use Knowledge through tools: they browse a scope's pages, search, read a long page a section at a time, write pages and add notes. With [pinned context](/docs/knowledge/pinned-context), a page you choose is in the agent's context every turn, and an edit to it reaches running agents on their next turn.

## When to use Knowledge

Use Knowledge when agents need information that outlives one conversation and is shared between people or agents:

- Documentation, policies or runbooks an agent should answer from instead of guessing.
- Decisions and conventions that several agents or users build on.
- Facts that only some runs may see, such as one customer's account notes or one team's playbooks.

[Memory](/docs/memory/overview) is the conversation: the messages and observations that guide one agent's work in a thread. Knowledge holds the organized information agents use outside that thread. They work together: with Memory, each run also holds its `resource:` and `thread:` scopes, and pinned pages are delivered every turn.

## Quickstart

Declare the scopes your runs hold, turn on the tools, and attach the instance to an agent:

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Agent } from '@mastra/core/agent'
import { Knowledge, knowledgeMemoryScopes } from '@mastra/core/knowledge'
import { LibSQLStore } from '@mastra/libsql'
import { Memory } from '@mastra/memory'

const storage = new LibSQLStore({ id: 'storage', url: 'file:./mastra.db' })

export const knowledge = new Knowledge({
  id: 'company',
  storage,
  scopes: { ...knowledgeMemoryScopes() },
  tools: true,
})

export const agent = new Agent({
  id: 'assistant',
  name: 'Assistant',
  instructions: 'You help the Acme team and keep its knowledge up to date.',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory({ storage }),
  knowledge,
  scopes: ['org:acme'],
})

export const mastra = new Mastra({ agents: { agent } })
```

`knowledgeMemoryScopes()` declares `org:$orgId`, `resource:$resourceId` and `thread:$threadId`, and lets each run edit the scopes it holds. Every run of this agent holds `org:acme`, plus its Memory `resource:` and `thread:` scopes:

```typescript
await agent.generate('Our refund window is 30 days. Save that for the team.', {
  memory: { resource: 'dana', thread: 'onboarding' },
})
```

The agent can call `knowledge_page` to create a page in `org:acme`, and any later run that holds `org:acme` finds it with `knowledge_search`.

`tools` is off by default, so an agent with Knowledge attached gets no tools until you turn them on. An agent without Memory works too, as long as the agent or the call passes `scopes`.

## Storage

Leave out `storage` to use the storage configured on `Mastra`. Knowledge storage is supported by `LibSQLStore`, `PostgresStore`, `MySQLStore`, `MongoDBStore` and `InMemoryStore` (for tests).

Upgrading from 1.79.0: on startup, the tables of the earlier experimental Knowledge store are dropped, with any rows in them, and the new tables are created. Tables already on the new schema, Memory and other tables are never touched. On MongoDB, Knowledge collections found without a schema version are adopted as the new schema.

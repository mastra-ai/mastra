# Knowledge in Studio

Studio's Knowledge page shows the people building and running your agents what those agents know: every scope and page, how they link together, and who wrote what. It's read-only.

:::alpha

Knowledge is in alpha. Its API may change between releases.

:::

## Turn it on

Register the Knowledge instance on `Mastra` and add the Knowledge routes:

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { KNOWLEDGE_ROUTES } from '@mastra/server/server-adapter'
import { knowledge } from './knowledge'
import { supportAgent } from './agents/support-agent'

export const mastra = new Mastra({
  agents: { supportAgent },
  knowledge: { company: knowledge },
  server: { apiRoutes: [...KNOWLEDGE_ROUTES] },
})
```

The routes are off by default. Until you add them, Studio's Knowledge page says browsing isn't enabled.

## What you see

- **Tree**: every scope and the pages inside it, nested the way your agents organized them.
- **Graph**: the same pages, linked to their parents and to the pages their notes mention. Select a page in either view to open it.
- **Page**: the body, version and who last updated it, its notes with their authors, its child pages, the notes on other pages that mention it, and who it's pinned for.
- **Activity**: each page's history of creates, edits, moves, merges, notes and pins, with the author and time of each.
- **Search**: over page names, descriptions, bodies and note text.

When an agent writes, the tree, graph and open page update as it happens, without a reload.

![Studio's Knowledge page: the page tree of a website scope on the left, and the graph of the same pages on the right, grouped around the scope with each branch in its own color.](/img/knowledge/studio-tree-and-graph.png)

Hover over or select a page in the graph to draw its links: solid green lines for the pages it links to, dashed orange lines for the pages that link to it.

![A page selected in the graph, with a tooltip reading "2 links in, 2 links out", and its links drawn to the pages they connect.](/img/knowledge/studio-graph-links.png)

Focus a page to see only it, its parent and its child pages.

![The graph focused on a Research page: its parent scope above it, four child pages below it, and one incoming link from another branch.](/img/knowledge/studio-graph-focus.png)

In an agent's chat in Studio, the pinned pages a run received and the pages its Knowledge tool calls touched link to the same view.

## Who sees what

Without auth on your server, Studio reads the whole instance. That suits a local project. With auth, each person sees only what their Knowledge scopes allow: map each user to their scopes in your `authorize` function. See [Studio Knowledge access](/docs/studio/knowledge#access) for the setup, and [Deployment notes](/docs/studio/knowledge#deployment-notes) before you expose the routes.

## Build your own view

To show Knowledge changes in your own app, subscribe with [`knowledge.onChange()`](/reference/knowledge/knowledge-class#onchange). Events carry IDs, not content. Read the page again under the user's scopes before you show it to them.

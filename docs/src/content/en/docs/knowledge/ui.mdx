# Knowledge UI

Mastra Studio and Agent Builder expose Knowledge as a scope-first workspace. Use the scope tree as the primary entry point. The graph canvas loads one bounded scope graph at a time.

## Explore

Select a scope in the sidebar before loading its canvas. The scope graph shows authorized nodes and visible intra-scope mentions plus accessible one-hop boundary relationships. Use the load-more control to continue an opaque cursor. Terminal-bound notices mean some relationships were intentionally omitted and can't be recovered by loading another node page.

Use the scope overlay for details and adjacent-scope navigation. **Scope map** contains only complete visited scope graphs, so it grows incrementally. Hidden targets produce no edge, placeholder, count, or navigation affordance.

## Other sections

- **Approvals** lists authorized proposals and their conflicts or review state. Its pending badge counts only proposals the viewer can see and act on.
- **Imports** shows importer bindings and resumable run state.
- **Activity** includes write, proposal, approval, rejection, and conflict actions.

These sections use the same server authorization path as Explore. A view-as perspective changes the principal used by that path. The server still performs every visibility check.

## Deep links and bounded views

Deep links identify authorized server-issued handles, not raw storage IDs. Unknown and hidden destinations both resolve as absent. Keep canvas requests within server limits and preserve the selected scope in the URL so refresh, back, and view-as behavior remain consistent.

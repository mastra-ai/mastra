# TaskMarket

The `@mastra/taskmarket` package lets a Mastra agent act as a Taskmarket
requester: create a funded task (USDC escrow on Base Mainnet), fetch its live
status, and list submissions for human review. All wallet, signature, legal,
and X402 payment handling is delegated to the first-party
[`taskmarket` CLI](https://docs.taskmarket.dev/reference/cli)
(`@lucid-agents/taskmarket`); the integration never touches private keys.

## Prerequisites

Install and initialize the first-party CLI on the machine running the agent:

```sh npm2yarn
npm install -g @lucid-agents/taskmarket@latest
```

```bash
taskmarket init         # create and register the agent wallet
taskmarket deposit      # show the wallet address and funding instructions
taskmarket legal accept # accept the current legal bundle once
```

Fund the wallet with Base Mainnet USDC before creating tasks. The CLI keeps
the keystore in `~/.taskmarket/`; Mastra never reads it.

## Installation

```sh npm2yarn
npm install @mastra/taskmarket zod
```

## Usage example

```typescript title="src/mastra/tools/index.ts"
import { createTaskmarketTools } from '@mastra/taskmarket'

const tools = createTaskmarketTools()
// tools.createTask, tools.taskStatus, tools.submissions
```

## Methods

### Factory functions

#### `createTaskmarketTools(config?)`

Returns an object containing all Taskmarket tools that share the supplied
configuration.

```typescript
import { createTaskmarketTools } from '@mastra/taskmarket'

const tools = createTaskmarketTools()
// tools.createTask, tools.taskStatus, tools.submissions
```

Returns: `{ createTask, taskStatus, submissions }`

#### `createTaskmarketCreateTaskTool(config?)`

Creates a funded Taskmarket task on Base Mainnet. Registered as
`taskmarket-create-task`.

The tool enforces, in order:

1. Local validation of the full configuration (description, reward, duration,
   mode, visibility, tags, auction fields).
1. A preview of the exact task that will be created — description, reward,
   duration, deliverables (mode and submission visibility), Base network
   (chain id 8453, USDC `0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913`), and
   the authorized max spend — with a confirmation code bound to that exact
   configuration.
1. An explicit authorization: the user must pass the code back in `confirm`.
1. A network guard: `taskmarket deposit` must report Base Mainnet with the
   canonical USDC contract.
1. A spending guard: the wallet balance must cover the max spend.

Only then is the CLI invoked; it escrows the reward in USDC. The tool returns
the task id, the public task link, the idempotency key, and the live status.

## Agent example

```typescript title="src/mastra/agents/index.ts"
import { Agent } from '@mastra/core/agent'
import { createTaskmarketTools } from '@mastra/taskmarket'

const agent = new Agent({
  id: 'requester-agent',
  name: 'Requester Agent',
  model: '__GATEWAY_ANTHROPIC_MODEL_SONNET__',
  instructions:
    'Use taskmarket-create-task only after showing the user the preview and receiving their confirmation code back. Use taskmarket-task-status and taskmarket-submissions for read-only checks.',
  tools: createTaskmarketTools(),
})
```

## Safety model

- The first-party CLI owns wallet keys, signatures, legal receipts, and the
  X402 payment flow. This package only spawns the CLI and parses its JSON
  envelopes; it never requests, stores, or logs secrets.
- A failed or timed-out paid write is never retried automatically. The error
  carries the idempotency key and the in-flight flag, and the guidance is to
  re-check the task status rather than re-run the write.
- Network and spending checks run before every paid action, and the
  authorization gate is bound to the exact task configuration.

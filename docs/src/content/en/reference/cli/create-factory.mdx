# create-factory

Create a new Mastra Factory project with either command:

```bash npm2yarn
npm create factory@latest
```

```bash npm2yarn
npx mastra factory create
```

Both commands use the same implementation to create a new project directory and install its dependencies. The command also initializes a Git repository and can connect the project to Mastra Platform.

This command creates a new Factory project. To add Mastra to an existing project instead, use [`mastra init`](./mastra#mastra-init).

## Usage

```bash
npm create factory@latest -- [project-name] [options]
```

```bash
npx mastra factory create [project-name] [options]
```

If you omit `[project-name]`, the command prompts you for it. Project names must be valid npm package names and can't point to a non-empty directory.

## Default scaffold

By default, `create-factory` writes the immutable Factory scaffold packaged with its release directly to the new directory. The scaffold includes the Factory server entry point, environment schema and example, Docker Compose configuration, TypeScript and package-manager configuration, and project documentation.

At package build time, Mastra derives the scaffold from the Factory configuration in `mastracode/web` and resolves its Mastra dependencies from the workspace versions assigned to the same release. Stable versions use caret ranges, while intentional prereleases use exact matching versions. Runtime project creation only copies the packaged snapshot and doesn't clone a remote Git template.

`npm create factory@latest` receives the newest tested scaffold included in the latest published `create-factory` release. It doesn't include unreleased changes from the Mastra repository's main branch.

## Platform setup

Unless you pass `--no-platform`, the command:

1. Authenticates with Mastra Platform.
1. Selects or resolves an organization.
1. Creates a Platform project in the selected region.
1. Creates a Platform API key.
1. Provisions a Neon Postgres database.
1. Writes `MASTRA_ORGANIZATION_ID`, `MASTRA_PROJECT_ID`, `MASTRA_PLATFORM_SECRET_KEY`, and `DATABASE_URL` to `.env`.

The generated `.gitignore` excludes `.env`, and the command verifies this before creating the initial Git commit so generated credentials aren't staged.

## Options

### `--template <url>`

Clone a custom Git template instead of using the built-in scaffold.

```bash
npx mastra factory create my-factory --template https://github.com/example/factory-template
```

The command passes the URL to `degit`. Use this option only when you intentionally want a custom template.

### `--no-platform`

Skip Mastra Platform authentication and provisioning.

```bash
npm create factory@latest -- my-factory --no-platform
```

### `--region <eu-or-us>`

Set the Platform project region to `eu` or `us` and skip the region prompt.

```bash
npx mastra factory create my-factory --region us
```

### `--org <id-or-name>`

Select a Mastra Platform organization by its ID or exact name and skip the organization prompt.

```bash
npx mastra factory create my-factory --org my-organization
```

## Telemetry

The command reports anonymous usage and failure telemetry when Mastra telemetry is enabled. The event identifies whether creation used the built-in scaffold or a custom template. Custom template URLs and generated secrets aren't included.

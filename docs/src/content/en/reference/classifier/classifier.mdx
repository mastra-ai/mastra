# Classifier

The `Classifier` evaluates named choice, score, and boolean questions against shared state. It returns typed answers and provider evidence without applying thresholds, blocking content, routing requests, or making other application decisions.

Import it from `@mastra/core/classifier` and provide an AI SDK `EvaluationModelV4` implementation.

## Configure questions in the constructor

Use constructor-configured questions when every evaluation uses the same question set. Literal question and choice names are preserved in the result type.

```typescript
import { Classifier } from '@mastra/core/classifier'

const classifier = new Classifier({
  id: 'content-safety',
  model,
  questions: {
    unsafe: {
      type: 'boolean',
      criteria: {
        true: 'The content is unsafe',
        false: 'The content is safe',
      },
    },
  },
})

const result = await classifier.evaluate({
  state: { content: 'A message to evaluate' },
})

result.answers.unsafe.probability // Estimated P(true), from 0 to 1
```

## Provide questions per call

Omit `questions` from the constructor when the question set changes between evaluations. Each call to `evaluate()` must then include questions.

```typescript
import { Classifier } from '@mastra/core/classifier'

const classifier = new Classifier({
  id: 'request-router',
  model,
})

const result = await classifier.evaluate({
  state: { request: 'I need help with an invoice' },
  questions: {
    route: {
      type: 'choice',
      criteria: {
        support: 'Customer support request',
        sales: 'Sales request',
      },
    },
  },
})

result.answers.route.choice // 'support' | 'sales'
```

Constructor-configured questions and per-call questions are mutually exclusive.

## Question types

Each question can include `instructions`, a JSON-compatible value that tells the model what to evaluate. When omitted, the question name is used as its instructions.

### Choice

A choice question uses a non-empty map of option names to JSON-compatible descriptions. The answer contains the selected option and may include a complete probability distribution.

```typescript
const question = {
  type: 'choice',
  instructions: 'Select the request category',
  criteria: {
    support: 'A request for product help',
    sales: 'A request about purchasing',
  },
} as const
```

### Score

A score question uses an ordered array with at least two levels. Level indexes define the numeric range, so three criteria allow scores from `0` through `2`, including fractional values. The answer may include a complete probability distribution over level indexes.

```typescript
const question = {
  type: 'score',
  instructions: 'Score the response quality',
  criteria: ['Poor', 'Acceptable', 'Excellent'],
} as const
```

### Boolean

A boolean question returns `probability`, the estimated probability that the answer is `true`. It isn't the confidence of whichever boolean outcome is more likely.

```typescript
const question = {
  type: 'boolean',
  criteria: {
    true: 'The content is unsafe',
    false: 'The content is safe',
  },
} as const
```

## Validation and retries

The classifier rejects malformed state, questions, and answers. Provider output must contain exactly one correctly typed answer per question. Probability distributions must be complete, valid, and consistent with selected choices or weighted scores.

Unsupported question types fail before provider I/O. Only retryable AI SDK `APICallError` failures are retried. Other errors are returned immediately, and an exhausted retry sequence rejects the evaluation.

The classifier records safe evaluation metadata in the active observability context when one exists. Raw state, criteria descriptions, answers, and provider-generated text aren't added to span attributes.

## Registering classifiers

Register classifiers on the `Mastra` instance to share them across agents and processors. Registration wires the classifier to Mastra's logger and observability, and makes it resolvable by key or ID.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Classifier } from '@mastra/core/classifier'

export const mastra = new Mastra({
  classifiers: {
    safety: new Classifier({
      id: 'safety',
      model,
      questions: {
        unsafe: { type: 'boolean' },
      },
    }),
  },
})

mastra.getClassifier('safety')
mastra.getClassifierById('safety')
mastra.listClassifiers()
```

A registered classifier can be referenced by string in [`ClassifierProcessor`](/reference/processors/classifier-processor) or a workflow.

## Using classifiers in workflows

A classifier with constructor-configured questions can be added to a workflow with [`createStep(classifier)`](/reference/workflows/step) or [`.classifier()`](/reference/workflows/workflow-methods/classifier). Workflow output contains a routing-oriented `values` map, complete `answers`, and normalized `usage`.

```typescript
const workflow = createWorkflow({
  id: 'ticket-triage',
  inputSchema: z.object({ message: z.string() }),
  outputSchema: z.any(),
})
  .classifier('safety', {
    state: { path: 'inputData.message' },
  })
  .commit()
```

The workflow adapter doesn't include warnings, raw provider responses, headers, or provider metadata in step output. Use direct `evaluate()` calls or classifier observability when you need that provider-level detail.

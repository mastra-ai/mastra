# Upgrade to Mastra v1

:::note[Update to latest 0.x version]
Before upgrading to v1, make sure you've updated to the latest 0.x version of Mastra. Follow the [upgrade to latest 0.x guide](https://mastra.ai/guides/v0/migrations/upgrade-to-latest-0x) first, then return here to complete the v1 migration.
:::

Mastra v1 was released in January 2026. We recommend starting any new projects with Mastra v1, or upgrading your existing project to continue receiving updates and support.

This guide covers the breaking changes when upgrading from Mastra 0.x to v1.0. The migration is organized by package and feature area to help you systematically update your codebase.

:::tip[Need help?]
Need help with the migration? Join our [Discord community](https://discord.gg/BTYqqHKUrf) to ask questions.
:::

:::warning[Coming from Mastra Cloud?]
The legacy Mastra Cloud product has been replaced by the [Mastra platform](/docs/mastra-platform/overview), which splits hosting into two separate products: **Studio** (visual environment, observability) and **Server** (production API). Because old Mastra Cloud access tokens don't work with Mastra platform, create new ones with `mastra auth tokens create`.

If you upgrade to v1 packages without also migrating your `telemetry:` config to `observability:` and creating a Studio project, observability data will stop flowing. Follow the [Mastra Cloud migration guide](/reference/migrations/mastra-cloud) end to end.
:::

## Migration strategy

### Update all Mastra packages to `latest` tag

Use your package manager to update your project's versions. Update **all** Mastra packages together to ensure compatibility (all `@mastra/*` packages and `mastra`).

Here's how you update the most commonly used packages:

```bash npm2yarn
npm install @mastra/core@latest @mastra/loggers@latest @mastra/memory@latest mastra@latest
```

Install any other Mastra package with the `@latest` tag and you'll get the latest v1 version available. Be sure to update all Mastra packages (especially if you're in a monorepo) to avoid version mismatches.

### Update Node.js version

Mastra v1 requires Node.js **22.13.0** or higher. Update your development and production environments accordingly.

### Go through migration checklist

Work through the [migration checklist](#migration-checklist) below to update your codebase. Each item links to a detailed guide for that specific change.

:::note[Codemods]

We prepared automated [codemods](https://github.com/mastra-ai/mastra/tree/main/packages/codemod) for you. If you want, you can run all v1 codemods at once:

```bash
npx @mastra/codemod@latest v1
```

:::

:::note[Database Migration Required]

If you're using PostgreSQL or LibSQL storage, you'll need to run a database migration. See the [Storage migration guide](/reference/migrations/upgrade-to-v1/storage#database-migration) for details.

:::

## Breaking changes by area

- **[Mastra Class](/reference/migrations/upgrade-to-v1/mastra)** - Import restructuring and property access changes.
- **[Agent Class](/reference/migrations/upgrade-to-v1/agent)** - Voice methods moved to namespace and streaming API updates.
- **[Tools](/reference/migrations/upgrade-to-v1/tools)** - CreateTool execute signature changed to separate input and context.
- **[Workflows](/reference/migrations/upgrade-to-v1/workflows)** - Function name changes and legacy features removed.
- **[Memory](/reference/migrations/upgrade-to-v1/memory)** - Configuration now requires explicit parameters and defaults changed.
- **[Storage](/reference/migrations/upgrade-to-v1/storage)** - Pagination standardized and methods renamed to list pattern.
- **[Vectors](/reference/migrations/upgrade-to-v1/vectors)** - Vector store methods renamed to list pattern.
- **[RAG](/reference/migrations/upgrade-to-v1/rag)** - Parameter naming updated for clarity.
- **[MCP](/reference/migrations/upgrade-to-v1/mcp)** - Tool context reorganized and deprecated client classes removed.
- **[Tracing](/reference/migrations/upgrade-to-v1/tracing)** - OTEL telemetry replaced with dedicated observability package and exporters.
- **[Evals & Scorers](/reference/migrations/upgrade-to-v1/evals)** - Scorers API consolidated with new naming conventions.
- **[CLI](/reference/migrations/upgrade-to-v1/cli)** - Commands and flags removed for simpler interface.
- **[Deployment](/reference/migrations/upgrade-to-v1/deployment)** - CloudflareDeployer configuration updated to use standard wrangler.json property names.
- **[Client SDKs](/reference/migrations/upgrade-to-v1/client)** - Types and utilities renamed for consistency.
- **[Voice Packages](/reference/migrations/upgrade-to-v1/voice)** - Packages renamed from speech to voice.

## Migration checklist

Work through this checklist in order, starting with high-impact changes that affect most applications.

:::note[Codemods]

We prepared automated [codemods](https://github.com/mastra-ai/mastra/tree/main/packages/codemod) for you. Throughout the migration guide you'll find instructions on how to use them for specific changes.

If you want, you can run all v1 codemods at once:

```bash
npx @mastra/codemod@latest v1
```

:::

### High Impact Changes

- Update `createTool` tool signatures to `(inputData, context)` format - [Tools](/reference/migrations/upgrade-to-v1/tools)
- Restructure `@mastra/core` imports to use subpath imports - [Mastra Class](/reference/migrations/upgrade-to-v1/mastra)
- Update pagination from `offset/limit` to `page/perPage` - [Storage](/reference/migrations/upgrade-to-v1/storage)
- Install `@mastra/observability` and wrap configuration with `new Observability()` - [Tracing](/reference/migrations/upgrade-to-v1/tracing)
- Migrate from `telemetry:` to `observability:` configuration (if upgrading from 0.x OTEL) - [Tracing](/reference/migrations/upgrade-to-v1/tracing)

### Medium Impact Changes

- Rename `RuntimeContext` to `RequestContext` throughout codebase - [Agent Class](/reference/migrations/upgrade-to-v1/agent), [Tools](/reference/migrations/upgrade-to-v1/tools), [Workflows](/reference/migrations/upgrade-to-v1/workflows)
- Update storage methods from `get*` to `list*` pattern - [Storage](/reference/migrations/upgrade-to-v1/storage)
- Replace direct property access with getter methods - [Mastra Class](/reference/migrations/upgrade-to-v1/mastra), [Agent Class](/reference/migrations/upgrade-to-v1/agent)
- Update memory scope if relying on default `thread` scope - [Memory](/reference/migrations/upgrade-to-v1/memory)
- Update vector store calls to use arguments by name - [Storage](/reference/migrations/upgrade-to-v1/storage)
- Remove `format` parameter from agent methods - [Agent Class](/reference/migrations/upgrade-to-v1/agent)
- Update voice methods to use `agent.voice` namespace - [Agent Class](/reference/migrations/upgrade-to-v1/agent)
- Rename configuration property `processors` to `spanOutputProcessors` (if using custom processors) - [Tracing](/reference/migrations/upgrade-to-v1/tracing)

### Low-Impact Changes

- Rename `keepSeparator` to `separatorPosition` in chunk options - [RAG](/reference/migrations/upgrade-to-v1/rag)
- Rename `createRunAsync` to `createRun` - [Workflows](/reference/migrations/upgrade-to-v1/workflows)
- Update voice package names from `@mastra/speech-*` to `@mastra/voice-*` - [Voice Packages](/reference/migrations/upgrade-to-v1/voice)
- Update scorer methods: `runExperiment` → `runEvals`, `getScorerByName` → `getScorerById` - [Evals & Scorers](/reference/migrations/upgrade-to-v1/evals)
- Remove deprecated CLI flags - [CLI](/reference/migrations/upgrade-to-v1/cli)
- Update client SDK types from `Get*` to `List*` - [Client SDKs](/reference/migrations/upgrade-to-v1/client)
- Replace `runCount` with `retryCount` - [Workflows](/reference/migrations/upgrade-to-v1/workflows)
- Update custom exporter method `exportEvent` to `exportTracingEvent` (if using custom exporters) - [Tracing](/reference/migrations/upgrade-to-v1/tracing)

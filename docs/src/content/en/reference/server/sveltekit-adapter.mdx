# SvelteKit adapter

The `@mastra/sveltekit` package mounts Mastra in a SvelteKit application. See [Server Adapters](/docs/server/server-adapters) for general adapter concepts.

## Installation

Install the SvelteKit adapter and its Hono peer dependency:

```bash npm2yarn
npm install @mastra/sveltekit@latest hono
```

## Usage example

Mount the adapter in a catch-all rest parameter route:

```typescript title="src/routes/api/[...path]/+server.ts"
import { createSvelteKitRouteHandler } from '@mastra/sveltekit'
import { mastra } from '$lib/server/mastra'

export const { GET, POST, PUT, DELETE, PATCH, OPTIONS, HEAD } = createSvelteKitRouteHandler({
  mastra,
})
```

The `prefix` option defaults to `/api` and must match the path the rest parameter route is served at. For example, when mounting at `src/routes/api/mastra/[...path]/+server.ts`, use `createSvelteKitRouteHandler({ mastra, prefix: '/api/mastra' })`.

## Signature

```typescript
function createSvelteKitRouteHandler(options: SvelteKitRouteHandlerOptions): SvelteKitRouteHandlers
```

## Return value

Returns a `SvelteKitRouteHandlers` object with `GET`, `POST`, `PUT`, `DELETE`, `PATCH`, `OPTIONS`, and `HEAD` properties. Each property is a handler with this signature:

```typescript
(event: SvelteKitHandlerContext) => Response | Promise<Response>
```

The context type is the part of SvelteKit's `RequestEvent` that the adapter reads. Because the type is structural, the handlers are assignable to SvelteKit's `RequestHandler` and the adapter doesn't depend on `@sveltejs/kit`:

```typescript
type SvelteKitHandlerContext = {
  request: Request
}
```

## Serverless deployments & lazy initialization

The adapter exports its route handlers synchronously, then creates the underlying Hono app and `MastraServer` when the first request arrives. Concurrent first requests share a single initialization, and the initialized app is reused for subsequent requests in the same process. This supports serverless runtimes without top-level asynchronous initialization.

If initialization fails, the failure isn't cached. The request that triggered it rejects, and the next request tries again.

It uses the same Hono-based `MastraServer` core as the [Next.js adapter](/reference/server/next-adapter). A2A endpoints use an in-memory task store, so task state lasts only for the lifetime of the process and isn't shared between serverless instances.

## Body size limit

Request bodies have a default limit of 4.5 MB. Requests that exceed the limit receive `{ error: 'Request body too large' }`.

Set `server.bodySizeLimit` on the `Mastra` instance to configure the limit.

## Middleware

Middleware configured with `server.middleware` or `setServerMiddleware()` runs through the adapter's Hono-based server, except on framework-public routes such as those marked `requiresAuth: false`. See [Server middleware](/docs/server/middleware).

## Custom API routes

Routes registered with [`registerApiRoute()`](/reference/server/register-api-route) are served at their own path, without the adapter's `prefix`. A SvelteKit route only reaches them if it also matches that path, so custom routes need their own mount point in your app.

## CORS

The adapter doesn't handle CORS, so cross-origin preflight requests receive a 404. To call the API from another origin, for example from [Studio](/docs/studio/overview) started with `mastra studio`, handle CORS in your SvelteKit app, such as in `hooks.server.ts`.

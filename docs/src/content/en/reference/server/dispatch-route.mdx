# dispatchRoute()

The `dispatchRoute()` function runs a server route in-process as the calling user. It expects a request context that Mastra server auth already authenticated, then applies what a server adapter applies to an HTTP request for that route: your auth provider's `authorize`, `authorizeUser`, and `rules`, schema validation, RBAC permission, and fine-grained authorization (FGA). It never allows a call the HTTP request would reject.

Use it to build another transport on top of the built-in routes, including streaming routes. For JSON routes called from a tool, [`invokeRoute()`](/reference/server/invoke-route) is the smaller API.

## Usage example

```typescript title="src/server/run-tool.ts"
import type { Mastra } from '@mastra/core/mastra'
import type { RequestContext } from '@mastra/core/request-context'
import { SERVER_ROUTES, dispatchRoute } from '@mastra/server/server-adapter'

const executeTool = SERVER_ROUTES.find(
  route => route.method === 'POST' && route.path === '/tools/:toolId/execute',
)!

export async function runWeatherTool(
  mastra: Mastra,
  requestContext: RequestContext,
  request: Request,
) {
  const outcome = await dispatchRoute(
    executeTool,
    { pathParams: { toolId: 'weather' }, body: { data: { city: 'Paris' } } },
    { mastra, requestContext, abortSignal: request.signal, request },
  )
  if (!outcome.ok) throw new Error(`Tool route failed with status ${outcome.status}`)
  return outcome.result
}
```

## Behavior

- **Authentication isn't re-run.** When server or Studio auth is configured, the request context must already carry the user Mastra server auth resolved. Otherwise `dispatchRoute()` returns `401`, unless the route's path is public.
- **Authorization hooks see the HTTP path.** `authorize()`, `authorizeUser()`, and `rules` receive the route's method and the path it's served under: the adapter's prefix plus the route path with path parameters filled in.
- **The serving adapter's paths and checks apply.** Each adapter records itself in the request contexts it creates, so a route dispatched with that request context gets that adapter's prefix and overrides, even when another adapter serves the same Mastra instance under the same prefix. Outside a request, the only adapter serving the Mastra instance (or `context.routePrefix`) is used. If the adapter can't be told, or no adapter serves `routePrefix`, `dispatchRoute()` returns `401` for a caller without a user and throws otherwise. It never picks one of several adapters on its own.
- **Path parameters are checked like a URL.** A missing, empty, non-string, `.`, or `..` value returns `400`. An optional `:param?` can be left out.
- **Path parameters win.** A body or query field with the same name as a path parameter is overridden, so authorization and the handler act on the resource named in the path.
- **Protected patterns don't open other paths.** With auth configured, a route needs a user unless its path is declared public, even when it's outside your `protected` patterns.
- **Adapter overrides apply.** A `checkRoutePermission()` override on the serving `MastraServer` subclass also runs for dispatched routes.
- **`authorizeUser()` gets a stand-in request.** It receives a request for the dispatched route's path and method that carries the headers of `context.request` and no body.
- **Server context can't come from the input.** `request`, `routePrefix`, `registeredTools`, and `taskStore` reach the handler only from `context`, never from body or query fields with those names.

## Custom adapters

Adapters that extend `MastraServer` tell `dispatchRoute()` where they serve routes. An adapter that doesn't must register itself, and record the returned handle in each request context it creates:

```typescript
import { MASTRA_DISPATCH_ADAPTER_KEY, registerDispatchAdapter } from '@mastra/server/server-adapter'

const handle = registerDispatchAdapter(mastra, { prefix: '/api' })

// For each request:
requestContext.set(MASTRA_DISPATCH_ADAPTER_KEY, handle)
```

An adapter that doesn't extend `MastraServer` can run the route permission and FGA checks of the built-in adapters with `authorizeRoute()`, after authenticating the request and validating its parameters. It resolves to `null` when the call is allowed, or to a `403` error to send back. `checkRouteRBAC()` runs the permission check alone.

```typescript
import { authorizeRoute } from '@mastra/server/server-adapter'

const denied = await authorizeRoute(mastra, route, params, requestContext)
if (denied)
  return Response.json({ error: denied.error, message: denied.message }, { status: denied.status })
```

# MastraPlatform

`MastraPlatform` is the client for a Mastra platform project. It creates and loads managed agents, returns the project's hosted services as Mastra types, and provisions projects and their resources. See [Platform SDK](/docs/mastra-platform/sdk) for how to use it.

## Usage example

```typescript title="src/platform.ts"
import { MastraPlatform } from '@mastra/platform'

export const platform = new MastraPlatform({
  accessToken: process.env.MASTRA_PLATFORM_ACCESS_TOKEN,
})

const agent = await platform.createAgent({
  name: 'Support',
  instructions: 'Answer billing questions.',
  model: '__GATEWAY_OPENAI_MODEL__',
})
```

## Methods

### `project(projectId)`

Returns a `MastraPlatform` for another project, with the same credentials and options.

### `setupAgents(options?)`

Sets the project up to run managed agents, then waits until it's ready. On a project that's already set up, it returns immediately. It throws if setup fails or doesn't finish within `options.timeoutMs`, which defaults to 15 minutes.

### `agentsSetupStatus()`

Returns whether the project is set up to run managed agents: `'none'`, `'provisioning'`, `'ready'`, or `'failed'`.

### `createAgent(input)`

Creates a managed agent in the project and returns it as a [`PlatformAgent`](/reference/platform/platform-agent).

### `getAgent(agentId)`

Returns an existing managed agent as a [`PlatformAgent`](/reference/platform/platform-agent), with its name, instructions, model, and tools read from the platform.

### `listAgents()`

Returns the project's managed agents, keyed by agent ID.

### `getMemory(options?)`

Returns a `PlatformMemory`, which extends `MastraMemory`, for a hosted Memory instance. `options.instanceId` falls back to `MASTRA_MEMORY_INSTANCE_ID`. The other options are those of `PlatformMemory`, such as `workingMemory`.

### `getKnowledge(options?)`

Returns a `PlatformKnowledge`, which extends `Knowledge`, for a hosted Knowledge instance. `options.instanceId` falls back to `MASTRA_KNOWLEDGE_INSTANCE_ID`.

### `createSandbox(options?)`

Starts a sandbox and resolves once it's running. Returns a [`PlatformSandbox`](/reference/workspace/platform-sandbox), which extends `MastraSandbox`. The options are those of `PlatformSandbox`, such as `environmentId` and `idleTimeoutMinutes`. Pass `sandboxId` to reattach to an existing sandbox when possible, and otherwise start a new one.

### `getSandbox(sandboxId, options?)`

Reconnects to a sandbox started earlier and returns it as a [`PlatformSandbox`](/reference/workspace/platform-sandbox). Throws when the sandbox no longer exists, instead of starting a new one.

### `getFilesystem(filesystemId, options?)`

Returns a provisioned file system as a [`PlatformFilesystem`](/reference/workspace/platform-filesystem), which extends `MastraFilesystem`. Throws while the file system is provisioning or if provisioning failed.

### `getStorage(databaseId, options?)`

Returns a provisioned database as `MastraStorage`. Throws while the database is provisioning or if provisioning failed.

The store depends on the database's kind, and its package must be installed:

| Kind | Store | Package |
| - | - | - |
| `turso` | `LibSQLStore` | `@mastra/libsql` |
| `neon`, `postgres` | `PostgresStore` | `@mastra/pg` |
| `redis` | `RedisStore` | `@mastra/redis` |

## Provisioning collections

`memoryInstances`, `knowledgeInstances`, `databases`, and `filesystems` share these methods:

| Method | Description |
| - | - |
| `list()` | Lists the resources. `filesystems.list()` takes an `environmentId`. |
| `create(input)` | Starts provisioning and returns the resource with status `provisioning`. See the inputs below. |
| `get(id)` | Returns the resource. |
| `waitUntilReady(id, options?)` | Polls until the resource is ready and returns it, throwing if provisioning fails or doesn't finish in time. |
| `delete(id)` | Deletes the resource. `filesystems.delete()` takes the file system record, or `{ id, environmentId }`. |

| Collection | `create()` input |
| - | - |
| `memoryInstances` | `{ name, environmentId? }`. Pass `environmentId` to scope the instance to one environment. |
| `knowledgeInstances` | None. |
| `databases` | `{ kind: 'turso' \| 'neon', name, regionId?, environmentId? }`, or `{ kind: 'redis' \| 'postgres', name, environmentId }`. |
| `filesystems` | `{ environmentId, name }`. |

Memory instance and file system names use lowercase letters, numbers, and dashes.

`waitUntilReady()` accepts `timeoutMs`, which defaults to 15 minutes, and `intervalMs`, which defaults to 2 seconds. Creating Memory instances, Knowledge instances, and databases requires the `admin` role in the organization.

## Errors

Requests to project and provisioning APIs throw `MastraPlatformError` when the platform answers with an error status. It has the HTTP `status` and the response `body`.

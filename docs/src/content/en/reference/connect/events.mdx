# ConnectEvents

Subscribes to a project's provider events: the webhooks the platform receives for the project's connections, such as a GitHub pull request opening or a Linear issue changing. Iterate it to receive each event as a `ConnectEvent`. Choose providers and event types with `events`, then check `provider` and `eventType` to get a payload typed from the provider's published contract.

## Usage example

```typescript title="src/events.ts"
import { ConnectEvents } from '@mastra/connect'

const events = new ConnectEvents({
  events: { github: ['pull_request.opened'], linear: ['Issue.create', 'Issue.update'] },
  cursorStore: {
    load: () => db.get('connect-events-cursor'),
    save: cursor => db.set('connect-events-cursor', cursor),
  },
  onGap: () => resyncFromProviders(),
})

for await (const event of events) {
  if (event.provider === 'github') {
    await reviewPullRequest(event.payload.repository.full_name, event.payload.pull_request.number)
  } else {
    await syncIssue(event.payload.data.id)
  }
}
```

Delivery is at-least-once: an event whose handling throws, or that you break out on, is delivered again. Make handlers idempotent, for example by keying them on `event.sourceEventId ?? event.id`.

## Methods

### `close()`

Ends the subscription. A pending iteration finishes without an error.

### `[Symbol.asyncIterator]()`

Returns an iterator of `ConnectEvent`. Skipped events still move the cursor. A `ConnectEvents` can be iterated once. Create a new one to subscribe again. The subscription reconnects after server closes, network failures and 5xx responses, resuming after the last delivered event.

## Choosing events

`ConnectEvents`, [`ConnectEventSignals`](/reference/connect/event-signals) and [`ConnectEventWorker`](/reference/connect/event-worker) handlers choose events the same way:

- **Unverified events** are skipped unless `includeUnverified` is set. Their payloads aren't typed, so check `event.unverified` before using one.
- **A listed event type** is received when its payload is JSON. For a provider with typed payloads, an event type the provider doesn't send is a compile error.
- **`true`, or no `events` at all**, receives every event of a provider without typed payloads. For a provider with typed payloads, it receives only the event types in [Typed payloads](#typed-payloads), with JSON payloads. Every event it delivers has a typed payload. To receive another event type of such a provider, type it and list it.

Payloads aren't validated at runtime. The types describe what the provider documents it sends, so a provider can still send a field the types don't list, or omit one.

## Typed payloads

`ConnectEventPayloads` maps each provider to its event types and their payload types. They're built from each provider's published contract:

| Provider | `eventType` format | Example | Contract |
| - | - | - | - |
| `clerk` | The body's `type` | `user.created` | Clerk's Backend API description and SDK webhook types |
| `elevenlabs` | The body's `type` | `post_call_transcription` | ElevenLabs' OpenAPI description and post-call webhook docs |
| `fireflies` | The body's `event`, or `eventType` for V1 webhooks | `meeting.transcribed` | Fireflies' webhook docs |
| `github` | `X-GitHub-Event` header, then `.` and the body's `action` when it has one | `pull_request.opened`, `push` | GitHub's REST API description |
| `gitlab` | `X-Gitlab-Event` header | `Merge Request Hook` | GitLab's webhook events docs |
| `hubspot` | Each notification's `subscriptionType` | `contact.creation` | HubSpot's webhooks docs |
| `incident-io` | The body's `event_type` | `public_incident.incident_created_v2` | incident.io's OpenAPI description |
| `jira` | The body's `webhookEvent` | `jira:issue_updated` | Jira's REST API description and webhook docs |
| `linear` | `Linear-Event` header, then `.` and the body's `action` | `Issue.create`, `OAuthApp.revoked` | Linear's GraphQL schema and webhook docs |
| `notion` | The body's `type` | `page.properties_updated` | Notion's webhook events docs |
| `openai` | The body's `type` | `response.completed` | OpenAI's OpenAPI description |
| `outlook` | Each notification's resource type, then `.` and its `changeType`; or `lifecycle.` and its `lifecycleEvent` | `message.created`, `lifecycle.missed` | Microsoft Graph's change notification docs |
| `resend` | The body's `type` | `email.delivered` | Resend's OpenAPI description |
| `sendgrid` | Each event's `event` | `delivered` | SendGrid's Event Webhook reference |
| `slack` | The inner event's `type` | `app_mention`, `message` | Slack's Events API docs |
| `supabase` | The body's `type` | `INSERT` | Supabase's Database Webhooks docs |
| `telegram` | The kind of update: the one field besides `update_id` | `message`, `callback_query` | Telegram's Bot API docs |
| `workos` | The body's `event` | `dsync.user.created` | WorkOS' OpenAPI description and events docs |
| `zendesk` | The body's `type` | `zen:event-type:ticket.created` | Zendesk's webhook event docs |

HubSpot, Outlook and SendGrid send events in batches. Connect delivers each item as its own event, so a payload is one notification.

Each provider's map is also exported, such as `GithubWebhookPayloads`, so you can name a payload type in your own code:

```typescript
import type { GithubWebhookPayloads } from '@mastra/connect'

type PullRequestOpened = GithubWebhookPayloads['pull_request.opened']
```

To type events of another provider, extend `ConnectEventPayloads`. To type more events of a typed provider, extend its map, then list the event type in `events`:

```typescript title="src/connect-events.d.ts"
import type { SlackEventCallback } from '@mastra/connect'

declare module '@mastra/connect' {
  interface ConnectEventPayloads {
    acme: {
      'order.created': { orderId: string }
    }
  }

  interface SlackWebhookPayloads {
    channel_rename: SlackEventCallback<{
      type: 'channel_rename'
      channel: { id: string; name: string }
    }>
  }
}
```

The HubSpot and Outlook maps are type aliases, so they can't be extended.

## Errors

The constructor throws a `MastraConnectError` with a `code` property when its configuration is incomplete or invalid:

| Code | When |
| - | - |
| `missing_access_token` | No platform token configured |
| `missing_project_id` | No project configured |
| `invalid_options` | An option is invalid, such as a non-positive delay or a malformed `after` |

Iteration ends by throwing a `MastraConnectError` when the subscription can't continue:

| Code | When |
| - | - |
| `invalid_options` | The events service rejected the subscription |
| `invalid_cursor` | The cursor can't be resumed from, and there is no time to fall back to or no `onGap` |
| `unauthorized` | The events service refused the token (401 or 403) |
| `platform_error` | The events service answered with another error that won't succeed on retry, such as a 404 |
| `invalid_response` | The events service sent a malformed event |

A `cursorStore` or `onGap` that throws ends iteration with that error.

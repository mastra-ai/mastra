# ConnectEvents

`ConnectEvents` streams the webhooks your Mastra platform project's connections receive, such as a new Linear issue or a GitHub pull request. Use it to react to provider changes as they happen instead of polling. It reads the project's `connect` topic, where the platform publishes those webhooks.

It reconnects on its own and resumes from the last event it delivered. Give it a cursor store and it saves each event you finish handling. A restarted process then resumes where it stopped.

## Usage example

```typescript title="src/events.ts"
import { ConnectEvents } from '@mastra/connect'

const events = new ConnectEvents({
  cursorStore: {
    load: () => db.get('events-cursor'),
    save: cursor => db.set('events-cursor', cursor),
  },
  onGap: () => resyncFromProviders(),
})

for await (const event of events) {
  if (!event.unverified) {
    await handle(event.integrationId, event.eventType, event.payload)
  }
}
```

An event is saved when your loop asks for the next one, including when your loop body finishes after `close()`. If handling an event throws, or you `break` out of the loop, that event isn't saved and is delivered again after a restart. An error thrown by `load()`, `save()`, or `onGap` ends the subscription and is thrown from the loop.

Iterate a `ConnectEvents` once. A second `for await`, whether after the first ends or alongside it, throws `MastraConnectError` with code `invalid_options`. Create a new `ConnectEvents` to subscribe again.

## Reconnects and errors

`ConnectEvents` reconnects, with growing delays, when the server ends the stream, the network fails, the service is unavailable, or the stream goes idle. A `Retry-After` on a 429 or 503 response sets the minimum wait. It resumes after `cursor`, so no events are skipped while the service still holds that position. If the service no longer holds it, `onGap` is called with reason `trimmed` before the events that follow.

Delivery is at least once. After a reconnect or a restart, an event can arrive again, so make handlers safe to repeat. `sourceEventId` helps you detect duplicates.

These errors end the subscription with a `MastraConnectError`:

| Code | When |
| - | - |
| `invalid_cursor` | The server rejected the resume position, and the subscription couldn't resume by time: no time is known for that position, there is no `onGap` handler, or it already resumed by time and no event has arrived since. Clear the stored cursor (or start without `after`) and catch up on anything you missed |
| `unauthorized` | The token can't read the project's topics (401/403) |
| `platform_error` | The project or topic wasn't found (404), or another request error |
| `invalid_options` | The server rejected the subscription itself (400) with no resume position, such as a start time it doesn't accept, or the cursor store returned an invalid cursor |
| `invalid_response` | An event didn't match the documented format |

# connect()

Discovers the connections available to a Mastra platform project and returns one toolset per connected provider, ready to pass to an agent's `toolsets` option. With `live: true`, returns a resolver for an agent's dynamic `tools` argument instead, so connections attached later are picked up without a restart (see [Live mode](#live-mode)).

```typescript title="src/agent.ts"
import { connect } from '@mastra/connect'

const toolsets = await connect()

const response = await agent.generate('Summarize my open Linear issues.', { toolsets })
```

Returns: `Promise<Record<string, ToolsInput>>` keyed by provider (`linear`, `notion`, `jira`, `gitlab`, `snowflake`, `neon`, `cloudflare`, `resend`, `anthropic`), or a `ConnectLiveTools` resolver when `live: true`.

See [Integrations](/docs/mastra-platform/integrations) for the concept overview.

## Integrations allowlist

When `integrations` is provided, only listed providers are returned:

- `true` (or `{}`) includes the provider with defaults.
- `false` excludes it.
- An object configures it: `connectionId` picks a specific connection, `allowTools` restricts the toolset by tool key.

A listed provider with no connection in the project throws `connection_not_found`. Without `integrations`, every connected provider is included. In live mode, a listed provider with no connection yet is skipped with a one-time warning and appears automatically once a connection is attached.

## Connection resolution

For each provider present in the project's connections:

1. An explicit `connectionId` (option or the provider's `MASTRA_<PROVIDER>_CONNECTION_ID` env var) wins.
1. Otherwise, a single active connection is used automatically.
1. Otherwise the provider is ambiguous: explicitly requested providers throw `multiple_connections`; in undirected calls the provider is skipped with a `console.warn` listing the candidates.

Connections in `needs_reauth` status are never silently mapped: explicitly requested providers throw `needs_reauth`, undirected calls skip them with a warning. Connections whose integration has no toolset in this package are skipped with a warning. In live mode, every one of these per-provider failures is downgraded to a warning so a single bad integration never fails the whole resolution.

## Live mode

With `live: true`, `connect()` returns a resolver compatible with an agent's dynamic `tools` argument instead of a one-time promise. Mastra calls the resolver on every generate/stream, and it serves a cached snapshot of the project's toolsets, revalidating from the platform every `ttlMs` (stale-while-revalidate). Connections attached to the project after startup become available within the TTL, and detached connections are dropped — no restart or redeploy required.

```typescript title="src/agent.ts"
import { Agent } from '@mastra/core/agent'
import { connect } from '@mastra/connect'

const agent = new Agent({
  name: 'ops',
  model: 'openai/gpt-5-mini',
  tools: connect({ live: true, ttlMs: 30_000 }),
})
```

The returned resolver also exposes two methods for manual control:

- `invalidate()` drops the cached snapshot so the next resolution fetches fresh.
- `refresh()` fetches from the platform immediately, updates the cache, and returns the toolsets.

Failure handling is tuned for long-running servers:

- Configuration errors — missing project id or token, unknown `integrations` keys, invalid `ttlMs` — still throw eagerly at `connect()` call time.
- If a background refresh fails while a snapshot is cached, the resolver keeps serving the cached toolsets and warns. It rejects only when nothing was ever cached.

## Errors

Throws `MastraConnectError` with a `code` property:

| Code | When |
| - | - |
| `missing_access_token` | No platform token configured |
| `missing_project_id` | No `projectId` option or `MASTRA_PROJECT_ID` |
| `invalid_options` | Invalid `ttlMs` in live mode |
| `connection_not_found` | A requested provider has no connection, or a directed connection id 404s |
| `multiple_connections` | A requested provider is ambiguous |
| `needs_reauth` | A requested provider's connection needs reauthorization |
| `unauthorized` | The platform rejected the token (401/403) |
| `platform_error` | Any other platform request failure |

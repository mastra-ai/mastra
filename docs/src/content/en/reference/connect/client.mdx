# Platform client

The platform client gives code outside an agent, such as a custom Knowledge importer, the same access to a project's connections that [`tools()`](/reference/connect/tools) uses. Every provider call goes through the platform's connection proxy: the platform injects the provider credential, so your code never handles it.

```typescript
import { listProjectConnections, proxyRequest, resolveClient } from '@mastra/connect'

const client = resolveClient({ projectId: 'proj_123' })
const connections = await listProjectConnections(client, 'proj_123')
const wiki = connections.find(connection => connection.integrationId === 'notion' && connection.status === 'active')

if (wiki) {
  const results = await proxyRequest(client, wiki.id, { method: 'POST', path: 'v1/search', body: {} })
}
```

Prefer this client over [`credential()`](/reference/connect/credential), which returns raw credentials and bypasses the proxy's guardrails.

## Required context

The client fails closed: it throws before making any request when the context it needs is missing.

| Context | Source | When missing |
| - | - | - |
| Platform access token | `accessToken`, or `MASTRA_PLATFORM_ACCESS_TOKEN` / `MASTRA_PLATFORM_SECRET_KEY`. Use a project service token for background work. | `resolveClient()` throws `missing_access_token` |
| Project | The `projectId` argument of `listProjectConnections()`. Pass it explicitly; don't derive it from untrusted input. | Throws `missing_project_id` |
| Connection | The `connectionId` argument of `getConnectionContext()`, `proxyRequest()` and `proxyRequestWithResponse()`. Use an ID returned by `listProjectConnections()` for the same project. | Throws `missing_connection_id` |
| Organization | `orgId`, or `MASTRA_ORG_ID`. Sent as `x-organization-id` when set. | Optional; omitted from the request |

The platform authorizes every request against the token.

## proxyRequest() and proxyRequestWithResponse()

Send a request to the provider through the connection proxy. `proxyRequest()` returns the parsed body. `proxyRequestWithResponse()` also returns the HTTP `status` and `headers`, for providers whose contract depends on them.

## Telling provider errors from platform errors

A failed request throws `MastraConnectError`. The `code` says who answered:

| Code | Meaning |
| - | - |
| `connection_not_found` | The platform has no such connection for this token. Says nothing about the provider's data. |
| `unauthorized` | The platform rejected the token (401/403). |
| `proxy_error` | The provider answered with a non-2xx status, available on `error.status`. Also used for other platform failures. |

This matters for importers that remove knowledge when an item is deleted upstream. Treat only a provider's own "not found" (`proxy_error` with `status` 404, or the provider's explicit deleted/archived state) as removal. A platform error, an auth failure, any other status or a network error is not evidence of removal, so remove nothing.

## Example: a custom Knowledge importer

One importer per active connection, writing into one explicit scope. Removing imported knowledge needs `owner` authority on that scope.

```typescript
import { Knowledge } from '@mastra/core/knowledge'
import type { KnowledgeImporterDefinition } from '@mastra/core/knowledge'
import {
  MastraConnectError,
  listProjectConnections,
  proxyRequestWithResponse,
  resolveClient,
} from '@mastra/connect'

async function wikiImporters(projectId: string, scope: string): Promise<KnowledgeImporterDefinition[]> {
  const client = resolveClient({ projectId })
  const connections = await listProjectConnections(client, projectId)

  return connections
    .filter(connection => connection.integrationId === 'acme-wiki' && connection.status === 'active')
    .map(connection => ({
      id: `acme-wiki:${connection.id}`,
      access: { [scope]: 'owner' },
      triggers: { webhook: { bindings: [{ source: `acme-wiki:${connection.id}`, scope }] } },
      handler: async ctx => {
        const importer = await ctx.importer()
        const { data } = await proxyRequestWithResponse(client, connection.id, { method: 'GET', path: 'pages' })
        const seen = new Set<string>()
        for (const page of (data as { pages: { id: string; title: string; body: string }[] }).pages) {
          const address = `acme-wiki:page:${page.id}`
          seen.add(address)
          const node = await importer.upsertNode(address, { name: page.title, metadata: { pageId: page.id } })
          if (!(await node.listKnowledge()).some(record => record.text === page.body)) {
            await node.appendKnowledge({ text: page.body })
          }
        }
        for (const node of await importer.listNodes()) {
          if (seen.has(node.node.address)) continue
          try {
            await proxyRequestWithResponse(client, connection.id, {
              method: 'GET',
              path: `pages/${node.node.metadata?.pageId}`,
            })
          } catch (error) {
            // Only the provider's own 404 confirms removal. Anything else fails the run and removes nothing.
            if (!(error instanceof MastraConnectError && error.code === 'proxy_error' && error.status === 404)) throw error
            for (const record of await node.listKnowledge()) await node.removeKnowledge(record.id)
          }
        }
      },
    }))
}

const knowledge = new Knowledge({ importers: await wikiImporters('proj_123', 'project:docs') })
```

The node stays when its records are removed. Only the knowledge imported from the deleted item goes.

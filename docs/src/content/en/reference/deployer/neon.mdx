# Neon

There is no `@mastra/deployer-neon`. Neon Functions are a `fetch` handler: export a Hono app and deploy it with the Neon CLI. For the full flow, see the [Neon deploy guide](/integrations/deploy/neon).

:::beta
Neon Functions are in beta and available only in AWS US East (Ohio) (`aws-us-east-2`).
:::

## Installation

```bash npm2yarn
npm install @mastra/hono@^1.7.0 hono @neon/config
```

## Usage example

Declare the function in `neon.ts`. `aiGateway: true` injects `NEON_AI_GATEWAY_BASE_URL` and `NEON_AI_GATEWAY_TOKEN` for `neon/` model ids.

```typescript title="neon.ts"
import { defineConfig } from '@neon/config/v1'

export default defineConfig({
  preview: {
    aiGateway: true,
    functions: {
      mastra: {
        name: 'Mastra server',
        source: './src/index.ts',
      },
    },
  },
})
```

Export a Hono app. Neon Functions invoke the default export's `fetch` method.

```typescript title="src/index.ts"
import { Hono } from 'hono'
import { HonoBindings, HonoVariables, MastraServer } from '@mastra/hono'
import { mastra } from './mastra'

const app = new Hono<{ Bindings: HonoBindings; Variables: HonoVariables }>()
const server = new MastraServer({ app, mastra })

await server.init()

export default app
```

Register agents on the `mastra` instance. Server adapters do not discover file-based agents.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { Agent } from '@mastra/core/agent'

const assistant = new Agent({
  id: 'assistant',
  name: 'Assistant',
  instructions: 'You are a helpful assistant',
  model: 'neon/claude-fable-5',
})

export const mastra = new Mastra({
  agents: { assistant },
})
```

## CLI

```bash
neon link
neon deploy
neon functions get mastra
neon dev
```

`GET {invocation_url}/api/agents` returns the registered agents. `neon dev` serves the same route at `http://localhost:8787/api/agents`.

For a provider API key instead of the gateway, declare it under the function's `env` field, use that provider's model id, and pass `--env <file>` so `neon.ts` can read `process.env`. See [Neon Functions environment variables](https://neon.com/docs/compute/functions/environment-variables).

# FactorySandbox

A `FactorySandbox` is the one object a host gives `MastraFactory` to describe where sessions run. It owns the session sandbox constructor, the repository template built for a session, the schema of settings a user can tune per project, and optionally the ability to build that template ahead of time.

Factory passes the project's stored settings to `create` on every session boot and serves the schema as JSON Schema to clients. Everything provider-specific stays inside the object: Factory only calls the contract and reads `provider` for display.

## Usage

Pass an instance of one of the provider classes as the `sandbox` option:

```typescript title="src/mastra/index.ts"
import { MastraFactory } from '@mastra/factory'
import { PlatformFactorySandbox } from '@mastra/platform-workspace'

export const factory = new MastraFactory({
  sandbox: new PlatformFactorySandbox({
    // Provider defaults for an environment that sets nothing.
    defaults: { cpuCount: 4, memoryMb: 8192 },
  }),
})
```

## Provider classes

| Class | Package | Settings | Builds |
| - | - | - | - |
| `PlatformFactorySandbox` | `@mastra/platform-workspace` | `cpuCount`, `memoryMb`, `idleTimeoutMinutes` | `start`, `get` |
| `E2BFactorySandbox` | `@mastra/e2b` | `cpuCount`, `memoryMb`, `idleTimeoutMinutes` | `start`, `get`, `list` |
| `DockerFactorySandbox` | `@mastra/docker` | `baseImage`, `owner` | No |
| `LocalFactorySandbox` | `@mastra/factory` | None | No |

Each provider class takes the same runtime options as its sandbox class (minus `id`, `sandboxId` and `template`, which the class fills in per session), plus `template` options for the repository template and `defaults` for settings the environment leaves unset.

```typescript
import { PlatformFactorySandbox } from '@mastra/platform-workspace'
import { E2BFactorySandbox } from '@mastra/e2b'
import { DockerFactorySandbox } from '@mastra/docker'
import { LocalFactorySandbox } from '@mastra/factory'

new PlatformFactorySandbox() // reads MASTRA_PLATFORM_ACCESS_TOKEN and MASTRA_ENVIRONMENT_ID
new E2BFactorySandbox() // reads E2B_API_KEY
new DockerFactorySandbox({ defaults: { baseImage: 'node:22-slim' } })
new LocalFactorySandbox({ root: '/var/sandboxes', env: { PATH: process.env.PATH! } })
```

`LocalFactorySandbox` runs every session on the host machine under `join(root, sessionId)`.

A setting the environment leaves unset is absent from the stored document. The provider applies its own default for it (2 CPUs, 1024 MB and a 5 minute idle timeout on Platform and E2B, overridable through `defaults`), and Factory stores only the values that were set.

### Callback form

The bare callback `sandbox: ctx => new E2BSandbox({ id: ctx.sessionId })` is also supported. Factory wraps it as a `provider: 'custom'` sandbox. Everything about the sandbox stays inside the callback, and the environment exposes nothing to tune.

To write your own provider, extend `FactorySandbox` from `@mastra/core/workspace`. Factory recognizes subclasses by a brand the base class sets, so a plain object with the same shape isn't accepted.

```typescript
import { FactorySandbox } from '@mastra/core/workspace'
import type { FactorySandboxContext } from '@mastra/core/workspace'
import type { PublicSchema } from '@mastra/core/schema'

interface Settings {
  region?: 'us' | 'eu'
}

class MyFactorySandbox extends FactorySandbox<Settings> {
  readonly provider = 'my-cloud'
  readonly settings: PublicSchema<Settings> = {
    type: 'object',
    properties: { region: { type: 'string', enum: ['us', 'eu'], default: 'us' } },
    additionalProperties: false,
  }

  create(ctx: FactorySandboxContext, settings: Settings) {
    return new MyCloudSandbox({
      id: ctx.sessionId,
      sandboxId: ctx.sandboxId,
      template: this.template(ctx, settings),
      workingDirectory: ctx.workingDirectory,
      region: settings.region ?? 'us',
    })
  }

  // Optional: the sandbox template image Factory can build ahead of time
  template(ctx: FactorySandboxContext, settings: Settings) {
    return myCloudTemplate(ctx, settings)
  }

  // Optional: build that template ahead of time and report on it
  readonly builds = {
    start: async (ctx: FactorySandboxContext, settings: Settings) =>
      myCloud.startBuild(this.template(ctx, settings)),
    get: async (ctx: FactorySandboxContext, settings: Settings, buildId: string) =>
      myCloud.buildStatus(buildId),
    list: async (ctx: FactorySandboxContext, settings: Settings) =>
      myCloud.builds(this.template(ctx, settings).name),
  }
}
```

## Build status

`FactorySandboxBuild.status` is one of `pending`, `building`, `ready`, `failed` or `unknown`. `unknown` means the provider can't read the status of a build it didn't start in this process.

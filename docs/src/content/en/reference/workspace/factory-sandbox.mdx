# FactorySandbox

A `FactorySandbox` is the one object a host gives `MastraFactory` to describe where sessions run. It owns the session sandbox constructor, the repository template built for a session, the schema of settings a user can tune per project, and optionally the ability to build that template ahead of time.

Factory passes the project's settings document to `create` on every session boot (empty until a settings surface stores one) and serves the schema as JSON Schema to clients. Factory never knows which provider is behind the object.

## Usage

Pass an instance of one of the provider classes as the `sandbox` option:

```typescript title="src/mastra/index.ts"
import { MastraFactory } from '@mastra/factory'
import { PlatformFactorySandbox } from '@mastra/platform-workspace'

export const factory = new MastraFactory({
  sandbox: new PlatformFactorySandbox({
    // Provider defaults for an environment that sets nothing.
    defaults: { cpuCount: 4, memoryMb: 8192 },
  }),
})
```

## Provider classes

| Class | Package | Settings | Builds | |
| - | - | - | - | - |
| `PlatformFactorySandbox` | `@mastra/platform-workspace` | `cpuCount`, `memoryMb`, `idleTimeoutMinutes` | No | |
| `E2BFactorySandbox` | `@mastra/e2b` | `cpuCount`, `memoryMb`, `idleTimeoutMinutes` | `start`, `get`, `list` | |
| `DockerFactorySandbox` | `@mastra/docker` | `baseImage`, `owner` | No | |
| `LocalFactorySandbox` | `@mastra/factory` | None | No | |

Each provider class takes the same runtime options as its sandbox class (minus `id`, `sandboxId` and `template`, which the class fills in per session), plus `template` options for the repository template and `defaults` for settings the environment leaves unset.

```typescript
import { PlatformFactorySandbox } from '@mastra/platform-workspace'
import { E2BFactorySandbox } from '@mastra/e2b'
import { DockerFactorySandbox } from '@mastra/docker'
import { LocalFactorySandbox } from '@mastra/factory'

new PlatformFactorySandbox({ accessToken, environmentId, projectId })
new E2BFactorySandbox({ apiKey: process.env.E2B_API_KEY })
new DockerFactorySandbox({ defaults: { baseImage: 'node:22-slim' } })
new LocalFactorySandbox({ root: '/var/sandboxes', env: { PATH: process.env.PATH! } })
```

`LocalFactorySandbox` runs every session on the host machine under `join(root, sessionId)`.

A setting the environment leaves unset is absent from the stored document. The provider applies its own default for it (2 CPUs, 1024 MB and a 5 minute idle timeout on platform and E2B, overridable through `defaults`), and factory only stores values the user typed.

### Deprecated callback

The bare callback `sandbox: ctx => new E2BSandbox({ id: ctx.sessionId })` keeps working. Factory wraps it as a `provider: 'custom'` sandbox. Everything about the sandbox stays inside the callback, and the environment exposes nothing to tune.

abstract class FactorySandbox<TSettings extends Record<string, unknown> = Record<string, unknown>> {
  readonly provider: string
  readonly settings: PublicSchema<TSettings>
  create(ctx: FactorySandboxContext, settings: TSettings): MastraSandbox
  template?(ctx: FactorySandboxContext, settings: TSettings): unknown
  builds?: FactorySandboxBuilds<TSettings>
}

Extend `FactorySandbox` from `@mastra/core/workspace`; the base class sets the `Symbol.for('mastra.factory.sandbox')` brand factory detects, never by shape.

```typescript
import { FactorySandbox } from '@mastra/core/workspace'
import type { FactorySandboxContext } from '@mastra/core/workspace'
import { z } from 'zod'

const settings = z.object({ region: z.enum(['us', 'eu']).optional() })

class MyFactorySandbox extends FactorySandbox<z.infer<typeof settings>> {
  readonly provider = 'my-cloud'
  readonly settings = settings

  create(ctx: FactorySandboxContext, { region }: z.infer<typeof settings>) {
    return new MyCloudSandbox({ id: ctx.sessionId, sandboxId: ctx.sandboxId, region })
  }
}
```

## Build status

`FactorySandboxBuild.status` is one of `pending`, `building`, `ready`, `failed` or `unknown`. `unknown` means the provider can't read the status of a build it didn't start in this process.

# React hooks

`@mastra/react` exports data hooks built on [TanStack Query](https://tanstack.com/query/latest) and the Mastra client. Render them inside `MastraReactProvider` and a `QueryClientProvider`.

Every hook takes a single object argument with its domain fields and an optional `queryOptions` key:

```tsx
import { useDataset, useWorkflowRun, useStoredAgent } from '@mastra/react'

const { data: dataset } = useDataset({ datasetId })
const { data: run } = useWorkflowRun({ workflowId, runId })
const { data: agent } = useStoredAgent({ agentId, status: 'draft', requestContext })
```

## Overriding query options

`queryOptions` accepts TanStack Query's own option types and is applied after the hook's defaults, so any key you pass wins. This includes `enabled`, `staleTime`, `retry`, `refetchInterval`, `placeholderData`, `select`, and even `queryKey` or `queryFn`.

```tsx
const { data: nameLength } = useDataset({
  datasetId,
  queryOptions: {
    staleTime: 60_000,
    enabled: isOpen,
    select: dataset => dataset.name.length,
  },
})
// nameLength is typed as number | undefined
```

When you pass `select`, the type of `data` follows its return type. Some hooks already apply their own `select` (for example `useInfiniteDatasets` flattens pages into a list). Passing your own `select` replaces it, so `data` takes the shape you return.

### Mutations

Mutation hooks accept `MastraMutationOptions` under `queryOptions`:

```tsx
const deleteRun = useDeleteWorkflowRun({
  workflowId,
  queryOptions: { onError: error => toast.error(error.message) },
})
```

Hooks that return several mutations take options keyed by the returned property name:

```tsx
const { createDataset, deleteDataset } = useDatasetMutations({
  queryOptions: {
    createDataset: { onSuccess: dataset => navigate(`/datasets/${dataset.id}`) },
  },
})
```

Hooks that run several queries at once (`useTraces`, `useTraceQuery`, `useAllConnections`, `useAllProviderTools`) also take options keyed per query, for example `queryOptions: { traceQuery: { refetchInterval: 10_000 } }`.

### Override behavior

Options are spread, not merged. Keep these effects in mind:

- **Callbacks replace the hook's callbacks.** Passing `onSuccess`, `onError`, or `onSettled` replaces the hook's built-in callback, including its cache invalidation. Invalidate the relevant queries yourself if you still need fresh data.
- **Hooks don't guard on empty ids.** A hook fetches as soon as it mounts, even if an id is `undefined` or `''`. Pass `enabled` yourself when an id may be missing:

  ```tsx
  const { data } = useAgent({ agentId, queryOptions: { enabled: Boolean(agentId) } })
  ```
- **Workspace hooks keep their compatibility check.** Workspace query hooks stay disabled when the server or client doesn't support workspaces, even if you pass `enabled: true`.
- **`queryKey` and `queryFn` change cache identity.** Overriding them stops the hook from sharing cache entries with other hooks that use the default key.

## Types

```tsx
import type {
  MastraQueryOptions,
  MastraInfiniteQueryOptions,
  MastraMutationOptions,
} from '@mastra/react'
```

- `MastraQueryOptions<TQueryFnData, TData>`: `Partial<UseQueryOptions<…>>`
- `MastraInfiniteQueryOptions<TQueryFnData, TData, TQueryKey, TPageParam>`: `Partial<UseInfiniteQueryOptions<…>>`
- `MastraMutationOptions<TData, TVariables, TContext>`: `Partial<UseMutationOptions<…>>`

# Saved Views API

The Saved Views API stores named setups for Studio pages, such as the filters and table settings of the **Traces** page. Views live in the `savedViews` domain of your [Mastra storage](/reference/storage/overview). They're shared: everyone who can open Studio sees every view, and anyone with write access can change one. Each view records who created it and who last changed it.

Saved views need a storage adapter with the `savedViews` domain: `@mastra/pg`, `@mastra/libsql`, `@mastra/mongodb`, `@mastra/mysql`, `@mastra/mssql`, `@mastra/spanner`, or the in-memory store. Other stores answer `501`, and servers that predate saved views answer `404`.

With [stored resource scoping](/docs/auth/fga#stored-resource-scoping) on, each view belongs to the scope of the caller that created it. Lists only include views in the caller's scope, and views in other scopes answer `404`.

## Usage

```typescript
import { MastraClient } from '@mastra/client-js'

const mastraClient = new MastraClient({ baseUrl: 'http://localhost:4111' })

const view = await mastraClient.createSavedView({
  page: 'traces',
  name: 'Errors today',
  state: {
    version: 1,
    filters: [{ id: 'status', fieldId: 'status', operatorId: 'is', value: 'error' }],
    settings: {
      datePreset: 'last-24h',
      groups: [],
      sortDirection: 'desc',
      columns: { visibleColumns: [], customColumns: [], metadataKeys: [], order: [] },
    },
  },
})
```

The server checks only that `state` is a JSON object with an integer `version`, at most 64 KB. The page that reads the view owns the rest of the shape, so it can add fields without a server release. The example uses the shape the Studio **Traces** page reads: `filters` holds the filter chips, and `settings` holds the time range, filter groups, sort, and columns.

## Methods

### `listSavedViews(params?)`

Lists saved views, oldest first, up to 100 per call. Pass `page` to list the views for one Studio page. When `pagination.hasMore` is `true`, more views follow: pass the next `pageIndex` to get them.

```typescript
const { views, pagination } = await mastraClient.listSavedViews({ page: 'traces' })

if (pagination.hasMore) {
  const next = await mastraClient.listSavedViews({ page: 'traces', pageIndex: pagination.page + 1 })
}
```

### `getSavedView(savedViewId)`

Gets one saved view. Throws a `MastraClientError` with status `404` when no view has this ID.

```typescript
const view = await mastraClient.getSavedView('view-id')
```

### `createSavedView(params)`

Creates a saved view and returns it. The server generates its `id` and records the caller's user ID as both `authorId` and `updatedById`, or `null` when the server runs without auth.

### `updateSavedView(savedViewId, params)`

Changes a view's `name` or `state` and returns the updated view. A new `state` replaces the old one as a whole. Omitted fields keep their value, `updatedAt` moves forward, and `updatedById` becomes the caller's user ID. Throws a `MastraClientError` with status `404` when no view has this ID.

```typescript
await mastraClient.updateSavedView('view-id', { name: 'Errors this week' })
```

### `deleteSavedView(savedViewId)`

Deletes a view and returns `{ deleted: true }`. Throws a `MastraClientError` with status `404` when no view has this ID.

```typescript
await mastraClient.deleteSavedView('view-id')
```

## Saved view object

```typescript oxfmt:false
{
  id: string;
  page: string;
  name: string;
  authorId: string | null;     // Who created the view; null without auth
  updatedById: string | null;  // Who last changed the view; null without auth
  state: { version: number; [key: string]: unknown };
  createdAt: string;           // ISO timestamp
  updatedAt: string;           // ISO timestamp
}
```

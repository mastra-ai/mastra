# dataset.createExternalExperiment()

**Added in:** `@mastra/core@1.61.0`

Creates an experiment with `targetType: 'external'`. Mastra does not run anything: your own infrastructure (for example a Temporal worker) executes each item and reports back with [`submitExperimentResult()`](/reference/datasets/submitExperimentResult), then marks the run complete with [`finalizeExperiment()`](/reference/datasets/finalizeExperiment).

The experiment pins the dataset version at creation time, so submissions are validated against a stable set of items even if the dataset changes afterwards.

## Usage example

```typescript
import { Mastra } from '@mastra/core'

const mastra = new Mastra({/* storage config */})

const dataset = await mastra.datasets.get({ id: 'dataset-id' })

const { experimentId, totalItems, datasetVersion } = await dataset.createExternalExperiment({
  id: 'temporal-wf-run-42', // optional: idempotent create on retry
  name: 'external-eval',
})
```

Passing your own `id` makes creation idempotent: calling it again with the same `id` returns the existing experiment instead of failing, so a retried workflow activity is safe. If the `id` belongs to an experiment on another dataset or a non-external experiment, the call throws an `EXPERIMENT_ID_CONFLICT` error.

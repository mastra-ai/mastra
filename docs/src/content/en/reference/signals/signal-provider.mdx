# SignalProvider

**Added in:** `@mastra/core@1.39.0`

:::beta

Breaking changes may occur without a major version bump until the API is stable.

:::

Abstract base class for building signal providers. A signal provider monitors external sources (APIs, webhooks, event streams) and pushes notification signals into agent threads through a built-in subscription registry.

Signal providers aren't processors by default. Providers that need to intercept agent execution return processors from `getInputProcessors()` or `getOutputProcessors()`. Providers that expose agent-callable tools return them from `getTools()`.

For a ready-to-use webhook-based provider, see [`WebhookSignalProvider`](/reference/signals/webhook-signal-provider).

## Usage example

Polling provider that checks an API every 30 seconds:

```typescript title="src/signals/slack-signals.ts"
import { SignalProvider } from '@mastra/core/signals'
import type { SignalSubscription } from '@mastra/core/signals'

class SlackSignals extends SignalProvider<'slack-signals'> {
  readonly id = 'slack-signals'
  readonly pollInterval = 30_000

  async poll(subscriptions: SignalSubscription[]) {
    for (const sub of subscriptions) {
      const messages = await fetchSlackMessages(sub.externalResourceId)
      if (messages.length > 0) {
        await this.notify(
          {
            source: 'slack',
            kind: 'new-messages',
            summary: `${messages.length} new messages in ${sub.externalResourceId}`,
          },
          { threadId: sub.threadId, resourceId: sub.resourceId },
        )
      }
    }
  }
}
```

Register with an agent:

```typescript title="src/mastra/index.ts"
import { Agent } from '@mastra/core/agent'

const agent = new Agent({
  id: 'agent',
  signals: [new SlackSignals()],
})
```

The agent calls `connect(this)` and registers any processors or tools the provider returns. It then starts polling.

## Constructor parameters

`SignalProvider` is abstract. Subclasses call `super()` with no arguments.

## Methods

### Connection

#### `connect(agent)`

Called by the Agent constructor. Establishes the bidirectional link so the provider can send signals back to the agent. Override to run additional setup after the link is established. Always call `super.connect(agent)`.

```typescript
class MySignals extends SignalProvider<'my-signals'> {
  readonly id = 'my-signals'

  override connect(agent) {
    super.connect(agent)
    // additional setup after agent link is established
  }
}
```

#### `__registerMastra(mastra)`

Called when the provider's agent is registered with a Mastra instance. Override to access storage or other Mastra services. Always call `super.__registerMastra(mastra)`.

```typescript oxfmt:false
override __registerMastra(mastra) {
  super.__registerMastra(mastra)
  // this.mastra is now available
}
```

#### `getInputProcessors()`

Return input processors this provider needs to be registered with the agent. Override when your provider intercepts agent input steps (for example, injecting context hints or detecting tool calls).

```typescript oxfmt:false
getInputProcessors() {
  return [this]
}
```

Returns: `InputProcessorOrWorkflow[]`

#### `getOutputProcessors()`

Return output processors this provider needs to be registered with the agent. Override when your provider intercepts agent output steps.

```typescript oxfmt:false
getOutputProcessors() {
  return [this]
}
```

Returns: `OutputProcessorOrWorkflow[]`

#### `getTools()`

Return tools this provider exposes to the agent. Override when your provider adds agent-callable tools such as subscribe or unsubscribe commands.

```typescript oxfmt:false
getTools() {
  return {
    subscribe_pr: createTool({ /* ... */ }),
    unsubscribe_pr: createTool({ /* ... */ }),
  }
}
```

Returns: `Record<string, unknown>`

### Subscription tracking

#### `subscribe(target, externalResourceId, metadata?)`

Subscribe a thread to an external resource. This is a protected method: call it from within your provider implementation.

```typescript
const sub = this.subscribe(
  { threadId: 'thread-1', resourceId: 'user-1' },
  'github:mastra-ai/mastra#123',
  { pr: 123 },
)
```

Returns: `SignalSubscription`: the created subscription, or the existing one with merged metadata.

```typescript

}
```

Returns: `number`

### Durable subscriptions

The subscription-tracking methods above keep subscriptions in process memory: they're lost on restart and invisible to other processes. The durable methods below store subscriptions in the `signalSubscriptions` storage domain instead, so they survive restarts and are shared by every process that uses the same storage. They're protected async methods and sit alongside the in-memory registry without changing it.

Durable subscriptions are scoped by agent, provider, resource, thread, and external resource ID. Two agents that share a provider `id` never see each other's subscriptions.

Where the durable methods store data:

- **No Mastra instance attached**: a provider-local, in-memory store.
- **Default storage (no `storage` configured)**: the in-memory domain in the default store. Data stays in the process.
- **libSQL or PostgreSQL**: the persistent `signalSubscriptions` adapter, shared by every process using that database.
- **A storage adapter without the `signalSubscriptions` domain**: every durable method throws a `MastraError` with id `SIGNAL_PROVIDER_DURABLE_STORAGE_UNSUPPORTED`. The methods never fall back to process memory.

Every durable method requires a connected agent. Calling one before `connect()` throws a `MastraError` with id `SIGNAL_PROVIDER_NOT_CONNECTED`.

#### `subscribeDurable(target, externalResourceId, metadata?, deliveryOptions?)`

Durably subscribe a thread to an external resource. Subscribing again to the same resource merges `metadata` into the stored metadata and keeps the existing subscription ID.

```typescript
const sub = await this.subscribeDurable(
  { threadId: 'thread-1', resourceId: 'user-1' },
  'github:mastra-ai/mastra#123',
  { pr: 123 },
  { ifIdle: true },
)
```

Returns: `Promise<SignalSubscriptionRecord>`

Returns: `Promise<SignalSubscriptionRecord[]>`

```typescript

```

Returns: `Promise<SignalSubscriptionRecord[]>`

#### `hasDurableSubscription(target, externalResourceId)`

Check whether a thread has an enabled durable subscription to an external resource.

```typescript
const subscribed = await this.hasDurableSubscription(target, 'github:mastra-ai/mastra#123')
```

Returns: `Promise<boolean>`

#### `unsubscribeAllDurable(target?)`

Remove durable subscriptions for this agent and provider. With a `target`, removes only that thread's subscriptions. Without one, removes them from every thread.

```typescript
const removed = await this.unsubscribeAllDurable({
  threadId: 'thread-1',
  resourceId: 'user-1',
})
```

Returns: `Promise<number>`: count of removed subscriptions.

#### `setDurableSubscriptionEnabled(id, enabled, fence?)`

Enable or disable a durable subscription by ID. Disabled subscriptions are kept in storage but aren't returned by `getDurableSubscriptions()`, `getDurableSubscriptionsForResource()`, or `hasDurableSubscription()`.

```typescript
await this.setDurableSubscriptionEnabled(sub.id, false)
```

Returns: `Promise<SignalSubscriptionRecord | null>`: the updated subscription, or `null` if it doesn't exist.

Pass `fence` only when the provider has claimed ownership of the thread's subscriptions. Without the current owner's fence, the update rejects for an owned thread.

### Polling

#### `poll(subscriptions)`

Called on each poll cycle with all active subscriptions. Override to check external sources and emit notifications. The framework prevents overlapping poll cycles: if a `poll()` call takes longer than `pollInterval`, the next cycle is skipped.

```typescript oxfmt:false
async poll(subscriptions: SignalSubscription[]) {
  for (const sub of subscriptions) {
    const events = await checkExternalSource(sub.externalResourceId)
    for (const event of events) {
      await this.notify(
        { source: 'my-provider', kind: event.type, summary: event.message },
        { threadId: sub.threadId, resourceId: sub.resourceId },
      )
    }
  }
}
```

#### `startPolling()`

Start the polling timer. Called by the Agent after `connect()`. Idempotent: calling multiple times has no effect.

```typescript
provider.startPolling()
```

#### `stopPolling()`

Stop the polling timer.

```typescript
provider.stopPolling()
```

### Webhooks

#### `handleWebhook(request)`

Handle an incoming webhook request. Override to parse the payload and match it to subscriptions. Then emit notification signals. See [`WebhookSignalProvider`](/reference/signals/webhook-signal-provider) for a ready-to-use implementation.

Call this method from an application-defined HTTP endpoint after verifying the webhook request.

```typescript oxfmt:false
async handleWebhook(request) {
  const payload = request.body as { repo: string, event: string }
  const subs = this.getSubscriptionsForResource(payload.repo)

  for (const sub of subs) {
    await this.notify(
      { source: 'github', kind: payload.event, summary: `Event on ${payload.repo}` },
      { threadId: sub.threadId, resourceId: sub.resourceId },
    )
  }

  return { status: 200, body: { matched: subs.length } }
}
```

Returns: `Promise<{ status?: number; body?: unknown }>`

### Lifecycle

#### `start()`

Called after `connect()` to run async initialization. Override when setup requires the agent or Mastra instance to be available.

```typescript oxfmt:false
async start() {
  await this.loadInitialState()
}
```

#### `stop()`

Called on shutdown. The default implementation stops polling and clears the in-memory subscriptions. Durable subscriptions stay in storage. Overrides may return `void` or `Promise<void>`.

```typescript
provider.stop()
```

### Notifications

#### `notify(notification, target)`

Send a notification signal to the connected agent. This is a protected convenience wrapper around `agent.sendNotificationSignal()`.

```typescript
await this.notify(
  {
    source: 'my-provider',
    kind: 'pr-updated',
    summary: 'PR #123 was updated',
    priority: 'high',
    payload: { prNumber: 123 },
  },
  { threadId: 'thread-1', resourceId: 'user-1' },
)
```

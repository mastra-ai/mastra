# RingSignals

`RingSignals` connects Ring doorbells and cameras to an agent. It receives Ring webhooks, delivers each event to an agent thread as a [notification signal](/reference/signals/notifications), and adds `ring_snapshot` and `ring_clip` tools so the agent can fetch media for an event. It also serves the routes Ring calls for account linking and webhooks.

For setup in the Ring Developer Console and on ring.com, see the [Ring integration guide](/integrations/channels/ring).

## Usage example

```typescript title="src/mastra/agents/home-agent.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'
import { RingSignals } from '@mastra/ring-signals'

export const homeAgent = new Agent({
  id: 'home-agent',
  name: 'Home Agent',
  instructions: 'Watch the front door and say briefly whether each event needs attention.',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory(),
  signals: [
    new RingSignals({
      events: {
        device_offline: { priority: 'low', summary: 'Device went offline.', coalesce: true },
      },
      tools: {
        clip: { visibleToModel: true },
      },
    }),
  ],
})
```

Linked accounts are saved in the channels storage domain. The Mastra instance needs a storage adapter.

## Events

Ring sends these event types. Events without an entry in `DEFAULT_RING_EVENTS` are disabled until you configure them in `events`.

| Event | Sent when | Default priority | Default summary |
| - | - | - | - |
| `button_press` | The doorbell button is pressed | `high` | Doorbell was pressed. |
| `motion_detected` | A device camera detects motion | `medium` | Motion was detected. |
| `device_added` | A device becomes accessible to your app | Disabled | |
| `device_removed` | A device is no longer accessible to your app | Disabled | |
| `device_online` | A device comes online | Disabled | |
| `device_offline` | A device goes offline | Disabled | |
| `app_integration_added` | A Ring account links your app | Disabled | |
| `app_integration_removed` | A Ring account unlinks your app | Disabled | |
| `subscription_activated` | A Ring paid subscription or trial starts | Disabled | |
| `subscription_deactivated` | A Ring paid subscription or trial ends | Disabled | |

Each notification has `deviceId` and `timestamp` attributes. Motion events also have `motionType`: `human`, `vehicle`, `package_delivery`, or `other_motion` when Ring Smart Alerts are on, and `motion` when they're off.

Some events also have side effects, whether or not they're enabled. `app_integration_removed` deletes the account's stored tokens, and `subscription_deactivated` logs a warning that media is no longer available.

### `RingWebhookEvent`

The webhook payload Ring sends for each event. The `target` function and the `attributes` function in `events` receive it.

```typescript
type RingWebhookEvent = {
  meta: {
    version: string
    time: string
    request_id: string
    account_id?: string
  }
  data: {
    id: string
    type: RingEventType
    attributes: {
      source: string
      source_id?: string
      source_type?: string
      timestamp?: number
      sub_type?: RingMotionType | 'paid' | 'trial'
      plan_id?: string | null
      expires_at?: string
      component_ids?: string[]
    }
  }
}
```

- `meta.account_id`: The Ring account associated with the event.
- `data.type`: The event type, from the table above.
- `data.attributes.source`: The device ID for device events, the account ID for `app_integration_added` and `app_integration_removed`, or `subscriptions` for subscription events.
- `data.attributes.source_id`: The subscription ID, on subscription events.
- `data.attributes.source_type`: The kind of source: `devices` for device events, `users` for app integration events.
- `data.attributes.timestamp`: When the event happened, in epoch milliseconds. It's missing on subscription events.
- `data.attributes.sub_type`: What caused a motion event: `human`, `vehicle`, `package_delivery`, `other_motion`, or `motion` when Smart Alerts are off. `paid` or `trial` on subscription events.
- `data.attributes.plan_id`: The subscription plan ID, on subscription events. `null` for trials.
- `data.attributes.expires_at`: When the billing cycle or trial ends, as an ISO 8601 date. Always present on `subscription_activated`.
- `data.attributes.component_ids`: The cameras involved, on devices with more than one.

## Tools

### `ring_snapshot`

Fetches a still image for an event. If Ring has no image right after the event, it uses the most recent image before it, up to 24 hours back.

Input: `{ deviceId: string, timestamp: number }`, taken from the notification's attributes.

## Routes

These routes are added to the Mastra server when the agent is registered. They don't use Mastra authentication. Webhooks are verified with Ring's signature, account links with Ring's link nonce, and media links with their signature and expiry time.

| Route | Purpose |
| - | - |
| `GET <routePrefix>/link` | Account Link URL. Finishes linking and shows the result. |
| `GET <routePrefix>/home` | App Homepage URL. Returns `Ring Signals` as plain text. |
| `POST <routePrefix>/token` | Token Exchange URL. Exchanges an authorization code for tokens. |
| `POST <routePrefix>/webhook` | Webhook URL. Receives Ring events. |
| `GET <routePrefix>/media/:kind/:deviceId/:timestamp` | Serves signed snapshot and clip links. |

## Methods

### `subscribeThread(target, deviceId)`

Sends events from a Ring device to a specific thread. Devices without a subscription use the `target` option. Several threads can subscribe to the same device, and each one receives every event. Subscriptions are kept in memory and are lost when the server restarts.

```typescript
ringSignals.subscribeThread({ resourceId: 'user-1', threadId: 'front-door' }, deviceId)
```

Returns: `SignalSubscription`

### `unsubscribeThread(target, deviceId)`

Stops sending events from a Ring device to a thread.

Returns: `boolean`, `true` if the thread was subscribed.

## Exports

`@mastra/ring-signals` also exports:

- `DEFAULT_RING_EVENTS`: The default `events` configuration.
- `DEFAULT_RING_INSTRUCTIONS`: The default system instruction, for both tools.
- `buildRingInstructions({ snapshot, clip })`: Builds the system instruction for the enabled tools. Use it to extend the default text.
- `RingApiClient` and `RingApiError`: A client for the Ring Partner API and the error it throws.
- Types: `RingSignalsOptions`, `RingEventType`, `RingEventNotification`, `RingMotionType`, `RingWebhookEvent`, `RingTargetResolver`, `RingToolsOptions`, `RingSnapshotToolOptions`, `RingClipToolOptions`, `RingAttachmentOption`, and `RingMaxAttachmentBytesOption`.

# Knowledge class

:::warning

Knowledge is experimental and can change without notice.

:::

The `Knowledge` class holds pages and notes, declares which scopes exist and who gets which role on them, and gives attached agents the Knowledge tools. See [Knowledge overview](/docs/knowledge/overview) for what it does and [Setup](/docs/knowledge/setup) for a walkthrough.

## Usage example

```typescript title="src/mastra/knowledge.ts"
import { Knowledge, knowledgeMemoryScopes } from '@mastra/core/knowledge'
import { LibSQLStore } from '@mastra/libsql'

export const knowledge = new Knowledge({
  id: 'company',
  storage: new LibSQLStore({ id: 'knowledge', url: 'file:./knowledge.db' }),
  tools: true,
  scopes: {
    ...knowledgeMemoryScopes(),
    'team:$orgId:$teamId': {
      access: [
        { principal: 'self', role: 'editor' },
        { principal: 'org:$orgId', role: 'viewer' },
      ],
    },
  },
})
```

The constructor throws a `KnowledgeDeclarationError` when `scopes` is missing or a declaration is invalid, for example two patterns of one type that overlap or a rule principal that doesn't bind. Without `scopes` the message is:

```text
Knowledge needs `scopes`: declare the scopes its runs hold, e.g. `scopes: { ...knowledgeMemoryScopes() }`, or `{}` for none.
```

## Methods

### `createTools()`

```typescript oxfmt:false
createTools(options?: { read?: boolean; write?: boolean; pinnedContext?: boolean }): Record<string, Tool>
```

Returns the Knowledge tools for explicit wiring, such as an agent that isn't attached with `knowledge`. Each option overrides the matching group set on the instance. See [Knowledge tools](/reference/knowledge/knowledge-tools).

```typescript
const tools = knowledge.createTools({ write: false })
// knowledge_search, knowledge_read
```

### `getInstructions()`

```typescript oxfmt:false
getInstructions(options?: { read?: boolean; write?: boolean; pinnedContext?: boolean }): string
```

Returns the usage instructions that go with `createTools(options)`, built the same way as for an attached agent: the built-in parts for the enabled groups, or what the `instructions` option makes of them.

### `reindex()`

```typescript oxfmt:false
reindex(): Promise<number>
```

Re-embeds every live page and note into the vector store and resolves to how many it indexed. Use it for content written straight to the store or after a failed embed. Throws without `vector` and `embedder`.

### `explainAccess()`

```typescript oxfmt:false
explainAccess(
  runScopes: readonly string[],
  target: { scope: string } | { page: string },
): Promise<KnowledgeAccessExplanation>
```

Says why a run holding `runScopes` can or can't reach a scope or page. `runScopes` are raw run scopes, as you'd pass to an agent. `target.page` takes a page ID or a page path such as `org:acme#policies/refund`. A run scope with no declaration throws, as it does at run start:

```text
Knowledge run scope "project:x" does not match a declared scope type. Declare it in Knowledge `scopes` (for Memory's resource:/thread: scopes, spread `...knowledgeMemoryScopes()`).
```

A `target.scope` with no declaration throws `Knowledge scope "project:x" does not match a declared scope type.`

:::warning

`explainAccess()` is host-only. It tells a missing page from a hidden one, which runs must never learn. Don't expose it through an agent tool, or through a server route without admin-level auth.

:::

```typescript
await knowledge.explainAccess(['org:acme'], { page: 'team:acme:support#refunds' })
// {
//   role: 'viewer',
//   reasons: [{ principal: 'org:acme', role: 'viewer', rule: 'team:$orgId:$teamId', via: 'rule' }],
//   page: { id: '…', scope: 'team:acme:support' },
// }

await knowledge.explainAccess(['org:globex'], { page: 'team:acme:support#refunds' })
// { role: null, reasons: [], page: { id: '…', scope: 'team:acme:support' }, reason: 'hidden' }
```

### `readScopeFor()`

```typescript oxfmt:false
readScopeFor(principals: readonly string[]): Promise<KnowledgeReadScope>
```

Returns what a holder of `principals` can read: the principals themselves plus every scope their rules reach in one hop. Pass the result as `read` to the store's read methods when host code reads Knowledge for a user. Undeclared principals throw `Knowledge run scope "project:x" does not match a declared scope type.` An empty list reads nothing.

### `getStorage()`

```typescript oxfmt:false
getStorage(): Promise<KnowledgeStorage>
```

Host code such as admin pages, deletes and your own import scripts uses the returned Knowledge store directly. Its methods skip role checks, so pass the `read` value from `readScopeFor()` whenever a read should be limited to what a user can see.

```typescript
const store = await knowledge.getStorage()
const read = await knowledge.readScopeFor(['org:acme'])
const [scope] = await store.getScopesByAddress(['team:acme:support'])
const page = await store.getPageByPath({ scopeId: scope.id, path: ['handbook', 'refunds'], read })
```

### `pinnedContextEnabled`

`true` when `pinnedContext` is on, so attached agents get pinned pages every turn.

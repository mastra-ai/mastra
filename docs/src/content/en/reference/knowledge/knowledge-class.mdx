# Knowledge class

The `Knowledge` class holds pages and notes, declares which scopes exist and who gets which role on them, and gives attached agents the Knowledge tools. See [Knowledge](/docs/knowledge/overview) for what it does and a quickstart.

:::alpha

Knowledge is in alpha. Its API may change between releases.

:::

## Usage example

```typescript title="src/mastra/knowledge.ts"
import { Knowledge, knowledgeMemoryScopes } from '@mastra/core/knowledge'
import { LibSQLStore } from '@mastra/libsql'

export const knowledge = new Knowledge({
  id: 'company',
  storage: new LibSQLStore({ id: 'knowledge', url: 'file:./knowledge.db' }),
  tools: true,
  scopes: {
    ...knowledgeMemoryScopes(),
    'team:$orgId:$teamId': {
      access: [
        { principal: 'self', role: 'editor' },
        { principal: 'org:$orgId', role: 'viewer' },
      ],
    },
  },
})
```

The constructor throws a `KnowledgeDeclarationError` when `scopes` is missing or a declaration is invalid, for example two patterns of one type that overlap or a rule principal that doesn't bind. Without `scopes` the message is:

```text
Knowledge needs `scopes`: declare the scopes its runs hold, e.g. `scopes: { ...knowledgeMemoryScopes() }`, or `{}` for none.
```

## Methods

### Tools

#### `createTools()`

```typescript oxfmt:false
createTools(options?: {
  read?: boolean; write?: boolean; pinnedContext?: boolean;
  principals?: readonly string[]; author?: string;
}): Record<string, Tool>
```

Returns the Knowledge tools for explicit wiring, such as an agent that isn't attached with `knowledge`. Each group option overrides the matching group set on the instance, and an omitted option keeps it. On an instance with `pinnedContext` on, `createTools({ write: false })` also returns `knowledge_pin`. See [Knowledge tools](/reference/knowledge/knowledge-tools).

```typescript
const tools = knowledge.createTools({ write: false })
// knowledge_list, knowledge_search, knowledge_read, knowledge_activity
```

`principals` fixes the scope addresses every call acts as, for a host that runs the tools outside an agent run, such as an MCP server acting for an external agent. Each address must match a declared scope type, the store's declarations included. A call made with one that doesn't is refused. `createTools()` throws only for an empty list. The call's own run scopes are then ignored, and access follows the scope rules for these principals. Set them from the host's own authentication, never from the request. `author` is recorded on writes made through these tools.

```typescript
const tools = knowledge.createTools({
  read: true,
  write: true,
  principals: ['agent:claude-code'],
  author: 'user:123 via mcp:claude-code',
})
```

#### `getPinnedContext()`

```typescript oxfmt:false
getPinnedContext(options: { principals: readonly string[]; read?: boolean }): Promise<KnowledgePinnedEntry[]>
```

Returns the pinned pages a caller holding `principals` receives, rendered as an agent run receives them: only pages it can read, within the instance's pin budget. Use it beside `createTools({ principals })` when a host serves Knowledge outside an agent run, and pass the same `read` as that call (default: the instance's `tools.read`) so entries point at `knowledge_read` and `knowledge_list` only when the caller has them. Throws for an empty list or an undeclared principal.

```typescript
const pins = await knowledge.getPinnedContext({ principals: ['agent:claude-code'], read: true })
// [{ id, text, name, scope }]
```

#### `getInstructions()`

```typescript oxfmt:false
getInstructions(options?: { read?: boolean; write?: boolean; pinnedContext?: boolean }): string
```

Returns the usage instructions that go with `createTools(options)`, built the same way as for an attached agent: the built-in parts for the enabled groups, or what the `instructions` option makes of them.

### Access

#### `explainAccess()`

```typescript oxfmt:false
explainAccess(
  runScopes: readonly string[],
  target: { scope: string } | { page: string },
): Promise<KnowledgeAccessExplanation>
```

Explains why a run holding `runScopes` can or can't reach a scope or page. `runScopes` are canonical addresses, including `resource:` and `thread:` (`resource:slack%3AU123` for Memory resource `slack:U123`). `target.page` takes a page ID or a page path such as `org:acme#policies/refund`.

```typescript
await knowledge.explainAccess(['org:acme'], { page: 'team:acme:support#refunds' })
// {
//   role: 'viewer',
//   reasons: [{ principal: 'org:acme', role: 'viewer', rule: 'team:$orgId:$teamId', via: 'rule' }],
//   page: { id: '…', scope: 'team:acme:support' },
// }

await knowledge.explainAccess(['org:globex'], { page: 'team:acme:support#refunds' })
// { role: null, reasons: [], page: { id: '…', scope: 'team:acme:support' }, reason: 'hidden' }
```

A run scope with no declaration throws, as it does at run start:

```text
Knowledge run scope "project:x" does not match a declared scope type. Declare it in Knowledge `scopes` (for Memory's resource:/thread: scopes, spread `...knowledgeMemoryScopes()`).
```

A `target.scope` with no declaration throws `Knowledge scope "project:x" does not match a declared scope type.`

:::warning

`explainAccess()` is host-only. It tells a missing page from a hidden one, which runs must never learn. Don't expose it through an agent tool, or through a server route without admin-level auth.

:::

#### `readScopeFor()`

```typescript oxfmt:false
readScopeFor(principals: readonly string[]): Promise<KnowledgeReadScope>
```

Returns what a holder of `principals` can read: the principals themselves plus every scope their rules give them a role on. Roles don't carry over to further scopes. Pass the result as `read` to the store's read methods when host code reads Knowledge for a user. Undeclared principals throw `Knowledge run scope "project:x" does not match a declared scope type.` An empty list reads nothing.

#### `scopeGrants()`

```typescript oxfmt:false
scopeGrants(scope: { address: string; parentAddress?: string | null }): KnowledgeScopeGrant[]
```

The roles the declarations give other scopes on this one, as `{ principal, role }` with the strongest role per principal and `self` rules left out. It reads no storage. `parentAddress` supplies the tree parent that rules binding through `belongsTo` need. Use it for a browsing UI that draws access between scopes. Use `explainAccess()` for one run's view.

#### `scopeDeclaration()`

```typescript oxfmt:false
scopeDeclaration(key: string): KnowledgeScopeDeclarationInfo | undefined
```

Returns the declaration a scope was created from, by its declaration key, for display: `{ key, description?, displayLabel?, belongsTo?, children }`. Child keys work too, such as `org:$orgId/private`. Access rules are left out. Use `explainAccess()` for those. Returns `undefined` for an unknown key.

#### `scopeLabel()`

```typescript oxfmt:false
scopeLabel(address: string): string | undefined
```

Returns the `displayLabel` for a scope address with its `$params` filled in: `'$orgId organization'` on `org:$orgId` gives `acme organization` for `org:acme`. A concrete address's own `displayLabel` wins. Returns `undefined` when the address matches no declaration or has no label.

### Host writes

`upsertPage()`, `removePage()`, `movePage()`, `addNote()`, `updateNote()` and `removeNote()` are host-only: they check no run scopes or access rules. Don't expose them through an agent tool, or through a server route without admin-level auth.

#### `upsertPage()`

```typescript oxfmt:false
upsertPage(input: {
  scope: string
  path: string
  name: string
  description?: string
  body?: string
  author?: string
}): Promise<{ page: KnowledgePage; status: 'created' | 'updated' | 'unchanged' }>
```

Creates or updates the page at `path` (keys joined by `/`, such as `guides/install`) in `scope`, creating the scope and any missing pages along the path. Writing the same path again updates that page. `description` and `body` keep their stored values when left out. An `unchanged` result means nothing was written. The page keeps its version, emits no change event and isn't re-embedded. `author` is recorded as the writer and defaults to `host`. A path with no keys throws `Knowledge page path "<path>" needs at least one key.` See [Load your content](/docs/knowledge/load-your-content).

#### `removePage()`

```typescript oxfmt:false
removePage(input: {
  scope: string
  path: string
  author?: string
  expected?: { id: string; version: number }
}): Promise<KnowledgePage | null>
```

Removes the page at `path` and resolves to it, or to `null` when no page is there. Throws `"<scope>#<path>" has child pages; remove them first.` for a page with children, and `"<scope>#<path>" is declared in config; change the scope's pages to remove it.` for a template page. Throws without retrying when another write changed the page first.

Pass `expected`, the page's `id` and `version` as you read it, to remove only that page. If the page at `path` is a different page or another version, or nothing is there, the call throws `KnowledgeConflictError` and removes nothing. The same applies when another write changes or removes the page during the call.

#### `movePage()`

```typescript oxfmt:false
movePage(input: {
  scope: string
  path: string
  parent?: string
  toScope?: string
  expectedVersion?: number
  author?: string
}): Promise<KnowledgePage>
```

Moves the page at `path` in `scope`, with its child pages, under the page at `parent` and resolves to the moved page. `parent` is a key path in the destination scope. Leave it out to move the page to the top of the scope. `toScope` moves the page to another scope, creating that scope on first write like `upsertPage()`. The page keeps its ID, notes, pins and embeddings, so use it instead of removing and re-creating a page when its source moves. Paths below the page change, and links by path are re-resolved.

Throws `KnowledgeNotFoundError` when the page or the parent doesn't exist, `"<scope>#<path>" is declared in config; change the scope's pages to move it.` for a template page, `"<scope>#<path>" can't move under itself or its own subtree.`, and `"<parent>" already has a page with key "<key>"; move or rename that one first.` It also throws when the move would put pages more than 10 levels below the scope, and without retrying when another write changed the page first or when `expectedVersion` is stale.

#### `addNote()`

```typescript oxfmt:false
addNote(input: {
  scope: string
  path: string
  text: string
  when?: Date
  stamps?: string[]
  author?: string
}): Promise<KnowledgeNote>
```

Adds a note to the page at `path`. `text` is at most 250 tokens. `[[scope#path]]` mentions of existing pages link the note to them. Other `[[...]]` text stays plain. `stamps` are the scope addresses whose readers see the note and default to the page's scope. Throws `KnowledgeNotFoundError` when the page doesn't exist.

#### `updateNote()`

```typescript oxfmt:false
updateNote(input: { id: string; text: string; when?: Date; stamps?: string[]; author?: string }): Promise<KnowledgeNote>
```

Replaces a note: adds the new note, then removes the old one, and resolves to the new note with a new ID. `when` and `stamps` keep their old values when left out or empty. If removing the old note fails after the add, both notes exist and the call throws, so remove the one you don't want. When the old note was already removed by someone else, the new note is removed too and nothing is left behind.

#### `removeNote()`

```typescript oxfmt:false
removeNote(input: { id: string; author?: string }): Promise<KnowledgeNote | null>
```

Removes a note and resolves to it, or to `null` when it's already gone.

### Storage and maintenance

#### `getStorage()`

```typescript oxfmt:false
getStorage(): Promise<KnowledgeStorage>
```

Returns the Knowledge store, for host code such as admin pages, deletes and your own import scripts. Its read methods take `read`: `'all'` skips the role checks, so pass the value from `readScopeFor()` whenever a read should be limited to what a user can see.

```typescript
const store = await knowledge.getStorage()
const read = await knowledge.readScopeFor(['org:acme'])
const [scope] = await store.getScopesByAddress(['team:acme:support'])
const page = await store.getPageByPath({ scopeId: scope.id, path: ['handbook', 'refunds'], read })
```

#### `reembed()`

```typescript oxfmt:false
reembed(options?: { scope?: string; limit?: number; cursor?: string }): Promise<KnowledgeReembedResult>
```

Embeds pages and notes that already exist, without changing them. Use it for content written before you added `vector` and `embedder`, or after you switch embedders. Each call handles up to `limit` pages (default 50, at most 500) with their notes, and resolves to:

- `embedded`: how many pages and notes this call embedded.
- `failed`: pages and notes whose embed still failed after Knowledge's own retries, each with its `kind`, `id` and `error`. The rest of the batch carries on, and a later run tries them again.
- `overChunkCap`: pages longer than the [chunk limit](/reference/knowledge/limits), with how many chunks they'd need. They're embedded up to the limit.
- `rateLimited`: `true` when the embedder kept rate limiting, so the call stopped early. Wait before you resume from `nextCursor`, or the next call is rate limited too.
- `nextCursor`: pass it as `cursor` to the next call. It's absent when everything has been handled.

`scope` limits the run to one scope's pages and the notes on them, such as `org:acme`. Without it, the run covers every page, then the notes on scope pages, where each scope counts toward `limit` like a page. Embedding a page again overwrites its vectors, so you can stop a run and resume it from the last cursor, or rerun it. The cursor isn't a snapshot. Pages added or removed during a run can be missed or handled twice, and a page read before a concurrent edit can overwrite the vectors that edit wrote. Run `reembed()` again after concurrent writes finish. Throws without `vector` and `embedder`.

```typescript
let cursor: string | undefined
do {
  const result = await knowledge.reembed({ cursor })
  for (const failure of result.failed) console.warn(failure)
  if (result.rateLimited) await new Promise(resolve => setTimeout(resolve, 60_000))
  cursor = result.nextCursor
} while (cursor)
```

#### `reindexLinks()`

```typescript oxfmt:false
reindexLinks(): Promise<number>
```

Rebuilds the page link index from every page body, and resolves to how many pages it indexed. Writes keep the index current, so this is for pages that predate it or were written straight to the store, and for links a write left as they were. A write re-resolves at most 100 linking pages, and checks at most 99 pages sharing a name. Past either limit it logs a warning that names `reindexLinks()`. It needs no vector store.

#### `renameScopeDeclaration()`

```typescript oxfmt:false
renameScopeDeclaration(from: string, to: string): Promise<number>
```

Moves stored scopes created from declaration key `from`, and its child scopes (`from/<name>`), to key `to`, in one step. Resolves to how many scopes moved. Refuses, and changes nothing, when `from` is still in `scopes`, `to` isn't, or a stored address doesn't match `to`'s pattern. Until stored keys match `scopes`, the instance refuses to run.

On MongoDB, the rename runs in a transaction only on a replica set. On a standalone server it isn't atomic, and a failure partway can leave some scopes renamed.

See [rename or retire a scope type](/reference/knowledge/scope-declarations#rename-or-retire-a-scope-type).

### Events

#### `onChange()`

```typescript oxfmt:false
onChange(listener: (event: KnowledgeChangeEvent) => void): () => void
```

Calls `listener` after each committed write made through this instance's store: tool writes, host writes through `getStorage()`, importer runs, and new scopes. Writes in a transaction are reported once it commits, and not at all if it rolls back. Returns a function that removes the listener. Use it to refresh a live UI. Writes made on a store obtained another way aren't seen.

Events carry IDs, not content or access, so anything that relays them to people must re-read each page under that person's read scope from `readScopeFor()`:

| `kind` | `op` | Fields |
| - | - | - |
| `scope` | `create` | `pageId`, `scopeId` (the new scope page's ID) |
| `page` | `create`, `update`, `move`, `merge`, `delete` | `pageId`, `scopeId`; `fromScopeId` for `move` and `merge`; `sourceId` (the page merged away) for `merge` |
| `note` | `add`, `restamp`, `remove`, `restore` | `pageId`, `noteId` |
| `pin` | `add`, `remove` | `pageId` |

Every event also has `knowledgeId` and `at`. Creating a scope emits one `scope` event, not one per child scope or template page, so re-list the scope when it arrives. A listener that throws is logged and doesn't fail the write.

```typescript
const unsubscribe = knowledge.onChange(event => {
  if (event.kind === 'page') refreshPage(event.pageId)
})
```

### Properties

#### `pinnedContextEnabled`

`boolean`. Whether `pinnedContext` is on, so attached agents get pinned pages every turn.

# SkillsProcessor

The `SkillsProcessor` is an **input processor** that adds the available skills to the system message as an `<available_skills>` list, so the model knows which skills exist and can load one with the `skill` tool. The agent adds it automatically when its workspace or its own `skills` option provides skills, so you only configure it yourself to change how skills are presented.

With `injectCatalog: false`, it replaces the list with a short instruction to find skills with `skill_search` and load them with `skill`. Use this when the list costs too many tokens. See [Turn off the skills list](/docs/sandbox/skills#turn-off-the-skills-list).

The `skill`, `skill_search`, and `skill_read` tools come from the agent, not from this processor, and stay available in both modes. To replace them with on-demand `search_skills` and `load_skill` tools instead, use [`SkillSearchProcessor`](/reference/processors/skill-search-processor). Configure one or the other, not both.

## Usage example

```typescript
import { SkillsProcessor } from '@mastra/core/processors'

const skills = new SkillsProcessor({
  workspace,
  format: 'markdown',
})
```

## Extended usage example

```typescript title="src/mastra/agents/skill-agent.ts"
import { Agent } from '@mastra/core/agent'
import { SkillsProcessor } from '@mastra/core/processors'
import { Workspace, LocalFilesystem } from '@mastra/core/workspace'

const workspace = new Workspace({
  filesystem: new LocalFilesystem({ basePath: './project' }),
  skills: ['skills'],
  bm25: true,
})

const agent = new Agent({
  id: 'skill-agent',
  name: 'skill-agent',
  instructions: 'You are a helpful assistant.',
  model: '__GATEWAY_OPENAI_MODEL__',
  workspace,
  inputProcessors: [new SkillsProcessor({ injectCatalog: false })],
})
```

With the list turned off, the agent finds skills by searching. `skill_search` works without any search setup; for larger collections, configure [BM25 or vector search](/docs/sandbox/search) on the workspace to improve ranking, as in the example above. The agent workflow is:

1. Agent receives a user message
1. Agent calls `skill_search` with keywords (e.g., "release notes")
1. Agent reviews results and calls `skill` with the skill name
1. Agent follows the loaded skill's instructions

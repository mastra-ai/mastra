# MastraStorageExporter

Persists traces to Mastra's configured storage with automatic batching and retry logic.

:::note

`MastraStorageExporter` was previously called `DefaultExporter`. The original `DefaultExporter` class is still exported from `@mastra/observability` so existing imports keep working, but it's deprecated and will be removed in a future major version. New code should use `MastraStorageExporter`.

:::

## Span previews

`MastraStorageExporter` and [MastraPlatformExporter](/reference/observability/tracing/exporters/mastra-platform-exporter) use the same formatter for `inputPreview`, `outputPreview`, and `errorPreview`. Previews are generated after span output processors, including redaction, and after the exporter's `customSpanFormatter`. Full payloads remain available separately.

Each preview contains up to 100 characters plus an ellipsis when truncated. Truncation preserves Unicode surrogate pairs. An explicitly supplied string takes precedence, including `""` for an intentionally empty preview. `null` and `undefined` request generation. Whitespace-only supplied strings become `""` without falling back to the payload.

### Input and output selection

| Span | Input preview | Output preview |
| - | - | - |
| Agent run | Latest user message, otherwise latest non-system message | Structured result, response text, tool calls, or generated-file count |
| Resumed agent run | Resume data and tool name, when recorded | Same result formatting as a fresh run |
| Model generation | Latest user message from the messages envelope | Structured result, text, tool calls, files, or reasoning text |
| Model step and inference | Latest non-system message with its role | Structured result, text, or tool-call names |
| Model chunk | Recorded input | Text/delta, tool-call data, or file label for recognized chunk shapes |
| MCP tool or server request | Request payload | Structured content, text content blocks, or nontext labels |
| Processor phase | Messages, request error, tool name, or stream content as appropriate | Recorded configuration/message changes or stream content/chunk count |
| Scorer run | Evaluated response | Score and reason |
| Classifier evaluation | Questions | Answers |
| Embedding | Text or bounded text-batch summary | Recorded vector dimensions |
| Vector operation, reranking, graph traversal | Request payload; query for reranking | Recorded returned-result count |

Recorded interruption or tripwire output takes precedence over normal agent/model results. For example, a suspended output can preview as `Suspended: awaiting approval (refund)`. This describes the individual span; it doesn't select the current outcome of a resumed trace.

Processor formatting uses `processorPhase`, including when a processor emits a memory or skill span. Other span types and unrecognized shapes use text/message fields or compact JSON. This includes caller-defined tool arguments, workflow data, mappings, and operations without a specialized writer. Generic JSON previews have bounded traversal and represent circular or deeply nested values with labels.

Message previews read AI SDK v4–v7 core/model and UI messages, Mastra stored messages, and string messages. They select answer text ahead of reasoning when both are present, and summarize tool calls and results by tool name. Message previews summarize recognized nontext content with labels such as `[image]`, `[audio]`, or `[file]`. They don't include encoded binary content. A span without a recorded output, such as a client-tool marker, receives an empty output preview.

### Error selection

`errorPreview` uses the recorded error's message, prefixed by a non-generic error name when available. For example: `TimeoutError: Order service timed out`. If the message is missing, the formatter tries the error name, ID, domain, and category. Plain-string errors are also supported.

Stack traces and error details aren't included. Missing or unrecognized errors produce `""`. Suspension, tripwire output, and failed-looking tool results don't produce an error preview unless the span also records an error. Output and error previews remain independent, so a partial result can appear alongside its error.

### Storage behavior

Generated previews are refreshed for each exported snapshot. An empty preview at span start doesn't suppress later output or errors. Storage preserves explicit empty strings; stored `NULL` remains the marker for missing previews that may need legacy fallback. Query responses may represent stored empty previews as `null` without regenerating them.

Preview generation requires the shared preview helpers in `@mastra/core`. With older core versions that lack these helpers, both exporters skip generation and pass through existing preview fields and payloads unchanged. The peer dependency range is unchanged. Use the updated `@mastra/core` to preserve intentionally empty previews through storage; earlier storage implementations can regenerate them from the payload. Platform ingestion must also preserve upstream empty strings when deploying this exporter behavior.

## `MastraStorageExporterConfig`

```typescript
interface MastraStorageExporterConfig extends BaseExporterConfig {
  /** Maximum number of spans per batch. Default: 1000 */
  maxBatchSize?: number

  /** Maximum total buffer size before emergency flush. Default: 10000 */
  maxBufferSize?: number

  /** Maximum time to wait before flushing batch in milliseconds. Default: 5000 */
  maxBatchWaitMs?: number

  /** Maximum number of retry attempts. Default: 4 */
  maxRetries?: number

  /** Base retry delay in milliseconds (uses exponential backoff). Default: 500 */
  retryDelayMs?: number

  /** Tracing storage strategy or 'auto' for automatic selection. Default: 'auto' */
  strategy?: TracingStorageStrategy | 'auto'
}
```

Extends `BaseExporterConfig`, which includes:

- `logger?: IMastraLogger` - Logger instance
- `logLevel?: LogLevel | 'debug' | 'info' | 'warn' | 'error'` - Log level (default: INFO)

## `TracingStorageStrategy`

```typescript
type TracingStorageStrategy = 'realtime' | 'batch-with-updates' | 'insert-only'
```

### Strategy Behaviors

- **realtime**: Immediately persists each event to storage
- **batch-with-updates**: Batches creates and updates separately, applies in order
- **insert-only**: Only processes SPAN\_ENDED events, ignores updates

## Automatic strategy selection

When `strategy: 'auto'` (default), the exporter queries the storage adapter for its capabilities:

```typescript
interface TracingStrategy {
  /** Strategies supported by this adapter */
  supported: TracingStorageStrategy[]

  /** Preferred strategy for optimal performance */
  preferred: TracingStorageStrategy
}
```

The exporter will:

1. Use the storage adapter's preferred strategy if available
1. Fall back to the first supported strategy if preferred isn't available
1. Log a warning if a user-specified strategy isn't supported

## Batching behavior

### Flush Triggers

The buffer flushes when any of these conditions are met:

- Buffer size reaches `maxBatchSize`
- Time since first buffered event exceeds `maxBatchWaitMs`
- Buffer size reaches `maxBufferSize` (emergency flush)
- `shutdown()` is called

### Retry Logic

Failed flushes are retried with exponential backoff:

- Retry delay: `retryDelayMs * 2^attempt`
- Maximum attempts: `maxRetries`
- Batch is dropped after all retries fail

### Out-of-Order Handling

For `batch-with-updates` strategy:

- Tracks which spans have been created
- Rejects updates/ends for spans not yet created
- Logs warnings for out-of-order events
- Maintains sequence numbers for ordered updates

## Usage

```typescript
import { MastraStorageExporter } from '@mastra/observability'

// Default configuration
const exporter = new MastraStorageExporter()

// Custom batching configuration
const customExporter = new MastraStorageExporter({
  maxBatchSize: 500,
  maxBatchWaitMs: 2000,
  strategy: 'batch-with-updates',
  logLevel: 'debug',
})
```

## Migrating from `DefaultExporter`

Both classes share the same constructor signature and behavior. To migrate, replace the import and constructor:

```typescript
// Before
import { DefaultExporter } from '@mastra/observability'
const exporter = new DefaultExporter()

// After
import { MastraStorageExporter } from '@mastra/observability'
const exporter = new MastraStorageExporter()
```

The original `DefaultExporter` is preserved unchanged so dashboards or alert rules that match the previous `mastra-default-observability-exporter` exporter name keep working until you migrate.

# DatadogExporter

Sends Tracing data to Datadog's LLM Observability product for monitoring and analytics.

:::note
If you also use `dd-trace` APM auto-instrumentation and need it correctly parented under Mastra spans, use the [DatadogBridge](/reference/observability/tracing/bridges/datadog) instead. The exporter sends LLM Observability data after execution completes, so it doesn't participate in `dd-trace`'s live scope.
:::

## Constructor

```typescript oxfmt:false
new DatadogExporter(config: DatadogExporterConfig)
```

## `DatadogExporterConfig`

```typescript
interface DatadogExporterConfig extends BaseExporterConfig {
  apiKey?: string
  mlApp?: string
  site?: string
  service?: string
  env?: string
  agentless?: boolean
  integrationsEnabled?: boolean

```

Extends `BaseExporterConfig`, which includes:

- `logger?: IMastraLogger` - Logger instance
- `logLevel?: LogLevel | 'debug' | 'info' | 'warn' | 'error'` - Log level (default: INFO)

## Methods

### `exportTracingEvent`

```typescript oxfmt:false
async exportTracingEvent(event: TracingEvent): Promise<void>
```

Exports a tracing event to Datadog LLM Observability.

### `onFeedbackEvent`

```typescript oxfmt:false
async onFeedbackEvent(event: FeedbackEvent): Promise<void>
```

Exports a feedback event to Datadog LLM Observability. See [Feedback export](#feedback-export).

### flush

```typescript oxfmt:false
async flush(): Promise<void>
```

Force flushes any buffered spans to Datadog without shutting down the exporter. Useful in serverless environments where you need to ensure spans are exported before the runtime terminates.

The flush is best-effort: dd-trace sends LLM Observability data from a background writer and gives no way to await the request, so `flush()` waits `flushGraceMs` (default 2000 ms) after asking dd-trace to flush. Each flush that sent new data costs that full wait, so a serverless handler that awaits `flush()` per request pays it per request. Raise it if spans from short-lived processes are missing in Datadog, or set it to `0` to skip the wait when something else keeps the process alive.

### shutdown

```typescript oxfmt:false
async shutdown(): Promise<void>
```

Flushes pending data and shuts down the exporter. Cancels any pending cleanup timers and disables LLM Observability.

## Usage

### Zero-config (using environment variables)

```typescript
import { DatadogExporter } from '@mastra/datadog'

// Reads from DD_LLMOBS_ML_APP, DD_API_KEY, DD_SITE, DD_ENV
const exporter = new DatadogExporter()
```

### Explicit configuration

```typescript
import { DatadogExporter } from '@mastra/datadog'

const exporter = new DatadogExporter({
  mlApp: 'my-llm-app',
  apiKey: process.env.DD_API_KEY,
  site: 'datadoghq.com',
  env: 'production',
})
```

### With local Datadog agent

```typescript
const exporter = new DatadogExporter({
  mlApp: 'my-llm-app',
  agentless: false, // Use local Datadog Agent
  env: 'production',
})
```

## Span mapping

Mastra span types are mapped to Datadog LLM Observability span kinds:

| Mastra SpanType | Datadog Kind |
| - | - |
| `AGENT_RUN` | `agent` |
| `MODEL_GENERATION` | `workflow` |
| `MODEL_STEP` | `llm` |
| `TOOL_CALL` | `tool` |
| `MCP_TOOL_CALL` | `tool` |
| `PROVIDER_TOOL_CALL` | `tool` |
| `WORKFLOW_RUN` | `workflow` |
| All other types | `task` |

All unmapped span types (including `MODEL_CHUNK`, `WORKFLOW_STEP`, `GENERIC`, and future span types) automatically default to `task`.

## Feedback export

Feedback recorded with [`addFeedback()`](/docs/observability/feedback) is exported to Datadog as end-user feedback. Feedback with a `spanId` targets that span, and feedback with only a `traceId` targets the trace. No extra configuration is needed.

```typescript
if (!mastra.observability.addFeedback) {
  throw new Error('Feedback is not supported by the active observability implementation')
}

await mastra.observability.addFeedback({
  traceId,
  feedback: {
    feedbackType: 'thumbs',
    value: 'down',
    comment: 'Wrong answer',
    feedbackUserId: 'user-123',
    metadata: { datadog: { assessment: 'fail' } },
  },
})
```

The Datadog LLM Observability trace ID is the Mastra trace ID, and each Datadog span ID is the Mastra span ID. Feedback reaches its trace or span even when it arrives hours after the run or from another process. You can also search Datadog for the `traceId` that a run returns.

| Mastra feedback field | Datadog feedback field |
| - | - |
| `traceId` | `trace_id`, the target when there is no `spanId` |
| `spanId` | `span_id`, the target span |
| `feedbackType` | `label`, with each `.` changed to `_` |
| `value` | `score_value` for numbers, `text_value` for `comment` and `correction` feedback, `categorical_value` for other strings |
| `comment` | `reasoning` |
| `feedbackUserId` (or `metadata.userId`) | `submitter.id`, or `anonymous` when neither is set or `feedbackUserId` is `null` |
| `feedbackSource` | `feedback_source` tag |
| `metadata.datadog.assessment` | `assessment`, when the value is `pass` or `fail` |

The `assessment` is optional. Your app decides which feedback passes or fails, and Mastra doesn't derive it from the value. Set it on the feedback, not on the run, because feedback can inherit the metadata of the run it rates. To find failed feedback with the `thumbs` label in Datadog, search for `@feedback.thumbs.assessment:fail`.

Feedback without a `traceId` is dropped. Feedback without a `spanId` can't reach a run that joined another LLM Observability trace, such as a run inside your own `llmobs.trace()` call or one continued from an upstream service. Those runs keep the Datadog trace ID that `dd-trace` gives them.

## Score export

Scores recorded with `mastra.observability.addScore()` are exported to Datadog as evaluations on the span they rate. A score reaches its span even when it arrives after the run or from another process. A late score can't reach a run that joined another LLM Observability trace.

## Environment variables

The exporter reads configuration from these environment variables:

| Variable | Description |
| - | - |
| `DD_API_KEY` | Datadog API key |
| `DD_LLMOBS_ML_APP` | ML application name |
| `DD_SITE` | Datadog site |
| `DD_ENV` | Environment name |
| `DD_LLMOBS_AGENTLESS_ENABLED` | Set to 'false' or '0' to use local agent |

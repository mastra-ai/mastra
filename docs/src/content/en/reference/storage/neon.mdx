# Neon storage

[Neon](https://neon.com) is a managed PostgreSQL service. Mastra connects to Neon through [`PostgresStore`](/reference/storage/postgresql), which uses the Node.js `pg` driver. Neon doesn't require a separate Mastra storage package.

## Set up Neon

Install the [Neon CLI](https://neon.com/docs/cli/install):

```bash npm2yarn
npm install -g neon
```

From your project directory, link an existing Neon project or create one:

```bash
neon link
```

The command signs you in, writes project context to `.neon`, and pulls the current branch's environment variables.

To manage branch settings in the repository, create a [`neon.ts`](https://neon.com/docs/reference/neon-ts) file:

```bash
neon config init
```

This installs `@neon/config` and `@neon/env` and creates a starter config. For example, the following policy expires new non-default branches after seven days:

```typescript title="neon.ts"
import { defineConfig } from '@neon/config/v1'

export default defineConfig({
  branch: branch => {
    if (branch.isDefault) {
      return {}
    }

    if (!branch.exists) {
      return { ttl: '7d' }
    }

    return {}
  },
})
```

Apply the config and refresh the local environment variables:

```bash
neon deploy
neon env pull
```

`neon env pull` writes `DATABASE_URL` and `DATABASE_URL_UNPOOLED` to `.env.local`, or to `.env` when that file already exists.

## Install Neon agent skills

Install the [`neon` and `neon-postgres` agent skills](https://neon.com/docs/ai/agent-skills) from your project directory:

```bash npm2yarn
npx skills add neondatabase/agent-skills --skill neon -y
npx skills add neondatabase/agent-skills --skill neon-postgres -y
```

The skills give compatible coding agents Neon setup instructions and Postgres-specific guidance.

## Quickstart

Install the PostgreSQL storage package:

```bash npm2yarn
npm install @mastra/pg@latest
```

Pass the direct connection string from `neon env pull` to `PostgresStore`:

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { PostgresStore } from '@mastra/pg'

export const mastra = new Mastra({
  storage: new PostgresStore({
    id: 'neon-storage',
    connectionString: process.env.DATABASE_URL_UNPOOLED!,
  }),
})
```

On startup, Mastra calls `storage.init()` and creates its tables and indexes in Neon. This setup uses `@mastra/pg` and must run in Node.js.

## Production connections

Neon provides direct and pooled connection strings:

- Use a direct connection for schema initialization and migrations.
- Use a pooled connection for normal application traffic, especially when your deployment opens many concurrent connections. Pooled hostnames contain `-pooler`.

In production, keep the pooled connection string in `DATABASE_URL` and the direct connection string in `DATABASE_URL_UNPOOLED`. Initialize the schema with the direct connection:

```typescript title="scripts/init-storage.ts"
import { PostgresStore } from '@mastra/pg'

const storage = new PostgresStore({
  id: 'neon-storage-init',
  connectionString: process.env.DATABASE_URL_UNPOOLED!,
})

try {
  await storage.init()
} finally {
  await storage.close()
}
```

After the schema exists, use the pooled connection at runtime and disable automatic initialization:

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { PostgresStore } from '@mastra/pg'

export const mastra = new Mastra({
  storage: new PostgresStore({
    id: 'neon-storage',
    connectionString: process.env.DATABASE_URL!,
    disableInit: true,
  }),
})
```

See [Neon connection pooling](https://neon.com/docs/connect/connection-pooling) for details.

## Vector search

Neon supports the [`pgvector` extension](https://neon.com/docs/extensions/pgvector). Use [`PgVector`](/reference/vectors/pg) for semantic recall and vector search:

```typescript
import { PgVector } from '@mastra/pg'

const vector = new PgVector({
  id: 'neon-vector',
  connectionString: process.env.DATABASE_URL_UNPOOLED!,
})
```

`PgVector` installs the extension when it creates its first index. Create the extension and indexes over the direct connection, then use the pooled connection with `disableInit: true` at runtime.
